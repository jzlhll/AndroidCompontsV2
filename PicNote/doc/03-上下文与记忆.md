# 竹节笔记 / Bambootes · 03 上下文与记忆

## 1. 目标与边界

让长链可以持续追加与解析，同时把单次请求固定在预算内；每段进入请求的上下文都能追溯到节点，内容变化后不会继续使用旧结论。

首版只做确定性的结构化上下文，不建全文索引、不做向量检索、不调用模型生成摘要；摘要标签随解析结果一并返回。

## 2. 分层

| 层 | 来源 | 用途 | 可重建 |
| --- | --- | --- | --- |
| 原始证据 | 本地 WebP、用户备注、解析文字、轮次输入与输出快照 | 回看与追溯 | 原始素材不可丢；轮次快照不可改写 |
| 起始信息 | 引言节点全文 | 固定放在偏好之后的文档前缀 | 用户原文，不被摘要替换 |
| 节点摘要 | `node_parse.summary / tags` | 相邻上下文与分段记忆 | 从已提交结果恢复 |
| 章节索引 | `chapter` 节点的标题与键序 | 让模型知道自己写在第几节附近 | 从节点链即时生成 |
| 分段记忆 | 连续已解析节点的紧凑索引 | 限制旧节点进入上下文的体积 | 从节点摘要确定性重建 |
| 写作偏好 | 用户显式设置的语言、结构、术语、篇幅 | 多文档复用写作要求 | 用户可改可删，不从正文猜测 |
| 本轮上下文 | 上述内容在本轮实际发送的部分 | 一次请求的完整输入 | 按发送快照留档 |

本版不设“文档记忆（章节正文）”与“历史引用”两层：文档由节点链投影而来，不需要第二份正文索引；跨文档引用首版不做，避免引用失效与上下文污染。

## 3. 起始信息

固定取第 2 位的引言节点全文，作为请求的 `brief`：

- 用户在新建文档或编辑引言时填写“这次想学什么、在看什么、想记录什么”，沿用现有引言交互与 `>` 导出。
- 未填写时省略该字段，不生成虚构背景。
- 修改引言只影响之后的批次，历史快照保持原样。
- 引言不参与分段记忆，也不会被摘要替换。

起始信息因此不需要单独的节点，也不新增节点类型，固定前两位的规则不变。

## 4. 节点摘要与分段

解析返回的 `summary` 保留关键术语、结论与不确定性，≤160 token；`tags` 用于记忆页展示。`markdown` 为空的节点不产生摘要。

分段规则：

1. 按链序遍历 `parsed` 节点；遇到 `pending / stale / failed` 或无 `node_parse` 的节点即结束当前段，不跨越缺口。
2. 满 12 个节点或摘要累计 1200 token 时封段，未满阈值作为尾段。
3. 段文本 ≤320 token：每个节点保留 `编号 + 摘要`，超过则截短摘要，完整内容仍在节点上。
4. 单段索引本身放不进 320 token 时提前封段，不通过删除来源满足上限。
5. 确定性生成，不调用模型，不拿上一版段文本再压缩。
6. 用户修正过文字的节点，用修正文字首行前 80 字代替摘要参与段文本。

```text
段 s03 · 节点 06—09
06 缩放：√d_k 控制点积尺度。
07 多头：独立投影后并行计算再拼接。
08 位置编码：正弦函数提供顺序信息。
09 残差与归一化：稳定深层训练。
```

## 5. 预算

设模型窗口 `C`、预留输出 `O`（默认 4096）、安全空间 `S`（默认 2048），输入上限 `B = min(16000, C - O - S)`。数值为默认值，按实际模型窗口与图片规则适配。

| 输入项 | 上限 | 规则 |
| --- | --- | --- |
| 系统提示与输出协议 | 1200 | 必须完整，放不下不发请求 |
| 本批素材 | 8000 | 本批节点用户文字与实际发送图片，优先保留 |
| 写作偏好与起始信息 | 800 | 仅启用项与已填写的引言 |
| 章节索引 | 800 | 全部章节标题；极长文档先保留当前章节前后各一节 |
| 相邻节点与分段记忆 | 1200 | 共用额度，不按来源另加预算 |

裁剪顺序：先移除分段记忆，再缩减相邻节点，最后缩小章节索引范围。本批用户文字、节点 ID 与图片不可裁剪；本批仍放不下时拆批或提示用户精简文字，不静默截断。

请求中的文字顺序与裁剪优先级无关，固定为：协议、偏好、起始信息、章节索引、上下文、本批素材、输出要求。

## 6. 上下文选择

不使用检索，只按结构选：

1. 夹角：本批首个与最后一个节点的链序位置决定“当前段”。
2. 相邻节点：位置前后各最多 2 个 `parsed` 节点的摘要，带 `node_id`。
3. 分段记忆：覆盖本批节点的段优先，其次最近 2 段。
4. 每条上下文都带 `kind / source_ids`，`kind` 取 `neighbor / segment`。
5. 已包含在本批素材中的节点不重复注入摘要。

只有图片、没有文字且尚未解析时，使用相邻与最近段；不凭空构造查询。本批提交成功后，下一批即可使用新产生的摘要。

## 7. 失效与重建

| 操作 | 立即执行 | 后续 |
| --- | --- | --- |
| 改备注、换图、加图、删图、切换 `detail` | 节点转 `stale`，其摘要退出上下文，删除覆盖它的段 | 新结果提交后重建相关段 |
| 修正解析文字 | 保持状态，`origin = user`，摘要不再作为有效片段，删除覆盖它的段 | 重建时用修正文字首行替代 |
| 纯排序 | 不失效任何摘要 | 段顺序按需重算，不改内容 |
| 删除节点 | 删除 `node_parse`，删除覆盖它的段 | 重建相邻段 |
| 修改写作偏好 | 无 | 只影响之后的批次 |
| 删除文档 | 级联清理 `node_parse / turn / memory_segments` 与 `parse/` 目录 | 无 |

重建按文档串行执行：重复触发先取消并等待旧 Job，再从当前有效节点整体重建，写回前校验节点仍为 `parsed`。段是可重建缓存，重建失败只提示，不阻断解析与阅读。

## 8. 内存管理对接

记忆与偏好页中的“重新整理”即重建分段，不重新识图、不改正文；展示已覆盖节点数、最近整理时间与待更新节点数。字段与页面见 [04-界面升级.md](04-界面升级.md)，表结构见 [05-存储、配置与迁移.md](05-存储、配置与迁移.md)。

## 9. 验收

1. 1000 个已解析节点时，请求不携带全部摘要与全部图片，`B` 不被突破。
2. 修改某节点图片后，该节点摘要不再出现在后续请求的 `context` 中。
3. 未填写引言时请求不含 `brief`，也不生成替代文案。
4. 分段不跨过未解析节点，重建结果与节点摘要一致。
5. 删除节点或文档后，相应段与轮次一起清理，无孤儿记录。
