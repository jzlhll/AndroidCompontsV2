# 竹节笔记 / Bambootes · 03 上下文与记忆

## 1. 目标与边界

长链持续追加时，单次请求保持在预算内，每条上下文可追溯到当前文档节点。首版只做结构化选择，不建全文或向量索引，不另发模型请求压缩记忆；模型摘要随节点解析结果返回，本地分段只是可删除、可重建缓存。

图片、备注、引言和历史结果都是资料，不能覆盖系统输出协议、发起工具调用或修改其它节点。写作偏好由显式设置决定，不从素材中的指令猜测。

## 2. 分层与快照

| 层 | 来源 | 用途 |
| --- | --- | --- |
| 原始资料 | 本地 WebP、用户备注、已保存解析文字 | 阅读、导出与重新解析；不可由缓存替代 |
| 起始信息 | 固定第 2 位 `introduction` 的原文 | 描述背景与记录目标；为空则省略 |
| 节点摘要 | 当前有效的 `node_parse.summary / tags` | 已解析节点的上下文 |
| 章节位置 | 当前节点之前最近的 `chapter` | 约束上下文范围；首个章节前为独立前言区域 |
| 分段记忆 | 同章连续有效正文的紧凑摘要 | 有限预算内回看邻近内容 |
| 写作偏好 | 语言、结构、术语、篇幅 | 全局设置，本轮启动时冻结 |
| 轮次快照 | 每批实际发送的输入和结果 | 只读追溯，不作为自动重新写入的数据源 |

本轮冻结引言、章节结构与偏好；改全局偏好只影响下一轮。所属文档在轮次期间只读，后批仍可引用前批刚成功提交的摘要。历史快照不随后续编辑改写。图片删除后历史只能显示当时的文字和图片元数据，不承诺恢复已删除的原图或逐字复现模型结果。

## 3. 起始信息与文字节点

引言沿用现有创建/编辑交互与 Markdown `>` 引用，不新增“起始节点”。引言非空时完整纳入 `brief`；超出预算时阻止发送并提示用户精简，不静默截断，也不修改本地原文。

纯文字 `body` 节点不需要解析，但其用户文字仍是有效资料：相邻上下文选择应包含它，不能因为没有 `node_parse` 就忽略用户补充的信息。有图片的节点只有显示状态为 `parsed` 时才提供解析摘要；`pending / stale / failed` 的旧模型结论不进入上下文。

用户备注与修正文字以用户原文为准。对 `origin = user` 的节点，旧模型摘要立即停用，改取当前修正文字的有限摘录；用户清空解析文字时不回退到旧摘要。摘录过长可按上下文预算缩短，附 `truncated = true`，原文与实际发送片段分别可追溯。

## 4. 分段规则

1. 按当前链序读取正文节点。章节边界强制封段，不跨章节；遇到未解析、待更新、失败图片节点封段，不跨未知缺口。
2. 有效来源包括 `parsed` 图片节点与有文字的纯文字 `body`。模型节点使用当前摘要加备注摘录；用户修正节点使用修正文字加备注摘录；纯文字节点使用用户文字摘录。空内容不伪造摘要。
3. 每段最多 12 个节点，段文本预算 ≤320 token；每个来源至少保留 `node_id` 与可用摘录。加入下一节点会超预算则先封段；单条摘录过长可缩短，但不丢来源 ID。
4. `node_ids` 为有序 JSON 数组，段文本用稳定 `node_id` 标识。页面编号从当前链序派生，不能把历史编号当成节点身份。
5. 每次从当前源数据确定性生成，不重复压缩上一版段文本，不调用模型。

缓存不改变节点状态、正文、`doc.md` 或文档更新时间。记忆页“已覆盖节点”统计有效段的去重来源数，不把一个节点在多个上下文片段出现的次数累加。

## 5. 预算

服务配置必须明确模型输入窗口 `C`、输出额度 `O`（默认 4096）、安全余量 `S`（默认 2048）与图片计费/限制规则；未知能力不能仅凭模型名猜测可用容量。输入上限 `B = min(16000, C - O - S)`；`B <= 0` 时要求修正配置，不发请求。以下为每项上限，最终总量还必须不超过 `B`。

| 输入项 | 上限（token） | 处理 |
| --- | --- | --- |
| 系统提示与输出协议 | 1200 | 必须完整，放不下就不发送 |
| 本批素材 | 8000 | 本批图片、备注、节点 ID；不能截掉图片或用户备注 |
| 写作偏好与引言 | 800 | 引言原文必须完整；超限提示精简 |
| 当前章节标题 | 800 | 不发送全书章节索引；标题本身过长则提示修改 |
| 相邻节点与分段记忆 | 1200 | 共用预算，允许减少或省略 |

图片估算纳入实际尺寸和接口规则；JSON 标识、角色封装、提示词和输出要求均计入请求总量，不能只算正文。输出额度按本批节点数预检，单节点输出过长时应减少节点或调整篇幅，不能把截断内容当成功。

裁剪顺序：先移除较远分段，再减少相邻摘录。必需内容仍放不下则缩小批次；单节点仍放不下就提示用户处理，不截断本批素材。发送前一次完成预算检查；服务报超窗口后停止本轮，由用户决定重试，不无限拆批自动重发。

请求顺序固定为：协议、偏好、起始信息、当前章节、上下文、本批素材、输出要求。上限是实现约束，不能宣称本地字符估算等同服务 token 计数；服务 usage 仅用于后续校准。

## 6. 上下文选择

每批限定同一章，以本批首尾节点位置定位：

1. 先选择本章内前后各最多 2 个相邻有效正文的摘要/摘录，均带来源 ID。
2. 再选择本章距本批位置最近的最多 2 段，不选“覆盖本批节点的旧段”。未解析节点本就不属于有效段。
3. 本批节点、相邻节点与分段之间按 `node_id` 去重；一个来源只发送一次，必要时拆出段内剩余来源重新组装。
4. 每个片段带 `kind = neighbor / segment`、`source_ids` 与实际文本。章节外正文、其它文档与历史失败结果不注入。
5. 无有效上下文时仅发送本批素材、引言及当前章节，不生成虚构记忆。

## 7. 失效与重建

首版以文档为单位清除段缓存，避免漏掉跨移动位置、章节变更与插入后的相邻关系；节点摘要是否有效单独按状态判断。

| 操作 | 节点状态/摘要 | 分段处理 |
| --- | --- | --- |
| 换图、节点内调图顺序、切换 `detail` | 按素材 hash 判断；旧结果失效时摘要退出上下文 | 清除此文档段缓存 |
| 改备注 | 不重新识图，当前备注立即作为新来源 | 清除此文档段缓存 |
| 修正解析文字 | `origin = user`，停止用旧模型摘要 | 从当前修正文字重建 |
| 纯节点排序、插入、合并、改章节 | 不因位置变化重新识图，合并按 02 处理 | 清除缓存，按新章节和顺序重建 |
| 删除节点 | 级联删除 `node_parse`；保留历史 `TurnItem` | 清除所属文档缓存 |
| 改引言/偏好 | 不自动重解析已有节点 | 下轮使用新值，不复写历史快照 |
| 删除文档 | 清理节点、轮次、缓存和文档目录 | 不留孤儿数据 |

重建按文档串行：重复触发先取消并等待旧 Job，再使用仓储 `Mutex` 读取、生成并在事务中替换该文档段。该区间只有本地有界文本处理，没有网络、图片解码或文件压缩；读取和写回共用写操作协调，不允许锁外旧快照覆盖新排序。读取用于发送时也验证来源仍有效、同章且顺序一致；缓存缺失可退化为相邻摘录，不阻断解析。

## 8. 页面与验收

“记忆与偏好”显示当前文档、有效覆盖节点数、最近整理时间、待更新节点数。“重新整理”仅重建缓存，重复点击沿用 Job 取消与等待，不增加 revision/generation；失败可重试，不改正文。

1. 千节点文档的请求仍只携带有界选定上下文，计入图片后不突破本地预算。
2. 纯文字正文能参与上下文；修改备注、修正文字、删除或跨章移动后，不再使用旧段。
3. 长引言提示精简而不是静默截断；没有引言则省略 `brief`。
4. 记忆不跨章节、不跨未知缺口、不重复发送同一节点；用户清空的修正文字不被旧摘要复活。
5. 删除节点保留历史轮次，删除文档才清理轮次；图片已删时回放明确说明素材不可用。
