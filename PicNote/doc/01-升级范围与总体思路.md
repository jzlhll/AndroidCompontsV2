# 竹节笔记 / Bambootes · 01 升级范围与总体思路

## 1. 是什么

在 PicNote 的节点链上加一层“图片转文字”的解析能力。用户把截图、照片按链序收集好，补上自己的文字，点一次解析：模型逐节点产出笔记文字，用户在节点页校对，文档页和导出继续由本地规则按链序生成。

模型不改文档结构。节点与章节的增删、类型、顺序、标题全部由用户决定，模型只填写每个图片节点的文字与摘要标签。这保证解析失败、取消或断网都不会破坏已有文档。

## 2. 沿用基线

以下能力保持不变，本组不重新设计，实现时以 `PicNote` 现有文档与代码为准：

| 能力 | 现状 |
| --- | --- |
| 文档模型 | `DocumentEntity` + `NodeEntity` 有序链，`sort_key` 间隔整数 |
| 文档生成 | `markdownNodes()` 按链序输出，`doc.md` 为可重建镜像 |
| 节点类型 | `title / introduction / chapter / body`，前两位固定，链尾插入项不入库 |
| 页面结构 | 单 `ComponentActivity` + Navigation 3，两 Tab（`节点 / 文档`） |
| 节点交互 | 圆点菜单只向前插入；拖动仅用于合并；上移下移走菜单 |
| 编辑 | 独立全屏编辑页 `EditorScreen`，保存后回读并刷新首页 |
| 抽屉 | 我的文档、＋新建、外观、设置 |
| 主题 | `ThemePalette` 五套方案，默认 Sage |
| 图片来源 | Photo Picker 手动选图 + 前台进入检查的待选区 |
| 图片存储 | PasteHub AAR 转 WebP 质量 90，存 `filesDir/documents/<id>/media/` |
| 导出 | ZIP + `doc.md`，图片相对路径 |
| 教程 | `WelcomeDocumentId` 内置文档，隐藏素材入口 |

唯一改动到现有行为的是 Markdown 组织：`markdownNodes()` 在每个非章节节点内按“图片 → 解析文字 → 用户备注”输出，其余基线不变；README 与 `doc.md` 镜像机制继续复用。

## 3. 新增能力

| 能力 | 作用 | 详见 |
| --- | --- | --- |
| 解析状态 | 每个图片节点有 `pending / parsing / parsed / stale / failed` | 02 |
| 解析轮次 `Turn` | 一次提交的输入快照、输出原文与提交结果，可回放 | 02 |
| NDJSON 流 | 逐节点返回结果，收到即提交，不必整批成功 | 02 |
| 提交入口与遮罩 | 底部“解析 N”，遮罩显示阶段、已保存进度、停止 | 04 |
| 解析记录页 | 顶栏入口的全屏页，回放历史轮次 | 04 |
| 记忆与偏好 | 起始信息、章节索引、节点摘要、分段记忆、写作偏好 | 03 |
| 派生压缩图 | 送模型的 JPEG 副本，长边 ≤1568，缓存可清理 | 05 |
| Room v4 | `node_parse / turns / turn_items / memory_segments` | 05 |

## 4. 不纳入本版的设计

以下方案与 PicNote 现有实现冲突，或体积远超收益，不纳入本版：

| 不纳入项 | 原因 |
| --- | --- |
| 第三个 Tab “会话” | 两 Tab 布局与 `HorizontalPager` 已定稿；轮次回放改为顶栏全屏页 |
| 前台服务 + `ContentObserver` + `FileObserver` 常驻捕获 | 前台进入检查与 Photo Picker 已覆盖同一需求，且不需要 `dataSync` 常驻服务 |
| 截图判定规则（路径含 `screenshot`、宽高比容差） | 待选区接受全部新图，由用户勾选，不做判定 |
| 自动追加开关 | 新图只进待选区，是否入链由用户确认 |
| 待选区“加载更早”分页 | 现有待选区一次列出全部候选 |
| 长按拖拽排序 | 排序走菜单上移下移；拖动只用于合并 |
| 菜单“插入上一个 / 插入下一个” | 只向前插入，链尾入口负责追加 |
| 全屏模糊编辑遮罩 | 独立全屏编辑页已定稿 |
| 自动生成的“起始节点” | 固定第 2 位的引言节点承担起始信息 |
| `document_section`、`section_id`、`doc_revision` | 文档是节点链的确定性投影，不存在独立章节实体 |
| 章节操作协议（`append_section / replace_section / insert_after / remove_section`） | 模型不写文档结构 |
| `stale_target`、“顺序待同步”、“按当前节点重建文档” | 链序变化即文档变化，无需同步与版本切换 |
| `commit_id` 提交分组与 `node_ids / op_ids` 完整性校验 | 节点级提交，一条结果一个事务 |
| 来源映射表与节末“来源 N 个节点” | 节点自身就是来源 |
| 跨文档引用与“引用历史文档” | 首版不做，避免引用失效与上下文污染 |
| 本地全文索引与中文双字符召回 | 首版只用结构化上下文选择，不建检索索引 |
| 固定绿色配色 `#2E7D5B` | 沿用五套主题，新增状态色进 `ThemePalette` |
| 局部 OCR、向量库、模型包下载 | 与现有“本地不上模型”的边界一致，不在首版 |

## 5. 对象

| 对象 | 说明 |
| --- | --- |
| `Document` | 一篇文档，必填标题、一条有序节点链、本地图片，沿用现有表 |
| `Node` | 标题、引言、章节标题或正文，沿用现有表 |
| `NodeParse` | 新增，1:1 附着在正文节点上：解析文字、解析时的内容 hash、状态、来源、摘要与标签 |
| `Turn` | 新增，一次提交：文档、模式、状态、批次数、提交结果 |
| `TurnItem` | 新增，轮次内每个节点：批次序号、内容 hash、是否已提交、错误 |
| `MemorySegment` | 新增，一段连续已解析节点的紧凑索引，用于后续批次上下文 |
| `ParsePreference` | 新增，用户显式设置的写作偏好与模型服务配置 |

节点文字分两处：

| 字段 | 归属 | 用途 |
| --- | --- | --- |
| `body_markdown` | 用户 | 用户自己的备注，现有字段与交互不变 |
| `parsed_markdown` | 模型或用户修正 | 截图讲什么，模型产出，用户可编辑 |

Markdown 与文档页按“图片 → 解析文字 → 用户备注”输出；两者都为空时该节点只输出图片。

## 6. 数据流

```text
截图/照片 → 待选区（现有）→ 勾选追加为 body 节点 → 节点状态 pending
  → 提交：冻结待解析节点 → 派生压缩图 → 分批请求 → NDJSON 逐节点返回
  → 每节点本地事务提交 → parsed → 文档页与 doc.md 重新生成
  → 分段记忆更新 → 轮次留档
```

## 7. 约束

1. 一次只允许一个活跃轮次，由独立于页面的执行器持有 Job、Call 与互斥；切换 Tab、切文档、收起遮罩都不启动新请求。
2. 模型输出只代表候选；节点文字在本地事务提交成功后才显示为“已解析”。
3. 素材未变化不重传图片：只有 `content_hash` 变化的节点重新进入批次，纯排序、纯文字修正不触发识别。
4. 取消或中断只丢未提交节点，已提交节点保留；进程退出不需要清理 `parsing`，该状态只在内存中。
5. 用户手写备注不被模型覆盖；解析文字也只在用户主动重新解析时才被新结果替换。
6. 全本机持久化，无账号与云同步；解析必须联网，请求只发送本批素材与本章选定上下文。
7. 密钥只存本机应用私有目录，不写入日志、轮次快照与导出包。

## 8. 首版验收

1. 没有配置模型服务时，解析入口禁用并提示去设置；配置后可解析，节点依次显示 `parsing → parsed`。
2. 一次解析 3 个节点，中途取消，已保存的节点保留、剩余回到 `pending`，重复提交不会重复写入。
3. 只调整顺序或只修正解析文字，不会重新上传图片，也不会把节点回退为 `pending`。
4. 修改图片后节点显示“待更新”，下次解析只重传该节点。
5. 1000 个已解析节点时请求仍受预算限制，不携带全部历史图片与全文。
6. 关闭网络或进程被杀，重启后本轮已提交节点仍为 `parsed`，其余为 `pending`。
7. 文档页与导出只按链序输出图片、解析文字与用户备注，未解析节点不生成占位结论。
