# 竹节笔记 / Bambootes · 05 存储、配置与迁移

## 1. Room v4

本版规划在 v3 的 `documents / nodes / node_images / source_images / media_* / pending_media` 之外新增四张表，数据库版本升级到 4。当前仍为 v3；实现时同步提交 `schemas/com.allan.picnote.data.PicNoteDatabase/4.json`、实体、DAO 与迁移。以下 SQL 是目标结构，不能仅改文档就认为迁移已实现。

```sql
CREATE TABLE IF NOT EXISTS `node_parse` (
  `node_id` TEXT NOT NULL,
  `parsed_markdown` TEXT NOT NULL DEFAULT '',
  `parsed_hash` TEXT NOT NULL DEFAULT '',
  `state` TEXT NOT NULL DEFAULT 'pending',
  `origin` TEXT NOT NULL DEFAULT 'model',
  `detail` INTEGER NOT NULL DEFAULT 0,
  `summary` TEXT NOT NULL DEFAULT '',
  `tags` TEXT NOT NULL DEFAULT '[]',
  `updated_at` INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY(`node_id`),
  FOREIGN KEY(`node_id`) REFERENCES `nodes`(`id`) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS `index_node_parse_state` ON `node_parse`(`state`);

CREATE TABLE IF NOT EXISTS `turns` (
  `id` TEXT NOT NULL,
  `document_id` TEXT NOT NULL,
  `mode` TEXT NOT NULL,
  `status` TEXT NOT NULL,
  `batch_count` INTEGER NOT NULL DEFAULT 0,
  `node_total` INTEGER NOT NULL DEFAULT 0,
  `committed_count` INTEGER NOT NULL DEFAULT 0,
  `error` TEXT,
  `created_at` INTEGER NOT NULL,
  `finished_at` INTEGER,
  PRIMARY KEY(`id`),
  FOREIGN KEY(`document_id`) REFERENCES `documents`(`id`) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS `index_turns_document_id_created_at` ON `turns`(`document_id`, `created_at`);

CREATE TABLE IF NOT EXISTS `turn_items` (
  `turn_id` TEXT NOT NULL,
  `node_id` TEXT NOT NULL,
  `batch_index` INTEGER NOT NULL DEFAULT 0,
  `content_hash` TEXT NOT NULL DEFAULT '',
  `replace_user_text` INTEGER NOT NULL DEFAULT 0,
  `committed` INTEGER NOT NULL DEFAULT 0,
  `error` TEXT,
  PRIMARY KEY(`turn_id`, `node_id`),
  FOREIGN KEY(`turn_id`) REFERENCES `turns`(`id`) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS `memory_segments` (
  `id` TEXT NOT NULL,
  `document_id` TEXT NOT NULL,
  `start_node_id` TEXT NOT NULL,
  `end_node_id` TEXT NOT NULL,
  `node_ids` TEXT NOT NULL,
  `text` TEXT NOT NULL,
  `token_estimate` INTEGER NOT NULL DEFAULT 0,
  `updated_at` INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY(`id`),
  FOREIGN KEY(`document_id`) REFERENCES `documents`(`id`) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS `index_memory_segments_document_id` ON `memory_segments`(`document_id`);
```

`turn_items` 不设节点外键：节点删除后历史轮次仍保留，回放显示“节点已删除”。`replace_user_text` 只保存本轮对该节点的覆盖确认；主键不能替代 `committed` 校验。`tags` 与 `memory_segments.node_ids` 都使用 JSON 数组编码。状态取值、错误分类和事务计数规则见 02。

## 2. 迁移与旧安装

- `MIGRATION_3_4` 只建四张新表与索引，保留全部旧业务表、图片和源 URI 映射。旧图片节点缺少 `node_parse` 时按 `pending` 显示，不批量创建结果、不自动上传。
- 仓库同时存在 `schemas/.../1.json / 2.json / 3.json`。移除 `fallbackToDestructiveMigration(dropAllTables = true)` 时必须提供完整的 `1 → 2 → 3 → 4` 路径，不能只注册 `3 → 4` 导致 v1/v2 安装无法打开。
- `1 → 2` 按已存 schema 重建媒体索引结构：保留文档、节点和图片身份/文件；用旧 `source_identity` 关联旧媒体快照恢复可确定的 `source_uri`，无法确定时留空，不猜测。创建 `source_images` 并补齐可确定映射；保留可映射的待选项，扫描基线设为无效后由既有前台流程重建，不把整个相册当新图。
- `2 → 3` 按 v3 schema 重建 `node_images`，保留 ID、节点归属、hash、图片顺序、文件名、尺寸、URI，只去除废弃 `name` 列。外键、索引、非空约束与 schema 对齐，重建过程中不能级联删除素材映射。
- 迁移不复制或重新压缩图片。`IF NOT EXISTS` 不是结构一致性检查；Room 校验目标 schema，任一步失败回滚并保留原库，不能降级清库。
- 中断后由 Room 的版本与事务恢复；已成功到 v4 再次启动不重跑迁移。实施验收覆盖三种旧版本、升级中断与升级后重复打开，不以“执行同一 SQL 两次成功”代替真实升级。
- 对未知或更高版本明确报兼容错误并保留数据。过去已被破坏性迁移删掉的数据无法由本版恢复。

## 3. 偏好与配置

| 存储 | 键 | 值 |
| --- | --- | --- |
| DataStore `parse_preferences.preferences_pb` | `language` | `system / zh / en` |
| 同上 | `structure` | `outline / paragraph` |
| 同上 | `terms` | `preserve / translate`，意译目标随输出语言 |
| 同上 | `length` | `short / normal / detailed` |
| 同上 | `endpoint` | 完整 HTTPS Chat Completions 地址；首版只支持这一协议，不靠路径片段猜协议 |
| 同上 | `model` | 模型名，需支持图片输入与流式文字输出 |
| 同上 | 容量配置 | 输入窗口、输出额度、图片数量/尺寸/字节限制与图片 token 估算规则，见 03 |
| SharedPreferences `parse_service` | `api_key` | 密钥，应用私有，界面掩码显示 |

- 复用现有 DataStore 写法（`AppearancePreferences`、`PermissionPreferences` 的结构）。
- 密钥不写入 DataStore、不进日志、不进轮次快照与导出包；读取失败按未配置处理，解析入口显示可点击的“配置解析服务”。
- 偏好保存失败提示并保留原值，不阻断解析以外功能；本轮冻结配置，不在批次之间切换服务或语言。`system` 在本轮开始时解析成明确语言代码。
- 服务地址不得内嵌账号、密钥或鉴权查询参数；密钥只进入鉴权头，不自动向跨域重定向转发。沿用当前 `android:allowBackup="false"`，配置与密钥不进入系统备份。卸载只删除本机副本，不会撤销服务端密钥。

## 4. 文件目录

```text
filesDir/documents/<document_id>/
  doc.md
  media/<hash>.webp
  parse/turns/<turn_id>.ndjson
  parse/turns/<turn_id>/input-<batch_index>.json
  parse/turns/<turn_id>/sse-<batch_index>.ndjson
cacheDir/
  parse/<image_hash>-<profile_hash>.jpg
  shared/exports/picnote-<uuid>.zip
```

- `media/` 与 `doc.md` 规则不变；`parse/` 是轮次留档，删除文档时随目录一起清理。
- `cacheDir/parse/` 是可重建缓存，清理不影响节点状态、解析文字与导出。
- 文档删除后的残留目录统一交给 `PicNoteCleaner` 回收；Room 外键负责轮次和记忆级联，不需要靠启动清扫补偿正常事务。解析缓存扩展同一清理类，按最近 7 天未使用或总量超过 200 MB 时从旧到新清理；活跃请求正在使用的文件排除在外，写入采用临时文件加原子替换。
- `sse-<batch_index>.ndjson` 逐事件记录 `{sequence, received_at, event, delta, finish_reason, usage}` 中服务实际提供的允许字段；文件路径确定轮次与批次，不保存 HTTP 头、完整请求体或未筛选的服务端错误。它记录服务 SSE 的展示数据，与 `<turn_id>.ndjson` 的业务解码/提交结论分开；会话 Tab 组合两者查看，不以业务行还原并冒充原始 SSE。
- 输入快照在发出请求前原子写入，失败则不发送该批。事件留档是诊断记录，数据库中的提交结果才是权威；崩溃后可能缺最后一条事件，回放应标明记录不完整，不能据文件尾部回滚数据库。落档失败停止后续发送但保留已提交结果。
- 快照保留当时的节点编号、稳定 ID、实际发送文字、图片 hash/尺寸/压缩策略及提交结论，不保留 base64、鉴权头或源 URI。业务文本单批上限沿用 02；SSE 与业务记录、输入快照合计的单轮留档上限 16 MiB；输入快照超过剩余额度则不发该批，流式输出触顶则停止本轮并提示。只读回放不保证原图仍存在，也不承诺重新联网复现。

## 5. 派生压缩图

模型输入使用独立 JPEG 副本，不改动正式 WebP：

| 项目 | 值 |
| --- | --- |
| 普通模式 | 长边 ≤1568px，quality 80，400KB 为软目标 |
| 精细识别（`detail = 1`） | 长边 ≤2048px，quality 85，仅在接口允许时使用 |
| 缓存键 | 每张图独立使用 `image_hash + profile_hash`；profile 含 `detail`、实际尺寸、quality、编码/策略版本与接口限制，不能用一个节点 hash 覆盖多张图片 |
| 编码 | 优先复用 PasteHub 可用 JPEG 编码接口；回退编码也遵循同一尺寸、quality 和透明底色策略，不能把精细模式固定降到 quality 80 |
| 失败 | 提示“图片处理失败”，节点保持原状态；不写半成品，单节点超过接口硬上限时提示拆分或调整素材 |

400 KB 仅为软目标；初版不为追逐此目标无限降质。超过接口字节硬上限时尝试有界编码策略，仍超限则停止并说明原因。普通/精细两种模式都不能保证极长截图的小字可辨；提示用户裁剪或拆分，精细模式也不能恢复正式 WebP 已丢失的细节。派生图可重建，不能替代正式图片；相同节点中的不同图片必须产生不同缓存文件。

## 6. 网络

- 首版只支持明确配置的 Chat Completions 多模态 SSE 适配器，设置 `stream = true`；其它协议需要独立适配器，不能只换地址就宣称支持。业务 NDJSON 是模型文字内容中的约定，不等于服务自身 SSE JSON。
- 组装 SSE 事件后提取单个选择项的文字增量，处理注释、空事件、多 `data:` 行、UTF-8 跨块、服务结束标记与截断终止原因；文字增量同时交给会话展示与 02 的有界 NDJSON 解码器。只有业务完整成功才标记本批完成。
- 连接超时 15 秒、读超时 120 秒；60 秒无业务进展或单批总耗时达到 5 分钟即停止。心跳不能无限延长业务超时。HTTP/解析异常统一进入轮次状态，协程取消仍按取消流程传播。
- 错误记录只保存 HTTP 状态、客户端归类错误码与允许的请求标识；不持久化原始响应体、完整服务端错误或可能包含鉴权信息的异常 URL。界面展示可操作原因，401/配置错误要求先修正设置。
- 不自动重发整个轮次；重试与重新解析均由用户触发。取消关联 `Call.cancel()`、Job 与事务的结构化等待，网络等待不占仓储锁。
- 网络能力接入时确认最终 Manifest 有 `INTERNET` 权限并沿用 HTTPS 策略；本版不新增常驻服务、通知权限或图片库权限要求。Photo Picker 导入的已保存图片也可解析。

## 7. 日志

复用 `logd / loge / logEx`，按 `startupId` 关联，不记录正文、图片 URI 与密钥：

| 事件 | 字段 |
| --- | --- |
| `parse_start` | `startupId, turnId, documentId, nodeCount, batchCount` |
| `parse_batch` | `turnId, batchIndex, imageCount, estimatedTokens` |
| `parse_commit` | `turnId, nodeId, ok, elapsedMs` |
| `parse_end` | `turnId, status, committed, failed, elapsedMs` |

`parse_commit` 失败记录可归因错误码，不打印解析文字。

## 8. 兼容与风险

| 风险 | 处理 |
| --- | --- |
| 旧安装升级后大量节点显示待解析 | 不自动提交；提交前显示数量与分批提示 |
| 迁移中断 | 事务回滚，重进重试；不降级清库 |
| 服务端协议与本文不一致 | 达到无效行或缓冲限制即停止；当前已发送批次的未提交节点 `failed`，已提交结果保留 |
| token 估算偏差 | usage 校准后续估算，超窗口停止并让用户调整后重试未成功节点 |
| 大图与长图 | 精细识别与拆批结合，仍超限时提示用户拆节点，不静默丢图 |
| 密钥泄露面 | 仅本机私有存储且排除备份/日志/导出；撤销需去服务端操作 |

## 9. 验收

1. v1、v2、v3 各自升级到 v4，文档、节点、图片和可恢复的 URI 映射保留，目标 schema 与实体一致。
2. 升级后不自动发起解析；未配置服务时入口为“配置解析服务”，其它功能可用。
3. 删除文档后 `parse/` 目录、轮次与分段记忆一并清理，`cacheDir/parse/` 清理不影响正式图片。
4. 日志中不出现解析文字、图片 URI 与密钥；导出 ZIP 沿用当前按标题命名的 Markdown 与 `media/`，不包含 `parse/`；本地镜像仍名为 `doc.md`。
5. 迁移中断可恢复、升级后重复启动不重跑；一个节点多图、不同识别模式的缓存互不覆盖，留档失败不伪造提交失败或重新识图。
