# 竹节笔记 / Bambootes · 05 存储、配置与迁移

## 1. Room v4

现有 `documents / nodes / node_images / source_images / media_*` 不变，新增四张表。数据库版本 3 → 4，`exportSchema` 继续开启，提交 `schemas/.../4.json`。

```sql
CREATE TABLE IF NOT EXISTS `node_parse` (
  `node_id` TEXT NOT NULL,
  `parsed_markdown` TEXT NOT NULL DEFAULT '',
  `parsed_hash` TEXT NOT NULL DEFAULT '',
  `state` TEXT NOT NULL DEFAULT 'pending',
  `origin` TEXT NOT NULL DEFAULT 'model',
  `detail` INTEGER NOT NULL DEFAULT 0,
  `summary` TEXT NOT NULL DEFAULT '',
  `tags` TEXT NOT NULL DEFAULT '',
  `updated_at` INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY(`node_id`),
  FOREIGN KEY(`node_id`) REFERENCES `nodes`(`id`) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS `index_node_parse_state` ON `node_parse`(`state`);

CREATE TABLE IF NOT EXISTS `turns` (
  `id` TEXT NOT NULL,
  `document_id` TEXT NOT NULL,
  `mode` TEXT NOT NULL,
  `status` TEXT NOT NULL,
  `batch_count` INTEGER NOT NULL DEFAULT 0,
  `node_total` INTEGER NOT NULL DEFAULT 0,
  `committed_count` INTEGER NOT NULL DEFAULT 0,
  `error` TEXT,
  `created_at` INTEGER NOT NULL,
  `finished_at` INTEGER,
  PRIMARY KEY(`id`),
  FOREIGN KEY(`document_id`) REFERENCES `documents`(`id`) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS `index_turns_document_id_created_at` ON `turns`(`document_id`, `created_at`);

CREATE TABLE IF NOT EXISTS `turn_items` (
  `turn_id` TEXT NOT NULL,
  `node_id` TEXT NOT NULL,
  `batch_index` INTEGER NOT NULL DEFAULT 0,
  `content_hash` TEXT NOT NULL DEFAULT '',
  `committed` INTEGER NOT NULL DEFAULT 0,
  `error` TEXT,
  PRIMARY KEY(`turn_id`, `node_id`),
  FOREIGN KEY(`turn_id`) REFERENCES `turns`(`id`) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS `memory_segments` (
  `id` TEXT NOT NULL,
  `document_id` TEXT NOT NULL,
  `start_node_id` TEXT NOT NULL,
  `end_node_id` TEXT NOT NULL,
  `node_ids` TEXT NOT NULL,
  `text` TEXT NOT NULL,
  `token_estimate` INTEGER NOT NULL DEFAULT 0,
  `updated_at` INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY(`id`),
  FOREIGN KEY(`document_id`) REFERENCES `documents`(`id`) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS `index_memory_segments_document_id` ON `memory_segments`(`document_id`);
```

`turn_items` 不设节点外键：节点删除后历史轮次仍保留，回放显示“节点已删除”。

## 2. 迁移

- 新增 `MIGRATION_3_4`，只建四张表与索引，不改动既有表与数据。
- 数据库构建改为 `addMigrations(MIGRATION_3_4)`，移除 `fallbackToDestructiveMigration(dropAllTables = true)`。
- 迁移后既有图片节点没有 `node_parse` 记录，界面按 `pending` 呈现，但不在启动时自动提交，需用户主动解析。
- 迁移不复制、不压缩、不迁移图片文件；`media/` 与 `source_images` 保持原样。
- 迁移可重复执行：全部使用 `IF NOT EXISTS`；中断后重进由 Room 事务回滚重试。

## 3. 偏好与配置

| 存储 | 键 | 值 |
| --- | --- | --- |
| DataStore `parse_preferences.preferences_pb` | `language` | `system / zh / en` |
| 同上 | `structure` | `outline / paragraph` |
| 同上 | `terms` | `preserve / translate` |
| 同上 | `length` | `short / normal / detailed` |
| 同上 | `endpoint` | 服务地址，含 `/chat/completions` 时按 SSE 请求 |
| 同上 | `model` | 模型名 |
| SharedPreferences `parse_service` | `api_key` | 密钥，应用私有，界面掩码显示 |

- 复用现有 DataStore 写法（`AppearancePreferences`、`PermissionPreferences` 的结构）。
- 密钥不写入 DataStore、不进日志、不进轮次快照与导出包；读取失败按未配置处理，解析入口置灰并提示去设置。
- 偏好保存失败提示并保留原值，不阻断解析以外功能。

## 4. 文件目录

```text
filesDir/documents/<document_id>/
  doc.md
  media/<hash>.webp
  parse/turns/<turn_id>.ndjson
  parse/turns/<turn_id>/input-<batch_index>.json
cacheDir/
  parse/<content_hash>-<policy_version>.jpg
  shared/exports/picnote-<uuid>.zip
```

- `media/` 与 `doc.md` 规则不变；`parse/` 是轮次留档，删除文档时随目录一起清理。
- `cacheDir/parse/` 是可重建缓存，清理不影响节点状态、解析文字与导出。
- 启动清理在现有 `cleanup()` 中增加：删除不存在文档的 `parse/` 目录与孤儿 `memory_segments`；`cacheDir/parse/` 按最近 7 天未使用或总量超过 200 MB 时从旧到新清理。

## 5. 派生压缩图

模型输入使用独立 JPEG 副本，不改动正式 WebP：

| 项目 | 值 |
| --- | --- |
| 普通模式 | 长边 ≤1568px，quality 80，400KB 为软目标 |
| 精细识别（`detail = 1`） | 长边 ≤2048px，quality 85，仅在接口允许时使用 |
| 缓存键 | `content_hash + policy_version`，文件名 `<content_hash>-v1.jpg` |
| 编码 | 复用 PasteHub `ImageCodec` 的 JPEG 输出；不可用时回退 `Bitmap.compress(JPEG, 80)` |
| 失败 | 提示“图片处理失败”，该节点保持原状态，不写半成品；超接口硬上限时拆批并提示 |

软目标超出时先降 quality 到 70，再考虑缩短长边；不允许压到文字不可辨认。派生图不写入 `filesDir`，缓存清理后按需重新生成。

## 6. 网络

- OkHttp 手写 SSE：`Accept: text/event-stream`，`Authorization: Bearer <key>`，连接 15s、读超时 120s。
- 逐 `data:` 行解码并累积文本增量；连续 60s 无任何数据视为中断，停止该批并提示。
- 取消使用 `Call.cancel()` 并与 Job 取消一起结构化等待当前事务，沿用现有写操作协调方式。
- 单批失败不自动整轮重试；用户点“重试”或再次提交才发起新轮次。
- 服务端返回非 2xx 时读响应体前 1KB 记录到 `turns.error`，界面只显示归类后的提示。

## 7. 日志

复用 `logd / loge / logEx`，按 `startupId` 关联，不记录正文、图片 URI 与密钥：

| 事件 | 字段 |
| --- | --- |
| `parse_start` | `startupId, turnId, documentId, nodeCount, batchCount` |
| `parse_batch` | `turnId, batchIndex, imageCount, estimatedTokens` |
| `parse_commit` | `turnId, nodeId, ok, elapsedMs` |
| `parse_end` | `turnId, status, committed, failed, elapsedMs` |

`parse_commit` 失败记录可归因错误码，不打印解析文字。

## 8. 兼容与风险

| 风险 | 处理 |
| --- | --- |
| 旧安装升级后大量节点显示待解析 | 不自动提交；提交前显示数量与分批提示 |
| 迁移中断 | 事务回滚，重进重试；不降级清库 |
| 服务端协议与本文不一致 | 连续 3 行解析失败即终止该批，节点保持原状态并提示 |
| token 估算偏差 | 记录服务返回 usage 校准估算，超窗口时拆批重发未提交节点 |
| 大图与长图 | 精细识别与拆批结合，仍超限时提示用户拆节点，不静默丢图 |
| 密钥泄露面 | 仅本机应用私有存储，日志与导出均不包含；卸载即失效 |

## 9. 验收

1. 从 v3 升级到 v4，文档、节点、图片与 `doc.md` 全部保留，`schemas/4.json` 与实体一致。
2. 升级后不自动发起解析；未配置服务时解析入口置灰，其它功能可用。
3. 删除文档后 `parse/` 目录、轮次与分段记忆一并清理，`cacheDir/parse/` 清理不影响正式图片。
4. 日志中不出现解析文字、图片 URI 与密钥；导出 ZIP 只含 Markdown 与图片。
5. 迁移连续执行两次不报错，不产生重复表或孤儿记录。
