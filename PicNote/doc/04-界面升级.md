# 竹节笔记 / Bambootes · 04 界面升级

本文只写升级涉及的界面增量，三张原型见文末；其它页面以本文 Markdown 约定为准。首页增加会话 Tab；页面骨架、抽屉、编辑页表单、主题切换、教程与导出沿用 `PicNote` 现有设计（[03-程序界面设计.md](../03-程序界面设计.md)、[05-节点设计.md](../05-节点设计.md)），不再重复。

## 1. 全局

- 首页为 `节点 / 文档 / 会话` 三个等宽 Tab，由 `HorizontalPager` 承载，仍只点击切换。标题栏 54dp 与 Tab 指示线 51dp 不变；每个文档的三个 Tab 分别保存滚动位置。
- 会话直接作为首页第三页。`MemoryRoute(documentId)`（记忆与偏好）为普通全屏目的地，明确所属文档，沿用 220ms 横向进退动画与顶栏返回箭头。尚无当前文档时隐藏文档记忆入口；全局写作偏好仍可从设置访问。
- 会话的入口为第三个 Tab；顶栏“⋯”保留文档操作，抽屉底部在“外观”“设置”之间新增“记忆与偏好”。
- 设置页在“语言”下新增“解析服务”，配置服务、模型、密钥和容量参数；配置页说明将发送的素材范围，保存配置本身不发送图片。
- 三个 Tab 共享同一个执行器状态。节点/文档使用浮动解析入口，会话在当前轮次区提供进度与控制，不重复叠放胶囊；切换保留各自滚动位置。活跃轮次所属文档的修改入口暂不可用，阅读和导出可用；其它文档仍可编辑，前台图片检查继续收集候选。

## 2. 节点页

### 2.1 解析条

图片卡片下方新增一行解析条，宽与卡片一致，最小高 48dp，字体放大时随内容增高：

| 状态 | 左侧标签 | 右侧文字 |
| --- | --- | --- |
| `pending` | “待解析” | 无（整行留白） |
| `parsing` | 进度点 + “解析中”或“本轮排队” | 无 |
| `parsed` | “已解析” | 解析文字最多 2 行，超出省略 |
| `stale` | “待更新” | 旧解析文字最多 2 行 |
| `failed` | “失败 · 重试” | 有旧文字时保留两行预览；整行点击仅重试该节点 |

- 标签 12sp，左侧圆点 6dp，标签底色为状态色 12% 透明、圆角 6dp，与卡片右上角类型标签同一视觉体系。
- 解析文字 14sp、行高 20dp、颜色 `onSurfaceVariant`，不做内部滚动，超出省略；完整内容在编辑页。
- 无图片的正文节点、标题、引言、章节标题不显示该行；`尚未解析` 不显示占位结论。
- 非失败状态点击解析条进入编辑页；失败条发起单节点重试，有用户修正文字时先确认覆盖。失败状态仍可用卡片右上角编辑按钮查看和修改旧文字。活动轮次内进入所属文档编辑页为只读，不隐式取消任务。

### 2.2 状态标记

状态只出现在解析条的标签与圆点上，不给整张卡片染色，不改变图片比例、圆角与卡片间距。左侧轴栏保持竹枝、编号与类型色不变，不新增状态图形。

批量提交后按链序自上而下依次变化，单节点提交成功即转“已解析”，不等整批结束。

### 2.3 底部操作

保留下层左侧新图框与右侧相册 `＋` FAB，解析胶囊放在它们上方的第二层，不把三个入口挤在窄屏同一行。节点与文档 Tab 使用同一操作容器；会话的布局见第 4 节：

| 元素 | 尺寸与样式 |
| --- | --- |
| 上层解析胶囊 | 最小高 56dp、圆角 16dp，`secondaryContainer` 底；右对齐，长文档名可省略，点击区及进度不能被截掉 |
| 下层相册 FAB | 56dp、`primary` 底、图标 `＋`；仍是相册导入，不冒充创建节点菜单 |
| 下层新图框 | 48dp 缩略图与“新增 N”，与 FAB 保留间距，窄屏优先收缩文字而非点击区 |
| 内容留白 | 无解析行时沿用 96dp；有解析行时最少 160dp，按操作容器实测高度、间距和系统栏增大，节点与文档 Tab 一致 |

- 无活跃轮次时，`N` 为当前文档 `pending / stale / failed` 节点之和；`N = 0` 不显示解析入口，教程不提供解析。
- `N > 0` 且未配置服务时显示可点击“配置解析服务”，进入设置；不能同时设计成 disabled 又依赖点击提示。
- 有活跃轮次时，上层唯一入口始终显示“文档名 · 解析中 已保存/总数”，替代任何文档的“解析 N”。切换文档或浏览教程也能查看正在进行的任务，不能把其它文档的统计拼入该进度。
- 所属文档的导入/追加操作暂不可用；新图框仍可展开查看待选区。若已切到其它普通文档，则可按当前文档正常导入。
- 解析入口不占正文内容，不随文档导出；可放大的字体、键盘与系统栏不能遮住最后一个真实节点或链尾入口。

### 2.4 文档 Tab

`DocumentPreview` 继续消费 `markdownNodes()` 的同一投影：标题一个 H1、主引言引用、章节 H2；正文按“图片 → 已保存解析文字 → 用户备注”输出。图片保持真实比例，状态标签、编号和轮次进度均不写入正文或 ZIP。

待更新或失败的旧解析文字保留在正文，未提交流式候选不进入正文。当前文档存在旧结果时，在阅读内容之外显示“部分解析内容待更新”提示并提供返回节点 Tab 的入口，导出前同样说明将包含现有已保存文字；不静默把旧结论称为最新。旧结果为空时不显示占位结论。运行中阅读和导出使用同一仓储快照，后续提交不会改变已生成的 ZIP。

## 3. 提交遮罩

全屏 `Dialog`（`usePlatformDefaultWidth = false`），底色 `MaterialTheme.colorScheme.surface`，不使用固定白色面板，不使用模糊背景：

| 区域 | 内容 |
| --- | --- |
| 顶部 | 所属文档名，右侧“收起”文字按钮；无关闭图标 |
| 进度 | 28dp 环形进度 + “已保存 1/3” + 阶段文案（读取图片 / 提取内容 / 组织文字） |
| 内容 | 已完成节点的解析文字流，14sp，`onSurfaceVariant`，可滚动；仅在用户原本位于底部时随新结果滚动；上翻阅读时显示“有新内容”入口 |
| 底部 | “停止解析”文字按钮（错误红）+ 已耗时 |

- “收起”或系统返回：遮罩关闭，任务继续；节点/文档 Tab 的全局胶囊显示“文档名 · 解析中 1/3”，点击再次展开；会话 Tab 在轮次区继续显示实时输出、进度和停止入口。
- 点“停止解析”：弹 `AlertDialog`，标题“取消本次解析？”，正文“已保存的节点会保留，其余保持原状态”，按钮“继续解析 / 取消解析”。
- 确认后按钮变为“正在停止…”，等待当前节点事务结束后关闭遮罩；等待期间禁止再次提交。
- 完成后关闭当前任务遮罩并提示“文档名：已保存 N 个节点”；部分失败则提示已保存数、失败数及原因，不误报整轮成功。用户正在其它页面时仅更新任务状态和提示，不自动跳回或打断编辑。
- 遮罩内容避开状态栏与导航栏安全区，进入动画 200ms，关闭系统动画时直接切换。

## 4. 会话 Tab：LLM SSE 记录

首页第三个 Tab 固定为“会话”，与节点、文档共同归属于当前文档。该页承载实时 SSE 输出和历史轮次，不需要等待解析结束；展示的是服务返回的流式内容，不以最终解析结果列表替代过程记录。

### 4.1 当前轮次

| 区域 | 内容 |
| --- | --- |
| 轮次头部 | “第 4 次解析”、当前批次、服务/模型名、开始时间与耗时 |
| 进度 | 当前阶段、已保存节点数/总数；接收文字不计作已保存 |
| 流式内容 | 按 SSE 接收顺序持续追加可展示文字增量，接收中标为“生成中”；业务 JSON 尚未闭合也能查看收到的片段 |
| 提交结果 | 节点事务成功后显示“节点 04 · 已保存”；协议或网络失败显示具体原因及已保存数量 |
| 控制 | 运行中提供“停止解析”和“展开进度”；停止复用遮罩的确认与结构化等待，不创建第二个任务 |

- 会话 Tab 直接订阅同一个执行器，不因切换、重组或重进而重连。流式刷新按短时间窗口合并 UI 更新，仍保留原始顺序；不能把每个 token 都创建为一张卡片。
- 用户位于底部时跟随追加；上翻查看旧记录时保持位置，显示“有新内容”，点击才回到底部。
- 选定轮次的“事件详情”可查看 SSE 事件序号、时间、文字增量、结束原因及服务返回的 usage。本地业务事件和 SSE 事件分别标识；无有效业务行的失败请求也保留已收到的输出。
- 当前文档没有活跃轮次、另一个文档正在解析时，顶部显示“文档名正在解析 · 查看会话”。点击切到任务所属文档的会话 Tab；不会把其它文档的记录插入当前文档。
- 会话页不显示相册 FAB、新图框或新增节点入口；全局图片检查仍工作，回节点/文档页可处理。无活跃轮次时，继续解析或重试从节点页发起。

### 4.2 历史轮次

历史轮次按时间倒序，每轮显示时间、状态（完成 / 中断 / 失败）、节点总数和已保存数量；运行中的本轮固定在列表顶部。展开后按接收时间正序阅读流式输出、批次分隔与提交结果，并可查看当时实际发送的输入快照。

- 历史只读，读取本地记录不重新发送请求、不再次提交节点。重试是新 `Turn`，保留原轮次。
- 列表按需加载，事件视窗每次最多 200 条，超长单条先显示前 2000 字并可展开/分段阅读；这只是展示窗口，不把本地完整记录静默截掉。实际留档达到上限或缺尾部时明确提示。
- 密钥、鉴权头、源 URI 与图片 base64 不落档；图片以数量、尺寸及可用的本地引用展示。
- 节点删除后显示“节点已删除”；原图被移除或事件留档不完整时明确提示，不把当时编号定位到别的节点。
- 当前文档无记录时显示“还没有会话记录”，并提供“前往节点”入口；切换文档按文档 ID 读取对应轮次，保留各自展开状态和滚动位置。

## 5. 记忆与偏好页

顶栏“记忆与偏好”，三组，均使用现有 Material 3 列表与单选样式：

| 分组 | 内容 |
| --- | --- |
| 写作偏好 | 语言（跟随系统 / 中文 / English）、结构（大纲 / 段落）、术语（保留原文 / 按输出语言意译）、篇幅（简短 / 标准 / 详细）；单选即时保存 |
| 当前文档记忆 | 当前文档名、已覆盖节点数、最近整理时间、待更新节点数；“重新整理”按钮 |
| 说明 | 一段说明：解析发送本批图片、备注、引言、写作偏好与本章选定上下文，不含其它文档 |

- “重新整理”触发分段重建，进行中禁用并显示进度，失败提示可重试，不影响节点状态与正文。
- 不提供 OCR 开关、模型包下载、向量库设置，也不提供跨文档引用入口。
- 有活跃轮次时可以查看与修改偏好，修改只影响下一轮。

## 6. 新增节点与编辑页

### 6.1 新增节点

使用现有 `EditRoute(documentId, nodeId = null, anchorId, kind)` 与 `EditorScreen` 创建态，不新增起始节点或文档创建流程。固定标题和主引言不能重复创建。

| 入口 | 目标 |
| --- | --- |
| 普通节点圆点菜单“向前插入” | 二级选择 `chapter / body`；`anchorId` 指向该节点 |
| 链尾文字“新增节点” | 直接选择 `chapter / body`，`anchorId = null` 表示追加 |
| 首页相册 `＋` 或待选区追加 | 沿用批量图片导入，每张新图单独成正文节点；不先打开一个多图草稿 |

正文创建态的固定顶栏为返回、“创建正文”、图片加号和保存。内容滚动区域显示完整比例图片、每图上下移与更多菜单（替换/移除）、“用户备注”多行输入；有图片才展示“精细识别”与说明。没有解析文字输入框、重新解析按钮或伪造的解析状态；说明“保存后加入节点，稍后手动解析”。章节创建态只提供必填章节标题。

- 图片准备完成且有图片或非空备注时允许保存正文；处理或保存中阻止重复点击。`detail` 与草稿一起保存，返回放弃不写任何解析配置。
- 仅保存成功才插入链并派生编号；有图节点 `pending`，无图正文无解析状态；均不自动上传。
- 插入锚点在保存前已删除或文档进入活跃轮次时拒绝写入并保留草稿，不静默改成链尾追加。返回有改动则确认放弃。
- 保存后回到原 Tab 和文档，节点 Tab 将新节点滚动到可见位置；编辑已有节点返回保持原位置。

### 6.2 编辑已有节点

有图片的正文在“用户备注”下提供解析区：状态、当前解析文字及“精细识别”。未成功解析时不显示可编辑的空结果输入框；已有结果允许修改或清空，只有实际改动文字才标记 `origin = user`。

“待解析/失败”提供“解析此节点/重试”，“已解析/待更新”提供“重新解析”。操作只能读取已保存内容，有未保存改动先提示保存或放弃；替换用户修正的结果前确认。切换精细识别仅改草稿，保存后才按素材 hash 判断状态。活跃轮次所属文档的编辑页只读，显示“本轮结束后可编辑”与进度入口。

删除最后一图时告知现有解析文字将保留为备注；正文合并确认也说明原解析文字转为备注、合并后图片需重新解析。具体事务规则见 02；不能因隐藏解析区而丢失文字。

## 7. 状态色

`ThemePalette` 新增四组状态色，仅用于解析条标签、圆点与遮罩进度；背景统一取同色 12% 透明，不新增独立底色：

| 主题 | 待解析 | 解析中 | 已解析 | 失败 |
| --- | --- | --- | --- | --- |
| Black | `#F0C674` | `#7DB4F0` | `#86E3A8` | `#F08C7C` |
| White | `#8A5A00` | `#1D4ED8` | `#166534` | `#B42318` |
| Dracula | `#FFB86C` | `#8BE9FD` | `#50FA7B` | `#FF7A85` |
| Sage | `#8A5B1F` | `#365F82` | `#2F6B45` | `#9E3B2F` |
| Alucard | `#846E15` | `#036A96` | `#14710A` | `#9E2B2B` |

“待更新”复用“待解析”色，文案不同。节点类型色、引言灰字、卡片底色与五套基础配色保持不变。
