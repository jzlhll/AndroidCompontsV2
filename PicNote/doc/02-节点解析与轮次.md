# 竹节笔记 / Bambootes · 02 节点解析与轮次

本文规定解析状态、批次、协议与提交边界。上下文见 [03-上下文与记忆.md](03-上下文与记忆.md)，界面见 [04-界面升级.md](04-界面升级.md)，持久化见 [05-存储、配置与迁移.md](05-存储、配置与迁移.md)。本文中的执行器与 `commitParse()` 为待实现接口。

## 1. 状态与输入身份

`node_parse` 附着在有图片的 `body` 节点上。旧节点没有记录时等价于默认值，不需要迁移时批量插入。

| 字段 | 说明 |
| --- | --- |
| `node_id` | 主键，删除节点时级联清理 |
| `parsed_markdown` | 已提交的解析文字，模型生成或用户修正 |
| `parsed_hash` | 最近一次成功解析的素材 hash；无成功结果时为空，修正文字不改此值 |
| `state` | 落库仅取 `pending / parsed / failed`；`failed` 表示当前素材最近一次尝试失败 |
| `origin` | `model / user`；仅实际修改解析文字时改为 `user` |
| `detail` | 精细识别选项，默认关闭 |
| `summary / tags` | 模型摘要 ≤160 token、JSON 字符串数组标签 |
| `updated_at` | 最近写入时间 |

`content_hash` 是图片 `hash` 按节点内 `sort_index` 排列的列表与 `detail` 的确定性摘要。使用带版本的规范化结构编码，不能直接拼接可歧义字符串。不含备注、节点链 `sort_key`、解析文字、引言与写作偏好。备注作为请求上下文留档，修改备注不自动重识图；需要按新备注改写时主动“重新解析”。本地 JPEG 缓存复用不等于远端免上传：每次显式重解析仍发送所需图片。

状态按下表优先级从上到下推导：

| 条件 | 显示状态 |
| --- | --- |
| 属于活跃轮次且尚未提交、尚未确定失败 | `parsing`，区分本轮排队与解析中 |
| `state = failed` | `failed`，保留旧文字与 `parsed_hash` |
| `parsed_hash` 非空且不等于当前 `content_hash` | `stale` |
| `parsed_hash` 非空且等于当前 `content_hash` | `parsed`，用户把解析文字清空也不自动重新识图 |
| 其它有图片正文节点 | `pending` |

`parsing` 只在执行器内存中；`stale` 由素材 hash 推导。无图片节点没有解析状态。

| 操作 | 结果 |
| --- | --- |
| 首次保存图片节点 | `pending`，不自动发网络请求 |
| 换图、增删图片、调整节点内图片顺序、切换 `detail` | 清除旧失败标记；有成功结果则按 hash 推导 `parsed / stale`，否则 `pending` |
| 只改备注、节点链顺序或解析文字 | 不改变素材 hash，不自动识图；相关上下文缓存失效 |
| 提交成功 | `state = parsed`，保存本次 hash 与结果 |
| 已发送批次发生网络、服务或协议失败 | 未成功节点立即 `failed` |
| 用户取消、尚未发送的排队节点 | 保持进入轮次前的状态，不能统一回退成 `pending` |
| 点重试 | 新建单节点轮次，开始时不抹掉持久化状态或旧文字 |

## 2. 选谁与快照

普通“解析 N”纳入当前文档所有 `pending / stale / failed` 图片节点，`N` 为节点数而非图片数。失败条的“重试”只纳入该节点；“重新解析”允许对已解析节点再次识图。

- 启动前先校验配置、可读图片与预算，再在仓储写锁内重读文档、创建 `Turn / TurnItem` 和冻结本轮输入，避免按钮显示数量与实际任务脱节。
- 配置页说明解析会发送本批图片、备注、引言、写作偏好与选定文档上下文；保存配置和保存节点均不发送图片，用户点击解析才发起请求。
- 含 `origin = user` 的结果将被替换时，提交前明确列出数量并确认；确认只授权本轮对应节点，写入 `turn_items.replace_user_text`。取消不创建轮次。模型结果、备注和历史记录不能充当授权。
- 本轮冻结服务、模型、写作偏好、引言、章节位置、备注、图片顺序、素材 hash 与覆盖授权。途中修改全局配置只影响下一轮，当前密钥只在内存中使用。
- 每批不跨章节，最多 6 张图。单节点不能拆散；单节点超过 6 张图时单独成批并校验接口上限，放不下就提示拆分节点。
- 各批串行；后批可使用前批刚提交的摘要。任一批失败停止后续批次；已提交节点不重发。

活跃轮次在应用进程内唯一。其所属文档在轮次结束前只读：禁止编辑、创建、导入、移动、合并、删除节点或文档；允许阅读、导出和切换到其它文档。其它文档可编辑，但不能启动第二轮解析。仓储也校验这一限制，不能只禁用页面按钮。前台图片检查仍可收集到待选区，追加入当前文档要等本轮结束。这样冻结上下文不会在请求期间被本地结构操作改变。

请求适配器将下列业务输入编码到所选服务的多模态请求中，JSON 本身不包含图片字节：

```json
{
  "turn_id": "t7",
  "protocol_version": 1,
  "batch_index": 1,
  "mode": "parse",
  "preferences": {"language": "zh-CN", "structure": "outline", "terms": "preserve", "length": "normal"},
  "brief": {"node_id": "n02", "text": "记录注意力公式与多头的作用。"},
  "heading_index": [{"node_id": "n03", "level": 2, "title": "多头注意力"}],
  "ordered_nodes": [
    {"node_id": "n05", "content_hash": "h05", "user_text": "比较单头和多头", "detail": false, "image_ids": ["i05a", "i05b"]}
  ],
  "images": [{"image_id": "i05a", "node_id": "n05"}, {"image_id": "i05b", "node_id": "n05"}],
  "context": [{"kind": "neighbor", "source_ids": ["n04"], "text": "Q/K/V 由独立投影获得。"}]
}
```

`brief` 为空则省略；引言过长的处理见 03，不静默截断用户原文。`heading_index` 仅含本批所属章节；首个章节前的正文属于文档前言区域，不引用后续章节。图片 ID 与节点 ID 的映射以冻结快照为准。

## 3. 流式协议

服务协议与业务 NDJSON 分层：SSE 适配器组装完整事件、解析文本增量，再由业务缓冲按换行取完整 JSON 行。网络块、SSE 事件与业务行都不能互当边界。业务 JSON 使用转义换行；最后没有换行的完整 JSON 在正常结束时可以校验，未闭合行不能提交。

| `kind` | 字段 | 处理 |
| --- | --- | --- |
| `stage` | `stage` | `reading / extracting / writing`，仅更新提示，不据此计算已保存进度 |
| `node` | `node_id, markdown, summary, tags` | 校验后逐节点事务提交 |
| `done` | `node_ids` | 与本批期望 ID 和实际提交集合核对，不能代替节点结果 |
| `error` | `code, message, retryable` | 作为候选错误；是否可重试由客户端错误分类决定 |

```json
{"kind":"stage","stage":"extracting"}
{"kind":"node","node_id":"n05","markdown":"多头注意力并行投影后拼接。","summary":"多头并行投影后拼接","tags":["Attention"]}
{"kind":"done","node_ids":["n05"]}
```

- 仅接受本批 ID；未知 ID 计入批次协议错误，不能给不存在的节点写错误记录。JSON 字段类型、长度、摘要预算、标签数组与非空 `markdown` 均要校验。
- 相同节点重复行第一次成功后忽略；重复行不改变计数或覆盖先前结果。连续 3 行无效终止批次；单行业务缓冲上限 256 KiB，单批文本累计上限 2 MiB，超限停止并保留已提交结果。
- 业务 `done`、服务正常结束、所有期望节点已提交三者齐备才算本批完成。缺漏、截断或异常结束记为失败，已提交结果保留；不能把 `[DONE]` 当作所有节点成功。
- 模型不得创建节点或章节。解析文字仅接受段落、列表、公式、代码块、表格等内容；不接受 H1/H2 文档结构标题、远端图片或本地文件引用，非法结果作为节点协议错误，避免污染投影和导出。

### 3.1 SSE 记录与界面数据

SSE 适配器在接收完整事件后，将返回的可展示文字增量同时发送到会话数据流与业务 NDJSON 解码器。会话不必等到完整业务行或节点事务成功才显示文字；接收中的内容标为“生成中”，只有事务成功的结果才标为“已保存”。

每批按接收顺序记录事件序号、接收时间、批次、服务事件类型、文字增量、结束原因及服务提供的 usage；本地提交/失败结论另记为业务事件，不伪装成服务端 SSE。相同文字增量可能合法重复，不能按内容去重。切 Tab、重建页面和回看历史都复用执行器与已有记录，不新建网络连接、不重新应用节点结果。存储格式与上限见 05。

## 4. 本地提交

规划 `DocumentRepository.commitParse(documentId, turnId, nodeId, ...)`，复用现有仓储 `Mutex`、`withTransaction` 与短 `NonCancellable` 提交区间。网络等待不占仓储写锁。

1. 取得仓储锁后、进入不可取消区间前检查 Job 仍活跃且未停止；在同一锁内重读节点和素材 hash。
2. Room 事务内校验 `turn.status = running`、文档归属、本批 `TurnItem` 存在、`committed = 0`、节点为有图片 `body` 且 hash 与快照一致。不符合就拒绝，不能先创建关联记录再认定重复。
3. 若当前 `origin = user`，必须有本轮该节点的 `replace_user_text` 授权；否则不写文字也不更新摘要，记录 `user_text_protected`。
4. 原子写入结果、hash、`state = parsed / origin = model`、摘要与标签，标记 `turn_item.committed = 1`，递增 `turns.committed_count`，使记忆缓存失效并 `touchDocument`。
5. 事务提交后仍在仓储协调区内刷新 `doc.md`；镜像失败沿用 `Saved.mirrorFailed` 与重试入口。数据库已提交就算已保存，不能为镜像失败重新调用模型。

`TurnItem` 的主键只保证每轮一个节点记录；幂等必须检查 `committed`，不能因为预建记录已存在就跳过首次结果。历史回放只读，终态轮次不能重新应用事件。

## 5. 轮次、取消与恢复

| 字段 | 值 |
| --- | --- |
| `mode` | `parse / retry / reparse` |
| `status` | `running / finished / interrupted / failed` |
| 统计 | `batch_count / node_total / committed_count / created_at / finished_at / error` |

执行器由应用持有 Job、Call 与活跃轮次信息，独立于页面生命周期。收起遮罩、切 Tab、切文档只改变视图，三个 Tab 始终能找到标明所属文档的进度入口；会话 Tab 直接订阅本轮 SSE 输出与提交状态。没有后台常驻服务，进程被系统终止后不自动续跑。

| 场景 | 处理 |
| --- | --- |
| 确认停止 | 先标记停止并取消 Call/Job，结构化等待已经进入提交区间的事务与镜像；再将轮次置 `interrupted`、清理候选并释放轮次占用 |
| 网络、服务、协议失败 | 当前已发送批次中未提交节点置 `failed`，后续未发送节点保持原状态；轮次 `failed` |
| 图片准备或本地存储失败 | 停止本轮，记录具体本地问题；不伪造已解析状态；存储不可写时下次启动按遗留轮次处理 |
| 进程退出 | 下次启动将遗留 `running` 置 `interrupted`，根据 `committed` 重算统计，不回滚已提交文字，不自动重发 |
| 重复点击 | 执行器与仓储校验活跃轮次，页面展示进度，不能另开网络请求 |
| 服务超窗口 | 本轮停止；提示减少本批节点或调整容量配置，用户重试只发未成功节点，不隐藏自动重试成本 |

停止确认统一说明“已保存的节点会保留，其余保持原状态”，不能声称所有剩余节点都会变成待解析。已经进入不可取消事务的节点可能在停止期间完成，最终数量以数据库为准。

## 6. 编辑、合并与图片移除

- 修改 `parsed_markdown` 时保持 `parsed_hash`，只在文本实际变化时设 `origin = user`；允许清空，不把它当作未解析。相关摘要立即退出缓存，重建使用修正文字；普通备注永远不被模型覆盖。
- “重新解析”只使用已保存内容。编辑页有未保存变更时先保存或放弃，不能把草稿悄悄送出；成功后替换，失败保留旧文字。`origin = user` 的覆盖按第 2 节确认。
- 移除最后一张图片时，把现有非空解析文字按“解析文字 → 用户备注”合并进 `body_markdown`，同一事务删除 `node_parse`。保存前说明“解析文字将保留为备注”；返回放弃不转移内容。没有任何文字则沿用禁止保存空正文、可删除节点的规则。
- 合并正文节点时保留较前节点 ID，图片仍按原链序合并；每个源节点的“解析文字 → 用户备注”按原链序合并为用户备注，删除两者旧解析记录。有图的合并结果为 `pending`，无图则没有解析状态。确认弹窗明确说明“已有解析文字将保留为备注，合并后的图片需重新解析”，不得级联删除后才发现丢失另一节点文字。
- 删除节点后其解析记录与记忆失效，历史 `TurnItem` 仍保留；删除文档才清理该文档轮次与文件。运行期间先停止轮次，结束后再执行删除。

## 7. 验收场景

1. 三个节点分两批，首批中第一个已提交后断流：它保持 `parsed`，首批未成功者 `failed`，下一批仍保持原状态。
2. 从 `pending / stale / failed` 开始的节点取消后分别保持原状态；停止期间刚提交的结果保留，进程重启没有 `parsing` 残留。
3. 重复事件不重复写入；历史轮次不能回放写入；镜像失败不再识图。
4. 改备注或移动整个节点不重新上传图片；调换节点内图片顺序才改变素材 hash。
5. 用户修正结果后，任何替换必须有本轮授权；只保存备注不会把 `origin` 改成 `user`。
6. 移除最后一图与合并不丢解析文字；轮次结束后重新开放所属文档编辑，切文档不会把进度算到新文档上。
