# 图笺 / PicNote · 02 文档与本地存储

## 1. 数据来源

`Document` 保存必填的 `title`；`Node` 保存 `document_id`、`sort_key`、`kind`（`text / image / chapter / introduction`）、用户填写的 `body_markdown` 和章节节点的 `title`。`NodeImage` 保存节点内顺序、本地图片路径、文件名、源内容 hash 和真实宽高。章节与引言沿用 `Node`，不额外建立表。

首次初始化在同一事务中创建教程文档、引言、图片、说明与 TODO 章节，随包 WebP 复制到文档素材目录；具体内容和语言选择见 [04-首次使用文档.md](04-首次使用文档.md)。用户新建时先在独立页面输入必填标题与可选引言，标题去除首尾空白后不能为空，点击“创建”才提交事务。引言非空时同时创建第一个 `introduction` 节点；返回、取消或校验失败不留下文档。引言可编辑、排序和删除，不添加图片，保存后保留类型。

Room 是文档结构、文字与顺序的权威；图片文件保存在应用自己的目录。`doc.md` 是可重新生成的镜像，不与节点数据分别编辑。

## 2. Markdown 组织

按节点顺序输出内容：

1. 文档标题输出为 H1。
2. 纯文字节点输出用户的 Markdown 原文；引言逐行加 `> `，空行也保留引用前缀，形成完整引用块。
3. 章节节点输出 `## 章节标题`，标题由用户填写。
4. 图片节点按图片顺序输出标准 Markdown 图片引用，随后输出该节点的用户备注。
5. 节点之间用空行分隔，不生成用户没有填写的说明、摘要或结论。

例如，用户填写简介、导入一张构图示例并补充备注后，导出内容为：

```markdown
# 摄影学习笔记

> 记录这次视频里讲到的构图方法和自己的练习。

## 构图练习

![构图示例](media/i01.webp)

把主体放在交点附近，留出视线朝向的空间。
```

图片说明优先使用用户设置的名称；未设置时使用简短的“图片”及顺序，不从图片内容猜测说明。节点在页面中的位置和点击目标由渲染数据关联，不向导出正文加入内部状态、数据库字段或节点 ID。

## 3. 文字编辑

从节点页打开编辑遮罩，完整图片下方保留多行“备注”输入框，编辑该节点的 `body_markdown`。保存后更新节点卡中的两行备注预览，并刷新文档页。

没有备注的图片节点显示空输入框，允许补充文字。点击固定 72dp 的纯文字节点卡，打开同一套节点编辑界面，仅显示文字输入区，保存后保留全文。章节节点单独编辑必填的章节标题，保存后刷新 Markdown 二级标题。

文档页只使用 Markdown 按节点顺序显示图片和用户内容。它与节点编辑共用同一份数据，不提供独立的文字编辑模式。复制与导出始终拿到完整的标准 Markdown。

替换和移除图片使用节点编辑中的按需操作菜单；图片与备注的修改一并保存。关闭或返回时，未保存的修改可选择放弃或继续编辑。

## 4. 顺序与删除

底部导入默认追加链尾。节点圆点菜单提供在前或在后插入普通节点，并可选择“创建章节 · 插在前面 / 插在后面”。打开编辑时记住所点节点与方向，保存时取该节点相邻位置写入 `sort_key`，不因编辑期间滚动页面而改成链尾。

无图且有文字时保存为 `text`，有图时保存为 `image`；两者内容都为空时不能保存。章节标题必填，未保存的草稿取消后直接丢弃。批量导入遵循用户选择的顺序，每张图片默认创建一个节点；节点编辑中可追加多张图片。`sort_key` 使用有间隔的整数，插入和拖拽只修改目标节点；相邻键无空隙时允许在同一事务内重新编号。

排序后按当前链序重新组织 Markdown。章节仅是一个标题节点，从它之后到下一个章节之前的内容按顺序自然呈现；删除章节只移除该标题，保留其后的其他节点。删除普通节点时移除它的文字与图片引用；如果图片已无有效引用，再清理本地文件。删除前提示具体范围，取消后不产生变更。

## 5. 本地保存

```text
filesDir/
  documents/<document_id>/
    doc.md
    media/<sha256>.webp
    media/launcher.webp  # 内置教程的随包图片
cacheDir/
  exports/picnote-<uuid>.zip
```

选图后通过 PasteHub 的 `pastehub-image-1.0.0.aar` 转为有损 WebP，质量使用 `ImagePreparation.kt` 中的统一常量 `ImportedImageWebpQuality = 90`，保持尺寸、方向与透明区域，不增加二次有损中转。后台逐张处理，临时文件完成后原子改名；编辑器追加和替换先准备本地草稿图片，保存时再提交节点与映射，放弃或失败清理未引用的草稿。正式文件位于 `filesDir`，不依赖系统 URI 长期授权。

AAR 从 PasteHub 的 `image-library/dist/android/` 复制到 `PicNote/libs/`，包含 `arm64-v8a` 和 `armeabi-v7a`。不支持的设备或无法编码的图片提示失败，不改存为其他格式；超出 WebP 单边 16383 像素上限的图片不静默缩小。

源 URI 与本地文件的对应关系在 Room 中持久化，与节点提交处于同一事务；内容相同的不同源 URI 也保留映射。源图删除不删除已导入的映射和本地图片；删除节点或文档后清理无引用文件及对应映射。不兼容旧开发数据，数据库结构变化时直接重建，不编写迁移或回填逻辑。

文字和顺序先提交 Room，再刷新文档预览及 `doc.md` 镜像。镜像通过临时文件原子替换，失败时保留上次完整文件，并提示重试；可从数据库恢复。图片预览缓存由 Coil 管理，可清理并重建，不用其替换持久化图片。

前台检查与文档写入通过现有 Job 等待和状态校验协调；同一次前台请求不会因页面重组、保存或重新加载而再扫描。文档镜像按文档串行更新，避免较旧的写入覆盖新编辑，不增加额外的 generation 状态。

## 6. 导出

顶栏“⋯”提供“复制 Markdown”和“导出文档”。导出时读取一份当前已保存的节点快照，生成 `document.md` 和 `media/`，打包为 ZIP；图片使用相对路径，不携带设备私有绝对路径。

导出失败保留原文档与本地图片，完成后再通过仅暴露导出目录的 `FileProvider` URI 和临时读取授权交给系统分享。不在导出过程中重写图片内容或调用外部服务。

## 7. 图片基线与差异记录

全库快照仅保存 `{uri, time}` 列表，`time` 使用 MediaStore `DATE_ADDED` 的秒值，按时间倒序、URI 稳定排序；不保存文件大小、修改时间、宽高或内容 hash。卷版本、完整授权基线及扫描时间单独保存。每次进入先完整查询系统列表，比较始终使用压缩前的系统 URI，不使用本地 WebP 路径或文件 hash。

- 首次完整扫描只建立基线。后续提取不在旧快照中、且时间大于或等于旧快照最新时间的 URI；相同时间戳也按 URI 判新，避免漏掉同一秒加入的图片。早于此边界的历史补入图片不主动推送，仍可手动选择。旧快照为空时，后续出现的图片均为新增。
- 新增图片进入独立待选列表，按时间倒序展示；不限截图，不自动加入文档。候选跨启动保留，导入成功或用户忽略后消费；系统中消失的未使用候选直接移除。不记录修改、删除差异，不据此修改已经保存的文档图片。
- 扫描在 IO 线程完整读取后，才在单个 Room 事务中更新快照和候选。查询失败、返回空 cursor 引用、取消或权限变化均不提交；成功查询到空列表才视为有效空结果。部分授权不做全库比较；权限恢复、卷重新挂载或 MediaStore version 变化时重建对应基线，避免把历史库当作新增。
- Photo Picker 返回的原始 URI 同样保存映射；仅通过可靠关联消费对应系统候选，不猜测 Picker URI 的内部路径或 ID。快照与映射各自持久化，重建快照不删除文档中的本地文件与源 URI 记录。
- 导入时计算源内容 SHA-256，在目标文档内去重；全部图片转换成功后才事务提交节点和映射，失败不产生半批节点，也不消费候选。写操作先取消并等待进行中的检查 Job，文档写入复用串行化与事务；保存前核对文档和插入锚点，失效时提示重新选择。

## 8. 首版恢复与预览约定

权限用途弹窗的已提示与已请求标记存入 Preferences DataStore；读取完成前不判断为首次使用，读取失败不自动弹窗。已提示状态在首次展示时保存，暂不授权、关闭或下次进入均不再主动提示。DataStore 不保存权限真值，系统权限始终实时查询；手动 Photo Picker 入口不依赖这些标记或完整图片权限。

外观选择使用独立的 DataStore 偏好，默认 Sage；启动先读取已选方案再展示页面，避免颜色闪变。外观读取或保存失败需提示，不覆盖权限提示记录，也不阻断文档操作；基础读写复用公共模块。

记住最近打开的有效文档；不存在则打开最近更新文档。首次启动先初始化教程；用户删除全部文档后正文留空，仍可从抽屉新建，不重复初始化教程。删除文档需确认，事务删除节点与引用后清理私有素材；文件清理失败可下次启动重试。启动清理无引用的临时文件和未入库素材，不删除有效引用。

编辑草稿与滚动位置至少支持配置变更；保存前退出确认，进程终止允许丢失未保存草稿，已经提交的数据必须恢复。`doc.md` 失败不回滚已成功的 Room 编辑；提示“已保存，文档镜像更新失败”并可重试，复制和导出始终从最新数据库快照生成，避免重复创建。

Markdown 使用成熟的本地渲染库，至少支持标题、段落、列表、强调、引用、代码和本地图片；禁止直接把 Markdown 源文当阅读预览。阅读与导出使用同一份完整 Markdown，统一解析跨节点引用，并以当前文档目录解析相对图片路径；页面分块加载，避免同时解码整篇图片。文档标题、章节标题与图片说明按 Markdown 语法转义，用户正文保留原始 Markdown。本地图片不可读时显示占位及错误，不让页面崩溃；ZIP 导出缺图须失败提示，不交付不完整包。

## 9. 前台检查日志

复用 `Module-AndroidCommon` 的 `logd / logdNoFile / loge / logEx`；正常诊断与错误默认落盘，临时调试才使用 `logdNoFile`。日志由 `FileLog` 写入应用外部 files 下的 `Log/`，不可用时使用内部 files，按天分文件、保留 7 天。

每次进程启动生成 `startupId` 并记录 `app_start`。`foreground_enter` 携带该标识、PID 与递增的 `foregroundOrdinal`，首次启动计为 1；统计某次启动的前台进入次数以此事件为准。`activity_*` 记录生命周期、焦点及多窗口状态，只用于对照，不计入前台次数。

`image_check_start / image_check_end` 使用相同启动标识和前台序号，结束记录成功、权限不足跳过、取消或失败，以及耗时和新增数。加载或写入期间仅延后真实前台请求，取消后不自动重扫；不因授权回调、页面重组或文档保存额外生成检查。日志不逐项记录图片 URI、引言或正文。
