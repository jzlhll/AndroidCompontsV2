# 竹节笔记 / Bambootes · 02 文档与本地存储

## 1. 数据来源

`Document` 保存必填的 `title`；`Node` 保存 `document_id`、`sort_key`、`kind`（`title / introduction / chapter / body / code`）、用户填写的 `body_markdown` 和标题、章节标题节点的 `title`。`NodeImage` 保存节点内顺序、本地图片路径、文件名、源内容 hash 和真实宽高。章节、引言与代码块沿用 `Node`，不额外建立表。

首次初始化在同一事务中创建教程文档、标题、引言、图片正文、文字正文与 TODO 章节，随包 WebP 复制到文档素材目录；具体内容和语言选择见 [04-首次使用文档.md](04-首次使用文档.md)。用户新建时先在独立页面输入必填标题与可选引言，标题去除首尾空白后不能为空，点击“创建”才提交事务。固定同时创建第一个 `title` 节点与第二个 `introduction` 节点，引言可以为空；返回、取消或校验失败不留下文档。固定头两项不能删除、移动或合并；`introduction` 只随文档自动创建，后续只允许编辑，不添加图片。`DocumentRepository.saveNode` 拒绝新增 `introduction`，只允许新增 `chapter`、`body` 和 `code`。

此约束不修改 Room schema，也不清理已有文档。旧版已保存的额外 `introduction` 保留原类型、内容及既有编辑、移动、删除和导出行为；仅禁止继续新增。

`code` 节点在 `body_markdown` 中先保存描述，再保存带语言标记的标准围栏代码块；代码中的反引号串长于默认围栏时自动加长围栏，保存前按所选语言整理代码结构与 4 空格缩进，再生成 Markdown；字符串、注释与宏续行保留，Python、Bash、YAML、SQL 和纯文本保留原有排版，结构不完整或格式化异常时按原文保存。描述可空、代码不能为空，不添加图片、不参与正文合并。此扩展不改变 Room schema、配置或媒体引用，无需数据迁移。旧版本仍可读取其 Markdown 内容，但无法保存 `code` 节点，需使用新版本编辑。

Room 是文档结构、文字与顺序的权威；图片文件保存在应用自己的目录。`doc.md` 是可重新生成的镜像，不与节点数据分别编辑。

## 2. Markdown 组织

按节点顺序输出内容：

1. 标题节点输出唯一 H1，与 `DocumentEntity.title` 同步；编辑标题节点时在同一事务中同步两处。
2. 正文节点输出用户的 Markdown 原文；非空引言逐行加 `> `，块内空行保留引用前缀，空主引言不输出。
3. 章节节点输出 `## 章节标题`，标题由用户填写。
4. 正文节点有图片时，按图片顺序输出标准 Markdown 图片引用，随后输出该节点的文字。
5. 代码块节点输出可选描述与围栏代码块，语言保留为围栏信息，不输出着色样式；网页导出保留代码空白、等宽字体和横向滚动。
6. 节点之间用空行分隔，不生成用户没有填写的说明、摘要或结论。

例如，用户填写简介、导入一张构图示例并补充备注后，导出内容为：

```markdown
# 摄影学习笔记

> 记录这次视频里讲到的构图方法和自己的练习。

## 构图练习

![图片 1](media/i01.webp)

把主体放在交点附近，留出视线朝向的空间。
```

移除用户编辑的图片说明字段，图片替代文本统一使用“图片 N”，按整篇文档的图片顺序编号。节点在页面中的位置和点击目标由渲染数据关联，不向导出正文加入内部状态、数据库字段或节点 ID。

## 3. 文字编辑

从节点页打开独立编辑页面，完整图片下方保留多行“备注”输入框，编辑该节点的 `body_markdown`。保存后更新节点卡中的两行备注预览，并刷新文档页。

没有备注的图片节点显示空输入框，允许补充文字。点击固定 72dp 的纯文字节点卡后显现设置按钮，再点击设置打开同一套节点编辑界面，仅显示文字输入区，保存后保留全文。章节节点单独编辑必填的章节标题，保存后刷新 Markdown 二级标题。

文档页只使用 Markdown 按节点顺序显示图片和用户内容。它与节点编辑共用同一份数据，不提供独立的文字编辑模式。导出始终拿到完整的标准 Markdown。

正文创建、编辑页的顶栏直接提供图片加号图标，点击打开系统选图。每张图片下方依次显示上移、下移和省略号按钮；上移、下移交换相邻图片的草稿顺序，首张禁用上移，末张禁用下移。省略号菜单仅显示“替换”和“移除”，不附带图片编号；替换使用系统单选，每次只替换当前图片。图片顺序、替换、移除与备注的修改一并保存，保存前不更改已存储内容。关闭或返回时，未保存的修改可选择放弃或继续编辑。

## 4. 顺序、合并与删除

标题和主引言固定占据前两位。节点页额外显示一个链尾空白插入项，不存储、不计数、不导出。创建菜单仅向当前锚点前插入章节标题、正文或代码块；链尾入口与底部图片导入均追加到真实节点末尾。路由、编辑状态和仓储接口不保留“插入下一个”或前后方向参数。

正文统一为 `body`，至少包含非空文字或图片；章节标题必填。只有固定主引言允许为空。`sort_key` 使用有间隔的整数，菜单移动只修改目标节点；相邻键无空隙时在同一事务内重排。插入和移动必须在仓储中校验不能越过固定前两项。未保存草稿取消后不入库。

正文节点支持拖动两个节点合并，或通过节点 Tab 顶栏“⋯”菜单中的“合并”多选至少两个节点。用户确认后重新校验全部所选节点有效性，在单个事务内按原链序保留最前节点 ID、拼接图片引用与非空文字，并删除其余所选节点。全部图片先转移归属并重排 `sort_index`，再删除节点；保留有效源 URI 映射和文件，不重新压缩，未选节点不受影响。章节标题、标题、引言和链尾空白项不参与合并。详细交互见 [05-节点设计.md](05-节点设计.md)。

堆叠图片的左右滑动仅改变查看位置，不修改顺序。点击卡片箭头时在单个事务中交换当前图片与相邻图片的 `sort_index`，保持查看位置、显示交换后的图片，并刷新文档页及 Markdown 镜像；仓储重新检查图片归属和首尾边界，失败不改变已保存顺序。

保存、移动、合并和删除后均按当前链序重新生成 Markdown。删除章节标题只移除该节点，保留其后的节点。普通删除移除节点文字与图片引用，之后仅清理无引用文件及对应源 URI 映射；固定头两项不提供删除。删除前确认范围，取消后不变更。

## 5. 本地保存

```text
filesDir/
  documents/<document_id>/
    doc.md
    media/<sha256>.webp
    media/launcher.webp  # 内置教程的随包图片
  image_drafts/<session>/
    <uuid>.webp
cacheDir/
  coil/
  shared/exports/picnote-<uuid>.zip
  shared/exports/picnote-<uuid>.html
```

选图后通过 PasteHub 的 `pastehub-image-1.0.0.aar` 转为有损 WebP，质量使用 `ImagePreparation.kt` 中的统一常量 `ImportedImageWebpQuality = 90`，保持尺寸、方向与透明区域，不增加二次有损中转。后台逐张处理，临时文件完成后原子改名；编辑器追加和替换先准备本地草稿图片，保存时再提交节点与映射，放弃或失败清理未引用的草稿。正式文件位于 `filesDir`，不依赖系统 URI 长期授权。

AAR 从 PasteHub 的 `image-library/dist/android/` 复制到 `PicNote/libs/`，包含 `arm64-v8a` 和 `armeabi-v7a`。不支持的设备或无法编码的图片提示失败，不改存为其他格式；超出 WebP 单边 16383 像素上限的图片不静默缩小。

源 URI 与本地文件的对应关系在 Room 中持久化，与节点提交处于同一事务；内容相同的不同源 URI 也保留映射。源图删除不删除已导入的映射和本地图片；删除节点或文档后清理无引用文件及对应映射。所有实现不兼容旧设计或旧开发数据，数据库结构变化时直接重建，不编写迁移、回填或旧类型适配逻辑。

文字和顺序先提交 Room，再刷新文档预览及 `doc.md` 镜像。镜像通过临时文件原子替换，失败时保留上次完整文件，并提示重试；可从数据库恢复。图片预览使用 Coil 3.6.3，`PicNoteApplication` 实现 `SingletonImageLoader.Factory`，所有 `AsyncImage` 共享同一个 ImageLoader。内存 LRU 缓存上限为应用可用堆内存的 `1/6`，保留默认弱引用复用和内存压力回收；这不是应用全部图片对象的总内存上限。磁盘缓存位于 `cacheDir/coil/`，上限 400 MiB，正式图片直接从本地文件或内容 URI 加载。滚动缩略图由 `ScrollThumbnailFetcher` 写入同一 Coil DiskCache，与其他缓存共同受 400 MiB 上限和 LRU 淘汰管理，不写入正式文档目录。正式图片仍保存在 `filesDir/documents/`，编辑草稿位于 `filesDir/image_drafts/`，Coil 缓存可清理、可重建，不替代这些持久化文件。

缓存与存储残留统一由 `PicNoteCleaner` 管理。`PicNoteApplication` 在每个进程第一次 `GlobalBackgroundCallback` 前台回调（`foregroundOrdinal == 1`）调用 `clean(clearAllCache = false)`；后续前后台切换、Activity 重建和 ViewModel 重建不重复触发启动清理。设置页“清理缓存”调用同一实例的 `clean(clearAllCache = true)`，执行期间禁用重复点击并展示进度，完成后反馈结果。

文件清理复用 `Globals.backgroundScope`，通过仓库锁按项串行执行；与导入、保存、导出互斥，避免清理正在写入的文件。各清理项及单个文件独立容错，失败记录日志并继续后续项目，协程取消仍向上传递。手动清理通过 Coil、Glide 的接口释放缓存；Glide 内存释放按库要求切到主线程并等待完成，不并行执行。清理策略如下：

| 目录 | 内容 | 清理设置 | 启动清理 |
| --- | --- | --- | --- |
| `cacheDir/coil/` | Coil 图片缓存及滚动缩略图 | 全部清理 | 保留，沿用 LRU |
| `cacheDir/imageCache/` | 公共 Glide 图片缓存 | 全部清理 | 保留，沿用 LRU |
| 内存 | Coil、Glide 可回收图片缓存 | 释放缓存 | 保留 |
| `filesDir/image_drafts/` | 导入、替换图片的临时草稿 | 清理失效会话，保留活跃会话 | 清理失效会话，保留活跃会话 |
| `cacheDir/shared/exports/` | ZIP、HTML 导出副本 | 全部清理 | 仅清理超过 7 天的副本 |
| 正式目录及导出目录中的 `.tmp` | 中断写入的残留 | 清理残留 | 清理残留 |
| `filesDir/documents/` | 正式文档及图片 | 仅回收 Room 无引用的文件、目录 | 仅回收 Room 无引用的文件、目录 |
| 文档目录内的 `doc.md` | Markdown 镜像 | 保留，缺失或过期时补建 | 保留，缺失或过期时补建 |
| `databases/`、`filesDir/datastore/`、`shared_prefs/` | 数据库、配置及持久状态 | 保留 | 保留 |
| `Globals.goodFilesDir/Log/` | 日志 | 保留 | 由 FileLog 自身按 7 天规则处理 |
| 系统相册、`Pictures/Bambootes/` | 原图及主动下载的图片 | 保留 | 保留 |

草稿目录、正式文件路径、Room schema 及配置格式保持兼容，不需要数据迁移。仍被节点引用的图片始终保留，失效草稿及导出副本的清理不删除文档内容。

节点操作引导使用独立的 `filesDir/datastore/node_guide.preferences_pb`：菜单和卡片各自保存点击总数、引导阶段与首次确认时的点击总数，均为 `Long`。新字段缺省为 `0`；阶段 `2` 为完成，后续启动优先读取阶段并提前结束检查，点击总数仍持续保存。已有 Room 数据、正式图片及外观和权限配置继续沿用。

添加模式使用独立 `filesDir/datastore/import_mode.preferences_pb`，保存 `ImportMode` 的稳定枚举名；旧版本缺省、未知值或读取失败均回退到 `AddOnly`，写入失败恢复先前模式。本次不修改 Room 版本、schema、正式图片或已有配置，保留已有数据；PicNote 的最低系统版本明确为 Android 12（API 31）。

系统相册删除通过 `Module-AndroidCommon` 的 `utilsmedia/SystemAlbumUtil.kt` 中 `deleteSystemAlbumImages` 统一处理，仅支持 Android 12 及以上，使用 `@RequiresApi(31)` 与运行时检查标明边界。公共函数只接收具体 MediaStore 图片 URI，按不超过 2000 项请求系统确认，取消时停止后续批次。PicNote 删除前校验冻结批次的 URI、加入时间与媒体卷版本；图片已不存在时跳过，身份变化或权限变化时停止，不扩大范围。源图清理不删除应用中的正式文件、节点或导入映射。

前台检查与文档写入通过现有 Job 等待和状态校验协调；同一次前台请求不会因页面重组、保存或重新加载而再扫描。文档镜像按文档串行更新，避免较旧的写入覆盖新编辑，不增加额外的 generation 状态。

节点页、文档页和编辑页采用主图与缓存小图配合的加载方式。正式文件始终按显示目标尺寸异步加载，优先使用清晰图内存缓存；已展示的清晰图不会因开始滚动而降级，慢速滚动时也可以直接完成清晰图加载，不必等待停止。主图完成前使用独立缓存 key 的小图占位，小图请求只读取 Coil 内存或磁盘缓存，未命中不抢先解码正式文件。主图完成后移除小图请求，离屏请求由 Compose 和 Coil 生命周期取消。

正式文件从非内存来源加载成功后，在当前图片组合的生命周期内后台预热小图缓存：从保存文件读取真实宽高，只解析尺寸而不先解码整张大图，按长边除以 20 取整、最低 32px 确定目标长边，并保持宽高比。由 Coil 按目标尺寸解码，缩略图以质量 90 的 WebP 写入其 DiskCache；图片内存缓存与压力回收继续由共享 ImageLoader 维护。缩略图不回写页面宽高比，页面尺寸以清晰图实际解码结果校正。请求优先使用 RGB_565 并关闭硬件位图，透明图等不支持的情况由 Coil 选择兼容格式。

## 6. 导出

顶栏“⋯”与抽屉行内菜单提供两种导出：完整导出与网页导出，文档标题统一通过 `title` 节点编辑。两者都读取同一份当前已保存的节点快照，不读取 `doc.md` 镜像。完整导出生成 `<清理后的标题>.md` 和 `media/`，打包为 ZIP，适合继续编辑与迁移；图片使用相对路径，不携带设备私有绝对路径。

网页导出生成为单文件 `<清理后的标题>.html`：标题节点输出 `<h1>`、章节标题输出 `<h2>`，其余节点先按顺序输出图片，再输出正文；正文用 CommonMark 渲染成 HTML，开启 `escapeHtml` 防止正文里的原始标签注入，软换行渲染为 `<br>`，引言包在 `<blockquote>` 中。图片以 base64 data URI 内嵌，按流写入避免整篇字符串驻留内存，产物不依赖任何外部资源；内置 720px 阅读卡片、8dp 圆角图片与浅色/深色两套样式，直接用浏览器打开即可阅读。

导出文件名将标题规范化为 NFC，把 `<>:"/\|?*`、控制字符、无效代理字符、括号和逗号替换为短横线；空白和连续短横合并，去除首尾句点和短横。清理后为空时使用 `document`，Windows 保留名及带扩展名的保留名添加 `document-` 前缀。标题部分按完整 Unicode 码点截断，上限为 255 字节减去扩展名与点号（`.md` 为 252、`.html` 为 251）。此清理只作用于导出文件名，不修改正文标题、Room 数据或本地 `doc.md` 镜像，无需数据迁移。

两种导出都保存在 `cacheDir/shared/exports/`，完成后通过 `Module-AndroidCommon` 的 `${applicationId}.fileprovider` 与 `getUriFromFile(context, file)` 获取 URI，附带临时读取授权打开系统分享面板；分享类型按扩展名取 `application/zip` 或 `text/html`。应用不额外声明 Provider 或 paths XML；`PicNoteCleaner` 在进程首次进入前台时清理临时文件与超过 7 天的导出副本，设置页手动清理时移除全部导出副本。正式文档保存在 Room 数据库和 `filesDir/documents/`，不受 cache 清理影响，导出副本清理后可重新生成。导出失败保留原文档与本地图片，不重写图片内容或调用外部服务。

## 7. 图片基线与差异记录

全库快照仅保存 `{uri, time}` 列表，`time` 使用 MediaStore `DATE_ADDED` 的秒值，按时间倒序、URI 稳定排序；不保存文件大小、修改时间、宽高或内容 hash。卷版本、完整授权基线及扫描时间单独保存。每次进入先完整查询系统列表，比较始终使用压缩前的系统 URI，不使用本地 WebP 路径或文件 hash。

- 首次完整扫描只建立基线。后续提取不在旧快照中、且时间大于或等于旧快照最新时间的 URI；相同时间戳也按 URI 判新，避免漏掉同一秒加入的图片。早于此边界的历史补入图片不主动推送，仍可手动选择。旧快照为空时，后续出现的图片均为新增。
- 新增图片进入独立待选列表，按时间倒序展示；不限截图，不自动加入文档。候选跨启动保留，导入成功或用户忽略后消费；系统中消失的未使用候选直接移除。不记录修改、删除差异，不据此修改已经保存的文档图片。
- 扫描在 IO 线程完整读取后，才在单个 Room 事务中更新快照和候选。查询失败、返回空 cursor 引用、取消或权限变化均不提交；成功查询到空列表才视为有效空结果。部分授权不做全库比较；权限恢复、卷重新挂载或 MediaStore version 变化时重建对应基线，避免把历史库当作新增。
- Photo Picker 返回的原始 URI 同样保存映射；仅通过可靠关联消费对应系统候选，不猜测 Picker URI 的内部路径或 ID。快照与映射各自持久化，重建快照不删除文档中的本地文件与源 URI 记录。
- 导入时计算源内容 SHA-256，在目标文档内去重；全部图片转换成功后才事务提交节点和映射，失败不产生半批节点，也不消费候选。首页写操作先取消并等待进行中的检查 Job，文档写入复用串行化与事务；编辑器保存回读当前图片记录，并在事务中重新校验源 URI 对应的卷版本，不恢复扫描已失效的源 URI。保存前核对文档和插入锚点，失效时提示重新选择。

## 8. 首版恢复与预览约定

权限用途弹窗的已提示与已请求标记存入 Preferences DataStore；读取完成前不判断为首次使用，读取失败不自动弹窗。已提示状态在首次展示时保存，暂不授权、关闭或下次进入均不再主动提示。DataStore 不保存权限真值，系统权限始终实时查询；手动 Photo Picker 入口不依赖这些标记或完整图片权限。

外观选择使用独立的 DataStore 偏好，默认 Sage；启动先读取已选方案再展示页面，避免颜色闪变。外观读取或保存失败需提示，不覆盖权限提示记录，也不阻断文档操作；基础读写复用公共模块。

记住最近打开的有效文档；不存在则打开最近更新文档。首次启动先初始化教程；用户删除全部文档后正文留空，仍可从抽屉新建，不重复初始化教程。删除文档需确认，事务删除节点与引用后清理私有素材；文件清理失败可下次启动重试。启动清理无引用的临时文件和未入库素材，不删除有效引用。

编辑草稿与滚动位置至少支持配置变更；保存前退出确认，进程终止允许丢失未保存草稿，已经提交的数据必须恢复。`doc.md` 失败不回滚已成功的 Room 编辑；提示“已保存，文档镜像更新失败”并可重试，导出始终从最新数据库快照生成，避免重复创建。

Markdown 使用成熟的本地渲染库，至少支持标题、段落、列表、强调、引用、代码和本地图片；禁止直接把 Markdown 源文当阅读预览。阅读与导出复用同一份节点 Markdown 源内容。App 内通过一次解析保留节点边界与跨节点引用，以当前文档目录解析相对图片路径；阅读专用的节点边界不进入导出文件。独立图片和正文、引用内混排的本地图片均可加载，页面分块加载，避免同时解码整篇图片。Markdown 链接可点击打开，正文保留原生长按选择与复制；不直接把 `file://` 文件链接交给外部应用，点击时通过现有消息提示说明不支持。阅读文本块按实际内容和可用宽度确定高度，由外层列表统一滚动，不能因内部焦点或滚动状态造成标题截断、引言留白或末尾章节缺失。引言在阅读页使用中性灰字与整块 8dp 圆角灰底，图片同样使用 8dp 圆角；字体与 12dp / 6dp 的节点排版间距仅用于 App 内显示，导出仍使用标准标题、引用、图片与正文，不添加字号、颜色、圆角或间距标记。文档标题、章节标题与自动图片替代文本按 Markdown 语法转义，用户正文保留原始 Markdown。本地图片不可读时显示占位及错误，不让页面崩溃；ZIP 导出缺图须失败提示，不交付不完整包。

## 9. 前台检查日志

复用 `Module-AndroidCommon` 的 `logd / logdNoFile / loge / logEx`；正常诊断与错误默认落盘，临时调试才使用 `logdNoFile`。日志由 `FileLog` 写入应用外部 files 下的 `Log/`，不可用时使用内部 files，按天分文件、保留 7 天。

每次进程启动生成 `startupId` 并记录 `app_start`。`foreground_enter` 携带该标识、PID 与递增的 `foregroundOrdinal`，首次启动计为 1；统计某次启动的前台进入次数以此事件为准。`activity_*` 记录生命周期、焦点及多窗口状态，只用于对照，不计入前台次数。

`image_check_start / image_check_end` 使用相同启动标识和前台序号，结束记录成功、权限不足跳过、取消或失败，以及耗时和新增数。加载或写入期间仅延后真实前台请求，取消后不自动重扫；不因授权回调、页面重组或文档保存额外生成检查。日志不逐项记录图片 URI、引言或正文。
