# 图笺 / PicNote · 01 总体思路

## 1. 是什么

把截图和用户文字排成一篇 Markdown 图文笔记。节点页负责收集、编辑备注、插入和排序，文档页负责展示图片与内容。

图片和文字都由用户提供，本地程序只处理保存、顺序、Markdown 排版和导出。没有模型请求、图片语义解析、生成摘要、会话轮次、提交按钮或解析状态。

## 2. 三个对象

| 对象 | 说明 |
| --- | --- |
| `Document` | 一篇文档，包含必填标题、一条有序节点链和本地图片 |
| `Node` | 一个纯文字、图片 / 图文或章节片段，按链序组织 |
| `NodeImage` | 节点关联的 WebP 副本，保留真实宽高 |

一份文档对应一条节点链。节点内容与顺序是唯一编辑来源，文档页和导出的 Markdown 都从同一份数据生成。

## 3. 两个 Tab

- `节点`：4:3 图片卡、72dp 纯文卡与章节卡、左侧节点轴；打开节点编辑内容，点击圆点前后插入节点或章节，长按拖拽排序。
- `文档`：按链序使用 Markdown 展示完整图片与用户文字，作为阅读预览。

由 Compose Foundation `HorizontalPager` 承载两个页面，分别保存滚动位置。节点编辑遮罩展示带阴影的完整图片和备注输入框；纯文字节点直接编辑文字，不增加主 Tab。

## 4. 新建

左侧 navMenu 有文档时在顶部右上角显示“＋ 新建”；无文档时隐藏顶部栏，居中显示 32sp 的“空空如也”及其下方的“+新建”。点击新建后先填写两个输入：**标题（必填）**和**引言（可选）**。标题去除首尾空白后不能为空，提交成功才创建文档并允许添加素材。

填写了引言，就将其保存为第一个 `introduction` 节点，显示为 72dp 圆角卡，文字在正常内容起点基础上缩进 24dp，使用灰色；未填写则创建空链。引言可编辑、移动或删除，始终保持引言类型；文档阅读同样缩进并用灰字显示，Markdown 输出为 `>` 引用。

## 5. 数据流

```text
填写标题与可选引言 → 创建文档 → 编辑纯文 / 导入图片 / 插入章节
  → 保存到本地 → 按节点顺序组织 Markdown → 文档页阅读 / 导出
```

相册和新图片待选区进入同一套导入流程。没有目标文档时，先完成标题与可选引言表单，再保存素材；选中图片后以质量常量 90 转成 WebP，写入文档素材目录并持久化源 URI 映射，保存后立即反映在文档页。

## 6. 节点类型

无图纯文节点使用固定 **72dp** 高的圆角卡片，最多展示两行文字，超出省略；点击编辑全文。章节也是链上的独立节点，使用 72dp 卡片展示章节标题，在文档中输出为 Markdown 二级标题。

圆点菜单提供“插入上一个节点 / 插入下一个节点”和“创建章节 · 插在前面 / 创建章节 · 插在后面”。保存后固定落在所点节点的相邻位置，取消不留下空节点。

图片卡固定 4:3，按 `centerCrop` 显示；小图可以放大，不要求填充留白。底部 32dp 半透明渐变层展示最多两行用户备注，超出省略；卡片下方不再附加状态或摘要区域。

单击图片显现右上角设置：0.5 秒渐显、停留 3 秒、0.5 秒渐隐。打开节点编辑遮罩后，按真实比例展示带阴影的完整图片，下方保留可编辑的用户备注；保存后同时更新节点卡和文档预览。

## 7. 技术选型

首版在 `PicNote/` 建立独立 Android application 模块 `:picnote`，接入仓库根工程，复用现有版本目录和 SDK 配置。采用 Kotlin、单 `ComponentActivity`、标准 Compose Material 3、Navigation 3、Room、本地文件和 Coil，不引入 Fragment、DI、模型 SDK、SSE 或语义检索。

使用 `navigation-3` skill 和官方资料：`NavDisplay` + `rememberNavBackStack`，路由为可序列化 `NavKey`，只传文档、节点 ID 和插入方向。参照 agit，由根组件统一承载页面导航和浮层，普通页面采用一致的横向进退动画。首页承载两个 Tab，新建文档为普通页面；节点与章节的创建、编辑为保留首页背景的同窗口悬浮目的地，整个编辑面板左右各留 24dp，背景取样模糊，前景内容清晰。页面由 ViewModel 管理状态，通过回调连接 UI 操作；ViewModel 由标准 factory 创建，Flow 按生命周期收集。此独立应用采用标准 Compose 组件，不接入主工程的 `FragmentShellActivity`；背景模糊与阴影复用 `Module-AndroidUiEx` 公共能力。

## 8. 首页权限与进入检查

图片访问提供两条独立路径：系统 Photo Picker 手动选图无需申请图片库读取权限；完整授权后才通过 MediaStore 比较图片变化。首页首次以“授予图片访问权限”说明用途，用户选择“授予权限”后再请求系统权限，也可选择“暂不授权”继续手动选图。Android 13+ 使用 `READ_MEDIA_IMAGES`，Android 14+ 同时声明和请求 `READ_MEDIA_VISUAL_USER_SELECTED` 以识别部分授权；Android 12L 及以下使用 `READ_EXTERNAL_STORAGE`（`maxSdkVersion=32`）。不请求视频、全部文件访问或悬浮窗权限。

首次用途弹窗的已提示状态通过 Preferences DataStore 保存，之后不再主动弹窗；未完整授权时，用户通过首页“图片权限”旁的小箭头主动进入授权或系统设置。图片检查只由应用级前台进入触发，每次一次，首次启动计为第一次；加载或写入期间延后同一次请求，没有手动刷新入口。完整授权才比较全库 URI 与加入时间，部分授权和拒绝只更新权限状态，仍可编辑文档和手动选图。权限回调更新展示，不额外触发扫描。首版不依赖后台任务、悬浮窗、截图回调或常驻 `ContentObserver`。

使用 `ProcessLifecycleOwner` 的 `ON_START / ON_STOP` 记录应用可见前后台；窗口失焦、页面切换与配置重建不单独触发图片检查。复用公共日志系统，启动标识、前台进入序号、窗口状态及检查结果默认落盘，供按某次启动统计进入次数。

首次完整扫描建立基线，不把历史图片全部提示为新增；历史图仍可通过相册导入。后续仅比较按时间排序的 `{uri, time}` 快照，选出最新时间段新增的 URI 作为候选，不记录修改与删除，也不自动加入文档。具体提交与权限降级策略见 02 文档。

官方依据：[Navigation 3](https://developer.android.com/guide/navigation/navigation-3/get-started)、[Photo Picker](https://developer.android.com/training/data-storage/shared/photo-picker)、[部分照片访问](https://developer.android.com/about/versions/14/changes/partial-photo-video-access)、[MediaStore](https://developer.android.com/training/data-storage/shared/media)、[DataStore](https://developer.android.com/topic/libraries/architecture/datastore)。

## 9. 边界

1. 文档、节点和压缩后的图片保存在本机；无账号和云同步。
2. 预览裁切不覆盖本地 WebP，Markdown 使用完整图片比例。
3. 文字编辑、插入、删除与排序即时更新本地文档，不产生待解析或待同步状态。
4. 简介与备注统一在节点编辑中修改，文档页只渲染节点中的图片和内容。
5. 导出包含 `.md` 与图片文件，可脱离应用阅读。
6. 初版不实现系统级悬浮窗、分享接收、归档与独立设置页；节点编辑使用应用内部浮层，无需悬浮窗权限。文档抽屉提供新建、切换、重命名、删除，以及四套外观方案切换；颜色和按钮样式与 agit 共用公共 UI 能力。
7. 初版验收闭环：完整/部分/拒绝权限均能进入首页；重进正确发现差异且重复进入不重复入待选；新建、选择图片、编辑文字/章节、插入和排序、删除、重启恢复、阅读、复制与 ZIP 分享可串联完成。源图删除不影响已导入文档。
