# 竹节笔记 / Bambootes · 01 总体思路

## 1. 是什么

把截图和用户文字排成一篇 Markdown 图文笔记。节点页负责收集、编辑备注、插入和排序，文档页负责展示图片与内容。

图片和文字都由用户提供，本地程序只处理保存、顺序、Markdown 排版和导出。没有模型请求、图片语义解析、生成摘要、会话轮次、提交按钮或解析状态。

## 2. 三个对象

| 对象 | 说明 |
| --- | --- |
| `Document` | 一篇文档，包含必填标题、一条有序节点链和本地图片 |
| `Node` | 标题、引言、章节标题或正文片段，按链序组织 |
| `NodeImage` | 节点关联的 WebP 副本，保留真实宽高 |

一份文档对应一条节点链。节点内容与顺序是唯一编辑来源，文档页和导出的 Markdown 都从同一份数据生成。

## 3. 两个 Tab

- `节点`：4:3 图片卡、72dp 文字卡、左侧节点轴与顺序编号；通过设置进入编辑页，圆点菜单在当前节点前插入，长按拖动正文节点请求合并。
- `文档`：按链序使用 Markdown 展示完整图片与用户文字，作为阅读预览。

由 Compose Foundation `HorizontalPager` 承载两个页面，分别保存滚动位置。节点编辑为独立全屏页面，展示完整图片与文字输入框，不增加主 Tab。

## 4. 首次使用与新建

首次进入应用时从 assets 创建“如何使用[竹节笔记] ？”教程，依次包含标题、引言、手机桌面图、“点击程序打开程序。”和 `TODO` 章节。系统中文选择简体中文教程，其他语言选择英文教程。仅初始化一次，已有文档时跳过，删除后不自动补回；详见 [04-首次使用文档.md](04-首次使用文档.md)。

左侧 navMenu 始终显示“我的文档”和“＋ 新建”。点击新建打开独立页面，填写必填标题与可选引言，点击“创建”成功后才生成文档；标题为空时不可提交，返回或取消不创建。不显示“空空如也”页面。标题与主引言固定为前两个节点，主引言允许为空，不能删除或移动。引言保持独立类型，文档阅读缩进并用灰字显示，Markdown 输出为 `>` 引用。

## 5. 数据流

```text
首次初始化教程 / 填写标题与可选引言并创建文档 → 编辑纯文 / 导入图片 / 插入章节
  → 保存到本地 → 按节点顺序组织 Markdown → 文档页阅读 / 导出
```

相册和新图片待选区进入同一套导入流程。没有目标文档时先完成标题与可选引言表单，再继续选图或导入；选中图片后以质量常量 90 转成 WebP，写入文档素材目录并持久化源 URI 映射，保存后立即反映在文档页。

## 6. 节点类型

统一为 `title / introduction / chapter / body` 四种类型，正文可包含文字、图片或图文。标题与主引言固定前两位，链尾始终显示一个不入库的插入项；所有节点在左侧圆点正下方只显示从 `01` 开始的数字编号。创建入口采用替换一级菜单的三类型二级菜单，只向当前节点前插入。

节点菜单负责上移、下移，正文拖动只用于确认合并。五套主题分别提供四种类型颜色；图片与文字卡均先显现右上角带框笔形编辑图标，再点击图标进入独立编辑页。完整交互、合并事务与配色见 [05-节点设计.md](05-节点设计.md)。

## 7. 技术选型

首版在 `PicNote/` 建立独立 Android application 模块 `:picnote`，接入仓库根工程，复用现有版本目录和 SDK 配置。采用 Kotlin、单 `ComponentActivity`、标准 Compose Material 3、Navigation 3、Room、本地文件和 Coil，不引入 Fragment、DI、模型 SDK、SSE 或语义检索。

`PicNoteApplication` 继承 `CommonInitApplication`，通过公共初始化接入 `Globals`、Activity 跟踪、前后台通知、日志、异常处理及基础模块服务，不重复手动初始化。业务页面仍使用 `MainActivity`；公共调试异常页 `CrashActivity` 使用独立的 AppCompat 主题，不承载业务导航。

图片选择使用 `Module-AndroidUiEx` 的 `rememberComposePhotoPicker` 公共入口，底层复用 `CompatMultiPickVisualMedia`，与已有 Fragment 入口共用系统选择能力。首页添加、编辑追加和替换统一接入，支持单选、多选、有序结果及配置重建后的回调；取消不修改内容，启动失败释放入口状态并提示。选择器不请求图库权限，返回 URI 后继续使用 PicNote 的 WebP 导入流程。

使用 `navigation-3` skill：`NavDisplay` + `rememberNavBackStack`，路由为可序列化 `NavKey`，只传文档、节点、插入锚点 ID 与节点类型，不再传前后方向。根组件统一承载页面导航，首页承载两个 Tab，新建文档与所有节点创建、编辑使用普通全屏目的地。页面由 ViewModel 管理状态，通过回调连接 UI 操作；ViewModel 由标准 factory 创建，Flow 按生命周期收集。此独立应用采用标准 Compose 组件，不接入主工程的 `FragmentShellActivity`；图片阴影复用 `Module-AndroidUiEx` 公共能力。

## 8. 首页权限与进入检查

图片访问提供两条独立路径：系统 Photo Picker 手动选图无需申请图片库读取权限；完整授权后才通过 MediaStore 比较图片变化。首页首次以“授予图片访问权限”说明用途，用户选择“授予权限”后再请求系统权限，也可选择“暂不授权”继续手动选图。Android 13+ 使用 `READ_MEDIA_IMAGES`，Android 14+ 同时声明和请求 `READ_MEDIA_VISUAL_USER_SELECTED` 以识别部分授权；Android 12L 及以下使用 `READ_EXTERNAL_STORAGE`（`maxSdkVersion=32`）。不请求视频、全部文件访问或悬浮窗权限。

首次用途弹窗的已提示状态通过 Preferences DataStore 保存，之后不再主动弹窗；未完整授权时，用户通过首页“图片权限”旁的小箭头主动进入授权或系统设置。图片检查只由应用级前台进入触发，每次一次，首次启动计为第一次；加载或写入期间延后同一次请求，没有手动刷新入口。完整授权才比较全库 URI 与加入时间，部分授权和拒绝只更新权限状态，仍可编辑文档和手动选图。权限回调更新展示，不额外触发扫描。首版不依赖后台任务、悬浮窗、截图回调或常驻 `ContentObserver`。

通过 `CommonInitApplication` 注册的 `GlobalBackgroundCallback` 接收应用可见前后台通知，底层使用 `ProcessLifecycleOwner` 的 `ON_START / ON_STOP`；窗口失焦、页面切换与配置重建不单独触发图片检查。复用公共日志系统，启动标识、前台进入序号、窗口状态及检查结果默认落盘，供按某次启动统计进入次数。

首次完整扫描建立基线，不把历史图片全部提示为新增；历史图仍可通过相册导入。后续仅比较按时间排序的 `{uri, time}` 快照，选出最新时间段新增的 URI 作为候选，不记录修改与删除，也不自动加入文档。具体提交与权限降级策略见 02 文档。

官方依据：[Navigation 3](https://developer.android.com/guide/navigation/navigation-3/get-started)、[Photo Picker](https://developer.android.com/training/data-storage/shared/photo-picker)、[部分照片访问](https://developer.android.com/about/versions/14/changes/partial-photo-video-access)、[MediaStore](https://developer.android.com/training/data-storage/shared/media)、[DataStore](https://developer.android.com/topic/libraries/architecture/datastore)。

## 9. 边界

1. 文档、节点和压缩后的图片保存在本机；无账号和云同步。
2. 预览裁切不覆盖本地 WebP，Markdown 使用完整图片比例。
3. 文字编辑、插入、删除与排序即时更新本地文档，不产生待解析或待同步状态。
4. 简介与备注统一在节点编辑中修改，文档页只渲染节点中的图片和内容。
5. 导出包含 `.md` 与图片文件，可脱离应用阅读；另有图片内嵌的单文件 HTML 导出。
6. 初版不实现系统级悬浮窗、分享接收、归档与独立设置页；节点编辑使用独立全屏页面。文档抽屉提供新建、切换、删除，以及五套外观方案切换；颜色和按钮样式与 agit 共用公共 UI 能力。
7. 初版验收闭环：完整/部分/拒绝权限均能进入首页；重进正确发现差异且重复进入不重复入待选；新建、选择图片、编辑文字/章节、插入、菜单移动、拖动确认合并、删除、重启恢复、阅读、复制与 ZIP 分享可串联完成。源图删除不影响已导入文档。
