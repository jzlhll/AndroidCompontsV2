# AGit

AGit 是一个简单的 Android Git 客户端。第一版只接入 GitHub，通过用户填写的 Personal Access Token 支持私有仓库，围绕 clone、查看或编辑文件、commit、fetch 和 push 完成最小工作闭环。

具体状态判断与操作边界见 [git-workflow.md](git-workflow.md)。

## 项目与界面

- 首次使用且没有任何 Token 分组时，先要求填写 Token 名称和 Token，创建一级分组。
- 添加 Token 分组时，已有有效作者邮箱则显示 `Save`；尚未配置作者邮箱则显示 `Next`，进入 `Commit author` 后最终一次保存分组和作者。中途返回不创建未完成分组，Token 草稿只在内存中保留，不写入 SavedState 或导航参数。
- 抽屉没有 Token 分组时不显示右上角 `+`，主体居中显示“添加 Token 分组”。不在底部保留独立的添加分组入口；有分组后，点击 `+` 才临时弹出已有分组与新建分组的选择，新建分组保存后继续填写仓库地址。
- 左侧抽屉采用两级结构：一级显示 Token 名称，二级显示该 Token 分组下的多个项目。一个分组内只能添加该 Token 有权访问的仓库，不在抽屉中展示 Token 明文。
- 点击抽屉 `+` 时，先选择已有 Token 分组或新建一级分组，再输入仓库地址并 clone；第一版的“新建项目”表示添加已有 GitHub 仓库，不包含创建 GitHub 远端仓库。
- `CloneScreen` 提供 full、depth、无Git 三段选择，选中块以水平滑动动画切换，也支持左右滑动选择。模式说明为 13sp，紧跟三段式，与数量行相隔 6dp；数量行与下方操作按钮相隔 32dp。数量行始终保留布局位置，仅 depth 模式显示并允许操作，切换时说明和按钮不发生上下位移。depth 默认 10，通过居中的左箭头、数量、右箭头调整，最小为 1；不显示左侧标签。无Git 选项使用眼睛图标和文字，按钮改为“下载”。
- 项目放在 FileProvider 已映射的 `filesDir/shared/<projectId>/`。三种模式先写入不共享的 `filesDir/temp/clones/<projectId>/`，下载、检出或解压完成且资源关闭后，再将 `content/` 原子改名为正式目录并登记；取消或失败时等待引擎停止，再删除本次未完成目录。启动后延迟 3 秒检查临时目录和未登记的正式目录，复用项目锁等待正在进行的操作，不清理已登记项目。
- 无Git 模式下载默认分支的 ZIP 源码快照，不创建 Git 仓库。标识使用灰度配色和带斜线的眼睛图标；三段式的无Git 选中块使用灰底，顶部用小圆角标签显示图标和“无Git”，抽屉项目名旁仅显示图标。只保留文件浏览、图片和视频预览、外部只读查看，不扫描 Git 状态，不显示修改、编辑、commit、更新或 push 入口。
- 主区域展示当前仓库的目录和文件，显示当前分支、文件修改状态、本地待推送提交和远端更新状态。
- 提供 commit、更新、push 入口；更新先 fetch，再根据本地和远端状态决定后续动作。
- 空 Token 分组在调节图标左侧提供“选择 / Select”；有仓库的分组仅在二级项目行提供选择入口。选中后入口原位显示“✓ 当前 / Current”，当前分组名称使用强调色，当前项目同时保留选中背景。
- 当前 Token 分组与当前项目一起持久保存，重启恢复相同上下文。旧数据未保存当前分组时，优先沿用最近项目所属分组；没有最近项目时使用第一个分组。
- 主界面和抽屉顶部显示当前 Token 分组名。有项目时直接进入仓库目录，主界面下方的大标题显示项目名和当前目录；空分组则显示“还没有仓库”和 `Clone Repository`，不会展示或自动切换到其他分组的仓库。空态的 Clone 入口直接使用当前分组，抽屉 `+` 仍可选择其他分组或新建分组。
- 顶部标题下显示提交身份：有填写姓名显示姓名，否则显示完整邮箱。作者邮箱必填、姓名选填；姓名留空时，实际 Git 提交作者名使用邮箱 `@` 前的部分。
- 文件列表保留文件类型图标、文件名、大小及状态；复用 `mydroid` 的文件类型图片，不展示与当前操作无关的实现说明。
- 界面保留清晰的标题、空态和一句简短引导，说明当前页面用途或下一步操作；作者命名回退、凭据存储方式等规则不作为界面提示。结果提示只展示实际结果，异常提示保留原因和必要的处理动作。
- 文件状态统一为绿色 `A` 新增、蓝色 `M` 修改、红色 `D` 删除、紫色 `R` 重命名、橙色 `U` 冲突。变动项的名称、浅底色和标记保持同色，未变动项使用普通文字色；目录聚合内部变动数量。删除项保留可见条目，文件名划线。
- 大小按 1024 进位，单位为 `B`、`KB`、`MB`、`GB`；`B` 为整数，其他单位不足 10 时保留一位小数，达到 10 后不显示小数，更大文件继续以 `GB` 表示。
- 图标使用浅色底与石板灰粗线条 `A`，保留顶部斜切留白；Git 分支从左上接入、向右下延伸，横杠中央以青绿色节点强调提交。提供自适应与单色主题版本。
- 普通按钮、描边按钮和文字按钮的最小视觉高度为 Material 3 默认值加 6dp；图标按钮高度为 54dp。
- 抽屉底部提供 `Settings`，`Operation logs` 位于其二级页面。

## 架构与语言

应用模块为 `agit`。唯一业务宿主为 `MainActivity : ComponentActivity`，页面使用 Material 3 Compose，Navigation 3 管理可保存的类型化返回栈，`NavEntry` 管理页面 ViewModel 与可保存状态。Koin 注册数据层与 ViewModel；界面通过 `collectAsStateWithLifecycle` 收集 StateFlow，业务通过公开方法接收用户操作。详细实现见 [architecture.md](architecture.md)。

界面、异常提示、Toast 和操作结果使用 `strings.xml`：`values` 为英语，`values-zh-rCN` 为简体中文；系统应用语言列表只声明英语和简中。操作日志固定使用英文。

外观提供黑色、白色、Dracula、护眼绿四套主题，参考 `Notepadmm` 的 Ember、Mist、Dracula 和 Sage 色板。在抽屉“外观”中选择后立即应用并持久化。状态保持绿 `A`、蓝 `M`、红 `D`、紫 `R`、橙 `U` 的语义，按各主题背景调整文字与底色；不由系统动态取色改变状态含义。

### 耗时操作弹窗与动画

包含多个步骤且明显耗时的操作使用统一进度弹窗，例如 push 的 fetch、状态检查、push，以及新建分支后推送。clone 等单步长耗时操作也复用该弹窗；普通目录浏览和 `onStart` 状态刷新不弹窗。

- 视觉采用带黑客终端感觉的深色背景、等宽字体和少量绿色高亮，配合命令提示符与闪烁光标，保持内容清晰可读。
- 每个步骤开始时，命令行以短促的逐字输入动画出现；随后显示循环变化的 `.`、`..`、`...`，营造命令敲入后等待执行的感觉。
- 同一个弹窗连续展示全部步骤，已完成的步骤保留并标记成功，当前步骤显示等待动画，后续步骤保持待执行状态。长输出可滚动，当前执行步骤始终容易找到。
- 命令内容对应当前实际操作；使用 Git 库时展示等价 Git 命令，不伪造底层终端输出。Token 和携带凭据的 URL 不进入显示内容。
- 动画由真实执行状态驱动，不为播完动画延迟操作。步骤快速结束时立即补全命令并展示结果；没有可用进度时只显示等待状态与已用时间，不模拟百分比。
- Clone 页面和执行弹窗的标题统一为 `Clone Repository`，不翻译。收到下载数据后显示实际已接收大小，不估算总大小；Clone 执行期间 Activity 在前台保持屏幕常亮，结束或进入后台后恢复。
- 成功后停止动画并显示完成结果，用户点击完成关闭。失败或检查不通过时立即停止后续步骤，保留已完成步骤和具体原因，提供适用的后续操作。
- 执行中不允许通过遮罩或返回键误关闭弹窗，也不允许重复发起同一操作。仅在执行引擎支持安全取消的阶段提供取消入口，实际停止后才显示已取消；关闭结果弹窗不触发重试。

## 文件查看与编辑

- 图片接入本仓库的 `Module-ImageCompressed`，复用已有图片加载与处理能力。
- 视频使用 [Media3 ExoPlayer](https://developer.android.com/media/media3/exoplayer) 等 Android 播放库。
- 文本文件统一调用系统中可处理该文件的应用查看和编辑，AGit 不内置文本编辑器。
- 文本通过 FileProvider 分享仓库内的实际文件，编辑时授予该文件的临时读写权限，优先直接保存回原文件；不增加手动导入或另存为操作流程。
- 每次 `onStart` 扫描当前仓库的 Git 状态。原文件被修改时直接显示修改；发现对应原文件的新增后缀文件时，提示是否覆盖原文件，用户确认后再替换并刷新状态。不把任意未跟踪文件都视作编辑副本。
- FileProvider 接入方式及外部编辑兼容性边界见下文；没有可处理的应用时给出明确提示。

### FileProvider 与外部编辑

复用 `Module-AndroidCommon` 的 `${applicationId}.fileprovider` 和 `getUriFromFile(context, file)`。现有 `openWith` 仅使用 `ACTION_VIEW` 与读取授权，编辑入口需要单独使用适合编辑的 Intent 并授予写入权限。仓库位于现有 `shared/` 映射范围内，不新增 Provider 或扩大共享根路径。

共享目录不等于向其他应用公开整个仓库。每次只授权所选文件，不授权 `.git`、凭据或整个目录；解析路径后拒绝越出仓库的符号链接目标。Token 保存在共享目录之外。

目标兼容行为是：支持回写的外部应用直接修改原文件；产生同名加后缀副本时，通过 `onStart` 的状态扫描发现仓库中的新增文件，再由用户决定是否覆盖。替换前展示原文件和候选文件路径，确认原文件没有在提示期间再次变化；拒绝覆盖时保留两份文件，避免每次 `onStart` 对同一未变化候选反复弹窗。

标准 FileProvider 支持对已授权文件读写，但不提供任意创建相邻文件的能力，AGit 也不能控制其他应用的保存位置和命名。因此，上述副本检测仅适用于已经写入仓库的文件；外部应用将副本保存到其他位置时无法通过 `git status` 发现，第一版不承诺兼容这类保存方式。仅凭文件名不能确认来源，必须让用户核对。参见 [FileProvider 文档](https://developer.android.com/reference/androidx/core/content/FileProvider)。

`onStart` 是刷新触发点，不是外部应用已经写入完成的保证。commit、覆盖和更新文件前重新检查文件状态；编辑仍未结束时暂缓会改动文件的 Git 操作。

## GitHub 与 Token

第一版通过 GitHub HTTPS 仓库地址和所属一级分组的 Token 访问仓库。每个分组保存用户填写的 Token 名称及受保护的凭据，同组项目通过分组标识引用凭据，不各自保存 Token 副本。后续 clone、fetch 和 push 均使用所属分组的 Token；验证某个仓库的访问失败时保留分组，提示检查 Token 权限或仓库地址。

Token 作为认证凭据使用，不拼入仓库 URL，不写入 `.git/config`、日志或提交内容；本地持久化使用系统密钥保护，存放于共享目录之外。认证凭据与 commit 的作者姓名、邮箱分别配置。

GitHub 支持 fine-grained 和 classic Personal Access Token；优先引导使用只授权目标仓库的 fine-grained Token。Token 的实际访问能力仍受账号权限与组织策略约束。参见 [GitHub Personal Access Token 文档](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)。

## 同步原则

`fetch origin` 获取远端对象并更新本地的远端跟踪引用，本身不改变当前工作文件。AGit 的“更新”操作在 fetch 成功后继续判断是否可以更新文件。参见 [git-fetch 文档](https://git-scm.com/docs/git-fetch)。

- 本地没有未提交修改，也没有独有提交，而远端存在新提交时，自动将本地快进到远端最新提交；文件内容与重新 clone 同一分支的对应版本一致。
- commit 允许逐文件勾选，不支持按代码行拆分。先提交需要推送的修改，再执行 push；未勾选的文件保留在本地，不随 push 上传。点击 push 后先 fetch；只要目标远端分支存在当前本地未包含的提交，就提示“远端有更新，不允许 push”。
- 被阻止后，用户仍想推送时，主动选择新建临时分支。该分支从当前本地 `HEAD` 创建，包含本地旧代码节点及自己的开发 commit，再推送到远端同名新分支。
- 第一版不把本地 commit 迁移到最新远端代码上，也不自动创建临时分支或替用户解决分叉。
- fetch 失败时保留本地内容，禁止根据旧状态继续 push。“更新”可以在满足条件时快进文件；push 前的 fetch 只用于检查，不隐式更新文件。
- 不支持强制推送，不在手机上进行 rebase、冲突解决或会产生冲突的合并。

“未提交修改”包含工作区、暂存区和未跟踪文件；“提交分叉”表示本地和目标远端分支各自存在对方没有的提交。两者分别判断，不能仅靠文件是否修改来决定能否 push。普通 push 的快进约束参见 [git-push 文档](https://git-scm.com/docs/git-push)。

## 第一版边界

先完成单一 `origin`、GitHub HTTPS + Token、多个本地仓库，以及基本文件访问和 Git 操作。不做手机端 IDE、终端、SSH、其他 Git 托管服务、PR 管理或复杂 Git 历史编辑。

## 实施顺序

1. 完成 Git 引擎的 Android 兼容性验证，打通 Token 一级分组、私有仓库 clone、凭据保存和多个项目目录隔离。
2. 完成抽屉、目录浏览和按文件类型打开；接通 FileProvider 编辑回写、`onStart` 状态刷新及副本覆盖提示。
3. 完成作者身份配置、逐文件 commit、更新、push 前 fetch 检查，以及被阻止后主动新建分支推送的闭环，并接入统一的终端风格进度弹窗与动画。

## 异常反馈与行为跟踪

clone、commit、fetch、更新、push、临时分支操作记录开始、步骤、结果和失败分类，通过 `Module-AndroidCommon` 的 `logd` / `loge` 落盘。操作以 trace ID 和 project ID 关联；目录扫描、项目切换、外部打开与编辑结束也记录必要状态。日志目录沿用 `FileLog.logDir`，保留策略沿用模块的七天清理机制，不另建共享日志目录。

用户反馈通过 `Module-AndroidUi` 的 `ToastBuilder` 展示；进度弹窗打开时附着当前弹窗窗口，避免提示被遮挡。进度弹窗保留失败步骤、原因及未执行步骤，关闭结果不触发重试。

日志查看沿用 `Module-AndroidLogSystem` 的展示方式：按日期分组的文件列表显示文件名和大小，支持查看、确认删除及最多三份日志压缩分享。内容页使用等宽文字和级别颜色，可切换换行、时间、进程/线程、级别、标签。入口统一为 `Settings → Operation logs`，不新增悬浮入口或全局监听；读取日志不会暂停正常落盘。

| 场景 | 处理 |
| --- | --- |
| Token 过期、撤销或失去授权 | 提示可能的认证失效，保留分组、项目及本地文件；在原分组更新 Token 后重试。无法从认证响应精确区分过期、撤销与权限不足时，不伪造结论。 |
| 仓库不存在或无访问权限 | 提示核对仓库地址、Token 所属分组和仓库授权，不删除分组。 |
| fetch 失败或取消 | 停止后续快进和 push；保留工作区与本地提交，记录失败分类并显示 Toast。 |
| push 被拒绝 | 区分非快进拒绝、权限或分支保护等类别，核对最新远端状态；不强推。远端领先时提供主动创建临时分支的入口。 |
| push 网络中断、结果不确定 | 再次 fetch，核对远端是否包含本次 HEAD；已包含则确认成功，无法确认时保留本地提交，提示重新检查，不自动重复 push。 |
| 临时分支推送失败 | 保留新分支、原分支引用、提交和工作文件；持久化待推送目标，后续重新 fetch 并核对同名目标后可继续普通推送，成功后配置上游。 |
| 文件持续写入或提示期间变化 | 停止 commit 或覆盖，要求结束外部编辑并刷新核对；不覆盖新内容。 |
| 外部应用不支持查看或编辑 | 使用模块 Toast 明确提示，不增加导入或另存为流程。 |

日志不包含 Token、解密结果、凭据 URL、文件内容、提交说明或原始网络异常；失败记录使用受控英文错误码和异常类型，避免异常原文泄露凭据。终端风格弹窗中的输出为实际步骤和应用计算的状态，不伪造 shell 输出或百分比。
