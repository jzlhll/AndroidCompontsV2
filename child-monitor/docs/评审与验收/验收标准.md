# 儿童监控验收标准

覆盖 V1 主体和 V1.1 扩展的功能、数据一致性、故障恢复及目标设备验收。当前功能已有源码入口、Room v1 Schema 文件已存在；完整构建、Schema 一致性、正式编码、真实识别和长时故障恢复仍缺通过证据，不能签署验收通过。

正式执行时记录受验提交、工作区差异、APK 哈希、设备与规则/模型版本，使用同一版本的交互、技术和扩展文档。所有场景均待执行；涉及 D06 至 D09 的未决结论先记阻塞。

## 2 执行规则与准备条件

### 状态和优先级

- **待执行**：尚未执行，或仅有源码与文档线索。
- **通过**：指定版本和设备上的步骤、界面、持久结果及必要媒体证据全部满足标准。
- **失败**：实际行为与已确定标准不符，须记录复现条件和缺陷编号。
- **阻塞**：缺少设备、受验包、故障注入条件、明确口径或必要证据。
- **不适用**：仅用于经确认不在受验设备或版本范围内的项目，必须写明理由；不能用于隐藏未实现功能。

P0 为采集、数据真实性、保存恢复、授权及误删等关键项目；P1 为其余已承诺功能和交互。以下场景初始状态全部为待执行；含第 3 节未决口径的判定部分先记阻塞。每行包含多个分支时，逐分支记录结果，不能只执行其中一条便标整行通过。

故障注入若无法稳定完成，记录为阻塞，不把普通退出或正常停止当作进程崩溃、写入失败的替代证据。缩短配置可用于交互排查，但默认时间和长时设备验收仍须使用真实时长。

时间边界优先对照采集时间和持久化微秒偏移。界面秒数、模型确认窗口、关键帧 seek 精度分别记录，不把界面四舍五入后的显示当作规则输入。

## 3 受验标准与阻塞事项

采用全画面自动校准，无座位框选或空座位采集；录像正式链路为 VideoOutput + MediaCodec / MediaMuxer，分析最低 640×480。设置为统一覆盖层，录像期间参数只读；停止先确认、启动取消直接执行。家长授权在同一前台会话有效，离开后重新验证。

D06 容量策略、D07 评价集合与金样、D08 释放异常恢复出口、D09 样本及性能预算见[待确认事项](设计约束与待确认事项.md)。这四项未闭环的对应判定仍阻塞。完整构建、Schema 一致性与设备证据为独立门槛，不因文档统一而通过。

## 4 核心闭环验收

先在默认配置、家长保护关闭、空间充足的设备上执行一次：首次首页 → 开始 → 完整人脸和双肩入镜 → 自动校准 → 正常与异常检测 → 提醒 → 停止确认 → 保存 → 结算 → 事件回看 → 返回相册 → 删除 → 再次开始。随后开启家长保护重走受保护入口。

全程核对同一 sessionId：准备、监控、暗屏、查看设置和重新校准不得拆分会话；录像、事件、提醒、评价与文件目录必须可关联。任何 P0 失败先定位处理，再继续依赖该能力的场景。

### C 检测事实与计数

依据：交互主文档第 4 节，技术主文档自动校准与检测事实章节。每个姿态项目均单独执行正例、反例和边界；效果结论需 D09 约定的标注样本。

| 编号 | 级别 | 操作与条件 | 通过标准 |
| --- | --- | --- | --- |
| C01 | P0 | 正常读写与短暂动作；低头/前倾、偏头、侧倾分别持续不足及达到默认 5 秒 | 不足确认时间不计异常；确认后起点回填候选起点；正常读写不直接等同于低头异常，转头不直接等同于偏头 |
| C02 | P0 | 异常后短暂恢复再异常，随后稳定恢复 2 秒 | 恢复抖动不拆成多次；稳定恢复后终点回填恢复起点；同类持续异常及重复提醒不重复计次 |
| C03 | P0 | 低头/前倾标签重叠，或偏头与侧倾同时发生 | 低头/前倾不重复生成总异常计数；各分项分别记录，总姿态异常时长取区间并集，不能相加重复计时 |
| C04 | P0 | 某分项关键点缺失、仅面部消失、检测关闭、观测乱序/迟到或超过有效间隔 | 只影响不可靠分项；不补假坐标，不将未知填为正常或异常；超过当前默认 1 秒证据间隔中断连续性；旧会话观测不进入新会话 |
| C05 | P0 | 未校准时路过；校准后真实离开画面，保持背景稳定且无移动物体 | 未校准不计此前离座；人物、人脸和有效肩部消失，原人物区域变化且背景稳定才积累候选；默认 3 秒确认回填起点，仅可靠片段计时 |
| C06 | P0 | 未观察到可靠离开就遮挡镜头；已离开后遮挡或物体移动，随后恢复证据 | 无人检出不直接判离开；干扰记 Unknown，未知不补时长；同一离开事实恢复后保留 logicalEventId、不重复计次 |
| C07 | P0 | 离开后人物回到画面；半脸、贴边和完整人脸分别持续；加入第二人 | 不完整人脸不确认返回；单人完整人脸稳定约 2 秒才结束离开并取消待播；多人歧义未知，不承诺身份识别或可靠区分路过 |

| C08 | P0 | 半脸、贴边、脸部过小、轮廓缺失、角度过大及遮挡；人体仍可见 | 不完整证据不作为正常校准；监控中立即提示，持续约 3 秒产生 FaceIncomplete，可回看；具体姿态项缺证据不补正常，不新增评分分项 |
| C09 | P0 | 物体出现/消失/移动及背景变化，人物完整人脸仍可见；随后真实离开 | 持续约 3 秒记录 SceneChange，确认后接纳新场景基准，避免旧物体状态持续提示或阻碍离开；事件可回看、不推断行为、不改三个姿态评分项目 |

### F 评价与结算

依据：交互主文档第 7 节、技术主文档评价计算及结算子文档。使用持久化事件、覆盖、配置和休息区间人工复算，不能只比较页面文案。

| 编号 | 级别 | 操作与条件 | 通过标准 |
| --- | --- | --- | --- |
| F01 | P0 | 分别以 179999999、180000000、180000001 微秒会话事实核对评价，再以真实录像检查显示 | 前两者仅小结，最后一种具备评价资格；准备计入、权限等待不计入；保存耗时和重试不增加本次时长 |

以下为验收输入示例，不代表已经执行的测试结果。时间使用持久化真实值；默认其他可判断指标均满足 Great，例中无休息和合理离座，除非特别说明。

## 9 交付判定

正式通过须同时满足：

1. 采用本目录统一的受验标准；D06 至 D09 已确定口径并具备对应证据，受验基线可追溯。
2. 受验包可安装运行，完整构建与 Room/KSP 结果可核验；v1 Schema 已导出、审阅并纳入交付，不用空目录替代。开发中未发布 v1 不强制增加升级迁移；正式发布后的结构变化另验迁移，不能删库重建。
3. 所有适用 P0、P1 场景通过，核心闭环在声明支持的设备组合上通过；未执行、阻塞或缺失证据均不算通过。
4. 无未关闭的数据损坏、误删、授权绕过、重复会话、虚假统计、错误媒体状态或资源占用问题；保存/删除/仅删录像恢复可重复验证。
5. D09 约定的样本效果、时间对齐和长时预算达标；失败设备明确排除或修复后复验，不能以一台设备结果覆盖所有 Android 设备。
6. V1.1 四批扩展逐项验收；如需缩小交付范围，先同步需求和可见入口，不能将仍展示的未完成能力记为不适用。
