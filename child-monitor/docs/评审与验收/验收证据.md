# 儿童监控验收证据说明

本文说明如何使用 child-monitor 的诊断日志，配合界面、数据库和媒体文件执行[验收标准](验收标准.md)。日志覆盖关键控制与提交边界，不代表对应验收已经通过，也不改变原有检测、评级、保存或授权规则。

## 日志入口与采集

统一 Logcat 标签为 `ChildMonitor`，源码只定义 `TAG` 常量，直接使用 `Module-AndroidCommon` 的 `logdNoFile`、`loge` 和 `logDebugEnabled`，不增加业务日志类、输出回调或日志格式封装。

- Debug 包开启 `logdNoFile` 诊断日志；Release 包默认关闭 Debug 日志，保留 `loge` 错误日志。完整验收证据应使用可调试受验包，并记录其版本、提交及 APK 哈希。
- 调试日志通过框架 `logdNoFile` 只写 Logcat；当前框架该函数没有 `forceNoFile` 参数。严重错误通过 `loge` 同时写 Logcat 和框架的 `Log` 目录，Application 初始化框架所需的应用引用。日志不上传。日志缓冲可能被覆盖，须在开始场景前持续采集；进程终止场景不要只绑定旧进程 PID。
- 事件新增或结束原因/配置关联变化时输出事件日志；观察计数随检查点及停止汇总。稳定状态、每帧坐标、每个编码样本、试听音频内容和每次触摸不逐条输出。
- 日志不输出图像、关键点坐标、PIN、盐/摘要、名称、备注、原始文件路径或目标 URI；错误仅附加异常类型，调用类由框架格式提供，不输出可能含用户内容的异常原文。

单台连接设备可在电脑终端执行以下命令，随后冷启动应用并复现场景；场景完成后停止采集。多设备时先选定受验设备，在 adb 参数中指定其序列号。

```sh
adb logcat -v threadtime 'ChildMonitor:D' '*:S' > child-monitor.log
```

Android Studio Logcat 可按包名 `com.allan.childmonitor` 和标签 `ChildMonitor` 过滤。保留完整原始采集文件，另按 PID、启动时间、`sessionId`、`requestId` 整理场景摘录，不以截图中的几行日志替代完整证据。若没有启动头，先确认受验包是否为 Debug、采集是否覆盖启动时刻以及过滤条件是否正确。

## 关联字段与时间口径

| 字段 | 含义与使用方式 |
| --- | --- |
| Logcat 时间与 PID/TID | 使用 `threadtime` 提供的时间、进程和线程字段，结合 `application started` 区分进程启动；PID 可能复用，不能单独作为长期身份。输出时间不是事件采集时间，不据此跨设备重启计算业务时长 |
| sessionId | 业务会话；准备、监控、重定位、保存重试及恢复沿用同一身份 |
| contextSessionId | 通用命令日志当时的 Runtime 上下文；历史操作可能处理另一条记录，目标以具体保存/删除/导出日志中的 sessionId 为准 |
| requestId | 一次命令或导出任务；同一会话可有多个请求。导出和自动恢复有各自请求标识，不要求与开始请求一致 |
| generation | Runtime 采集代次，隔离迟到回调；家长授权日志中的 generation 属于独立授权代次，两者不能互相比对 |
| revision / revisionId | 前者为界面快照或明确命名的设置版本，后者为持久化 ConfigRevision ID；不能混当一套版本 |
| originUs | 首个实际写入样本对应的单调时间；`start recording` 应与同会话的 `encoder first sample` 一致 |
| sourcePtsUs / clockOffsetUs / mediaPtsUs | 编码原始 PTS、时钟映射偏移、归零后的媒体 PTS；首样本 `originUs = sourcePtsUs + clockOffsetUs`，`mediaPtsUs = 0` |
| atUs / effectiveUs / endedUs | 会话内业务偏移；停止取首个被接受的 endedUs，保存耗时不追加本次时长 |
| startUs / endUs / confirmedUs | 事件事实时间；确认后起点可回填，不能直接用日志输出时刻代替；active 事件的 endUs 只是该次检查点进度 |
| eventId / logicalEventId | 数据库事件行与逻辑事件；跨片段计次按 logicalEventId 去重 |
| playerInstanceId | 页面播放器实例，用于核对进入播放与退出/删除/锁定后的释放 |

`state changed` 是内存状态快照，`evaluation calculated` 是计算输出。只有相应 `committed` 日志说明对应 DAO 或 DataStore 调用已成功返回；它不保证稍后没有故障，也不代替重启后的数据库读取。

`command received` 表示进入命令处理，尚未通过业务校验；`command completed` 表示命令函数返回，启动/停止的异步工作可能仍在进行，批量操作也可能部分失败。必须继续检查具体操作的终态及失败数量。

## 场景与证据对应

| 验收范围 | 关键日志 | 必须补充的证据与判断 |
| --- | --- | --- |
| A01 至 A04 启动与准入 | `application started`、`start requested`、`start accepted`、`capture capability`、`command rejected`、`start failed`、`start timed out` | 受验包信息、权限界面、设备能力与实际空间；availableBytes/requiredBytes/targetMs 用于 D06 的空间策略核对，日志不会自动修复该口径 |
| A05、L04 正式录像与对齐 | `encoder configured`、`analysis format`、`encoder first sample`、`start recording`、`encoder finished`、`save committed` | 实际 MP4 的尺寸、方向、音轨、时长、可播放性及标注动作时间；configured 中 audioTracks=0 是编码配置，最终文件仍须探测 |
| A06、E03、K06 停止及释放 | `stop accepted`、`stop ignored`、`stop capture finished`、`capture release components`、`capture released`、`capture release pending`、`stop incomplete` | 首次停止终点、按钮状态、重试/再次启动行为；released=false 或 pending 表示未确认释放，不能因编码 finished 就宣称相机/模型全部释放 |
| B 组定位与失效 | `state changed`、`calibration committed`、`reposition accepted`、`checkpoint committed` | 自动校准步骤、完整人脸 / 双肩 / 光线 / 多人提示、暗屏状态和 10/30/120 秒时间线；faceComplete / sceneChanged 核对半脸、贴边与场景变化；invalidSinceUs 核对重定位是否延长无效截止时间；采样进度仍须录屏 |
| C 组事件 | `event committed`、`checkpoint committed`、`state changed` | 带人工标注的原视频、Event/Coverage/ConfigRevision；检查起止、确认时刻、logicalEventId、有效覆盖及 Unknown，不以日志中有事件等同于识别正确 |
| D 组提醒及休息 | `reminder committed`、`reminder persist failed`、`terminal audio started/finished/canceled/failed` | requested/started/finished/result 逐阶段核对；声音关闭时 started 可代表可见提示，不表示发声；核对 RestWindow、提醒来源和离座候选起点 |
| E 组暗屏与生命周期 | `state changed`、`camera state`、`stop accepted` | 真实屏幕、前后台操作、亮度恢复、中断卡及原因；状态日志不证明触摸没有穿透 |
| F 组评价 | `evaluation item`、`evaluation calculated`、`evaluation committed`、`evaluate once reused` | Evaluation 快照及人工复算；calculated 显示真实分母/覆盖率，committed 才表示持久化调用完成；D07 的预期公式仍须先确认 |
| G 组相册与播放 | `player registered`、`player released`、`delete intent committed`、`delete committed`、`delete sessions finished` | 列表、筛选、选择、返回栈录屏；seek 的请求及实际位置仍用播放器显示和媒体时间核对，当前日志不提供 seek 完成证明 |
| H 组设置 | `update settings committed`、`update preferences committed`、`command rejected/failed` | 新旧版本、effectiveUs、持久化配置和页面回显；头像仅记是否修改，不输出草稿；失败后重读原值，不能只看成功提示 |
| I 组目标及存储 | `state changed`、`stop accepted reason=TargetReached`、`storage low`、`purge video intent committed`、`purge video committed`、`retention finished/failed` | 文件删除前后、统计保留、空间实测、OperationIntent；目标到点日志不证明实际空间足够完整录到目标 |
| J01、J02、J06 历史与标记 | `note committed`、`annotation committed`、`evaluation committed` | 名称备注、标记及汇总结果由 UI/数据库核对；日志仅记身份及 label，不含文本，不替代逐日分项复算 |
| J03、J04 导出 | `export accepted`、`export completed`、`export failed` | 同 requestId 的复制字节数、源与目标文件大小/哈希及可播放性；targetDeleted=false 时确认提示和残留处理；进程被杀后没有完成日志不能推断目标已自动清理 |
| J07 至 J10 授权 | `parent configure committed`、`parent verify result/blocked`、`parent access locked`、`parent device credential authorized`、`record access denied` | 前台/后台及敏感入口录屏，cooldownStarted/remainingMs 核对冷却；旧 requestGeneration 与当前 generation 不一致时不能 authorized=true |
| K 组保存与恢复 | `save intent committed`、`save file moved`、`save committed/unavailable/failed`、`recover started/session/finished`、`restore facts committed` | 同一 sessionId 的目录、manifest、Media、OperationIntent、检查点与未知尾段；先有文件移动日志仍不算 Saved；恢复后须重新读取结果 |
| L 组长期运行 | 周期性 `checkpoint committed`、`encoder finished`、停止/资源日志 | 外部内存/温度/耗电记录、完整媒体及标注样本；计数或日志连续不构成性能、准确率或无掉帧证明 |

`acceptedObservations` 为本次运行中通过 Runtime 时间筛选并交给引擎的观测数；`rejectedObservations` 仅统计匹配当前活动会话但时间早于起点、乱序/重复或过期的观测，不包含平台限频丢帧、推理前丢帧及旧会话回调。两者不能计算摄像头丢帧率或识别准确率。无回调时检查点仍可能由 Runtime 时钟推进，需要同时查看观测计数、Unknown 覆盖及停止原因。

`capture release components` 中 `null` 表示该组件没有可读的当前句柄，不等于已验证成功；`isCompleted` 是现有释放信号状态，不是系统资源检测工具。释放异常的 D08 仍需按验收文档闭环。

## 一次正常会话的取证步骤

1. 固定受验包、设备、默认配置与样本，启动连续 Logcat 采集，记录 `application started` 的时间与 PID。权限等待期间的录屏另保留。
2. 找到 `start accepted` 的 sessionId 和 requestId，核对配置版本、空间预估；对照 `encoder first sample` 与 `start recording` 的 originUs。
3. 完成自动校准、一个持续姿态事件、半脸 / 贴边 / 脸部不可见、一次物体变化和一次离开 / 返回；保留操作录屏与标注时刻。用 `calibration committed`、`event committed` 和提醒记录核对事实与实际动作。
4. 确认停止后，记录首个 `stop accepted` 的 reason/endedUs；核对 `encoder finished`、资源释放、`evaluation committed` 与 `save committed`。不同线程的日志输出可交错，以标识和业务时间关联，不要求所有日志排成固定总顺序。
5. 打开结算和回放，记录实际定位位置、结果及返回路径。读取同 sessionId 的持久结果，并对实际 MP4 做媒体探测。
6. 重启应用，再次查询记录，比较评价快照、事件、媒体及文件身份。仅生成一次录像、不因查看重算评级；保存重试或恢复复用评价时可看到 `evaluate once reused`，普通读取历史结果不要求输出该日志。

## 故障场景的取证步骤

在验收数据上，分别选定封装、移动后提交前、最终事实提交及删除阶段实施故障。保留故障前日志与数据快照，记录注入时刻；以 PID 与启动时间区分重启前后，sessionId 保持，用两个进程的日志和持久结果还原链路。

- 保存失败：核对源文件是否经过验证、当前媒体状态及重试入口。`save failed sourceVerified=true` 只说明本次探测成功过，之后文件仍可能变化，不能代替重试时重新验证。
- 进程恢复：核对 `recover session` 的 checkpointUs/mediaEndUs 与 `restore facts committed` 的 unknownTail；未知尾部不能被补成正常或异常。无结束日志可能是进程被杀或采集丢失，不直接判代码没有执行。
- 批量删除/仅删录像：按每条 sessionId 的 intent/committed/failed 和批次 failed 数量核对。命令返回不表示每条成功，只有最终数据与文件均符合才关闭问题。
- PIN 迟到验证：保留离开前验证、`parent access locked` 与验证结果；授权代次改变后，即使 correct=true，也必须 authorized=false。
- 导出中止：记录已复制字节数、清理结果与目标文件实际状态。后台进程终止没有自动续传保证，不能用普通取消替代该场景。

## 证据包与完成标准

每个场景至少提供：场景编号及分支、受验版本和 APK 哈希、设备/系统、配置/模型版本、PID/启动时间/sessionId/requestId、预期与实际、原始日志、操作录屏、必要数据库快照与媒体探测结果、缺陷及复验结论。

数据库取证必须获得一致快照：使用 Database Inspector 或在应用停止且确认无写入后采集数据库及其 WAL/SHM 配套文件，不只复制一个仍在写入的主库文件。记录导出/采集时刻；只整理本轮验收会话对应的文件与数据。评价必须能追溯到其 Event、Coverage、RestWindow 和 ConfigRevision，媒体必须能追溯到相同 sessionId 的 manifest 与最终文件。

建议每个场景独立保存以下材料，实际目录名采用场景编号和设备标识：

```text
A05-device/
  environment.md
  child-monitor.log
  actions.mp4
  media-info.txt
  data-snapshot/
  result.md
```

日志实现完成只能记为“具备取证入口”。只有取得受验设备上的实际证据并满足[验收标准](验收标准.md)标准，才能标记通过。完整构建、Room Schema 一致性、D06 至 D09 和真机长时效果仍沿用原交付门槛。
