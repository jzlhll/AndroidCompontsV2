# 儿童监控技术文档 V1

本文维护当前 Android 工程的架构、采集、检测事实、持久化和恢复边界。用户行为与默认值见[交互设计](../交互设计/主.md)，设备交付门槛见[评审与验收](../评审与验收/验收标准.md)。源码已接入不代表运行验证通过。

## 工程与技术选型

唯一应用源码位于 `androidApp/src/main/kotlin/childmonitor/`；根工程 `:child-monitor` 指向 `child-monitor/androidApp`，也保留独立 androidApp 入口。两种入口都依赖完整仓库中的 Module-AndroidCommon 和依赖目录。应用 ID 为 `com.allan.childmonitor`，namespace 为 `childmonitor.android`。

| 包 | 职责 |
| --- | --- |
| model | 配置、观测、记录和不可变快照 |
| domain | 唯一 MonitorRuntime、DetectionEngine、SceneChangeTracker、ReminderScheduler、EvaluationEngine |
| data/database、preferences、repository、coordinator | Room、DataStore、查询与设置、RecordCoordinator 保存删除恢复 |
| storage、platform | 应用目录、相机、模型、编码、时钟、音频、播放和导出 |
| app、ui | Application 装配、单 MainActivity、Compose / Nav3 页面与 ViewModel |

使用 Kotlin、协程/Flow、kotlinx.serialization、Room + KSP + BundledSQLiteDriver、DataStore Preferences、CameraX、ML Kit Pose/Face、MediaPipe Object Detector 和 Media3。最低 API 29，日期使用 java.time，业务模型不持有 Activity、View、播放器或导航栈。

当前锁定 JDK 17、compileSdk 37、targetSdk 36、Gradle 9.6.0、AGP 9.4.0、内置 Kotlin 2.4.20、KSP 2.3.12；CameraX 1.6.2、ML Kit Pose 18.0.0-beta5、Face 16.1.7。其他精确版本直接查[依赖目录](../../gradle/libs.versions.toml)，避免重复维护版本表。CameraX 受限高级接口的版本兼容性仍待完整工程验证。

## Runtime 与页面

Application 持有唯一 MonitorRuntime、Repository 和平台适配器。Runtime 在应用作用域接受命令、串行推进状态；IO 和模型结果携带 sessionId/generation，requestId 关联操作，快照 revision 区分更新。取消、停止和恢复按同一身份处理，旧会话与迟到观测不进入新会话。

运行态为 Idle、Starting、Preparing、Monitoring、Stopping、Stopped；媒体保存态独立为 Finalizing、Saved、RetryableFailure、Unrecoverable、MetadataOnly。首个接受的停止固定终点，保存等待不继续累计业务时长。相机、Surface、编码器和模型未确认释放时禁用新开始。

Compose 通过 ViewModel 按生命周期收集 StateFlow；Nav3 使用类型化可序列化 key、可保存返回栈与 NavEntry 作用域，路由只携带 sessionId、来源和少量恢复参数。进程恢复核验运行态、记录与授权，不自动重启监控。CameraX PreviewView 经稳定 AndroidView 接入，计时、提示、设置和暗屏不重建预览。

设置为首页内统一覆盖层，检测与提醒可动态调整，头像和存储设置在覆盖层内切换；主界面始终保留在组合树中。暗屏等待、相机检查、清理和默认恢复单独要求停录。相册与播放检查资源已释放及 Idle/Stopped；家长保护另检查授权。删除后清理引用该记录的结果和播放 key。页面可以取消订阅，已接受保存、删除和导出由应用完成；进程终止后的恢复依靠持久化。

## 采集、模型与时间

CameraX 同时绑定 Preview、VideoCapture、ImageAnalysis。正式编码为 VideoOutput + MediaCodec / MediaMuxer，Recorder 仅提供 SD 质量配置；Debug Recorder 探针不能替代正式链路验收。视频短边不超过 480、长边不超过 854，无音轨，不申请麦克风权限。分析输入短边至少 480、长边至少 640，采样约 5 Hz、只允许一帧推理在途，过期帧丢弃不积压。

ML Kit Pose 提供姿态点，打包 Face 模型提供完整轮廓及角度，EfficientDet-Lite0 INT8 提供人体和非人体物体框。Face 检查 36 点外轮廓、双眼、鼻和唇部，框及轮廓留 2% 边距，分析图人脸至少 200×200；半脸、贴边、遮挡和轮廓缺失不能作为正常校准。模型来源、尺寸与 SHA-256 见[模型清单](../../androidApp/src/main/assets/models/manifest.json)。

Observation 只带规范化观测：采集时间、转正未镜像坐标、landmarks、people、faces、objects、sceneGrid、质量和模型/映射版本；ImageProxy 等缓冲由适配器负责关闭，不进入业务模型。模型结果按采集时间处理；超过默认 1 秒证据间隔、乱序、过期或旧代次均不能补成连续事实。

首个实际写入的编码样本定义媒体与会话时间起点；sourcePtsUs 经 clockOffsetUs 转换为 originUs，mediaPtsUs 从零开始。未知摄像头时钟源拒绝启动。事件使用会话微秒偏移，seek 扣除 videoOriginOffsetUs 并核对实际播放器位置；墙钟仅用于固定日期。重启不延续旧单调时钟。

## 自动校准与检测事实

完整人脸、双肩和自然正向姿态稳定约 3 秒自动采集基准，使用有效样本中位数和稳定性约束。无需人工 ROI 或空座位采集；Calibration.roi 仅兼容旧快照，新会话不使用或保存座位区域。reposition 清除旧校准、人物、场景与休息许可，关闭旧覆盖并增加校准版本，沿用同一录像；已有连续无效截止时间保留。

SceneChangeTracker 保留人物完整入镜时的亮度、色差和纹理网格、自动人物框及非人体物体集合。人物仍可见时，物体出现/消失/移动或背景网格持续变化产生 SceneChange；约 3 秒确认且完整人脸可见后接纳新基准，避免旧物体状态长期阻碍离开判断。人物、脸和有效双肩都不可见时，仅在原人物区域明显变化、背景稳定且物体无干扰时积累离开候选。遮挡、多人与证据不足转 Unknown；设备移动需重新校准。

人体可见但人脸不完整时立即提示，持续约 3 秒记录 FaceIncomplete，复用姿态提醒。低头与偏头使用可用的头肩及人脸角度证据，侧倾使用可信躯干相对基准；某项缺证据只影响该项有效覆盖，不补正常。FaceIncomplete、SceneChange 只供提示和事件回看，评价仍只有三个姿态分项。

事件确认后起点回填候选时刻，稳定恢复默认 2 秒后回填终点。同一 logicalEventId 跨可靠片段去重，Unknown 不补离座或姿态时长；完整人脸持续恢复后才确认返回。全画面差异属于启发式证据，不能保证识别身份或绝对区分遮挡与离开，须用标注样本验收。

持续无效由 Runtime 时钟推进：默认 10 秒提醒、30 秒操作提示、120 秒停止；无模型回调也不能无限延长。多人退出后可稳定恢复，设备移动保留人工确认。各默认值、休息许可和提醒阈值见[交互规则](../交互设计/主.md)。

## 数据、文件与恢复

Room version = 1，含 Session、Media、ConfigRevision、Event、Coverage、RestWindow、Reminder、Evaluation、MonitorSettings、OperationIntent、EventAnnotation 共 11 张实体表。[v1 Schema](../../androidApp/schemas/childmonitor.data.database.MonitorDatabase/1.json)已存在，正式发布前仍需核验与实体及实际建库一致；开发期未发布 v1 不新增迁移，发布后结构升级须显式迁移，不能删库重建。

| 数据 | 唯一归属与提交边界 |
| --- | --- |
| 会话、媒体、事件、覆盖、提醒、休息和评价 | Room，事实和检查点按事务提交 |
| 检测/声音/目标/休息配置 | Room MonitorSettings，独立 monitorRevision；会话 ConfigRevision 保留实际配置和校准 |
| 头像、暗屏等待、保留期 | DataStore UserPreferences，独立 preferencesRevision，原子合并字段 patch |
| 家长 PIN、盐/摘要及失败冷却 | 独立 DataStore，授权只在当前前台内存会话有效 |
| 保存、完整删除、只删录像 | Room OperationIntent：save、delete、purge_video；文件操作可恢复且幂等 |
| 事件标记与名称备注 | EventAnnotation 与 Session，不修改原始检测事实或历史等级 |
| 视频与恢复清单 | 应用 filesDir/child-monitor；数据库只存相对路径 |
| 封面和统计报告 | 可重建缓存；报告分享范围见[扩展设计](../扩展设计/功能扩展.md) |

```text
filesDir/child-monitor/
  database/monitor.db
  preferences/user.preferences_pb
  sessions/YYYY-MM-DD/<sessionId>/
    manifest.json
    recording.pending.mp4
    video.mp4
```

日期、timezoneId 和 localDate 在创建时固定，跨午夜或修改系统时间不搬迁既有文件。SessionManifest 保留格式版本、sessionId、relativeDir、timezoneId、startedWallUs、videoOriginOffsetUs、stage、暂存/最终文件名、lastCheckpointUs、writtenAtUs；临时文件 fsync、同目录 rename、目录 fsync 后提交。缺字段或损坏清单不能认领 Saved，无数据库身份的孤立目录保留，不补造成完整记录。

保存先结束编码、验证媒体、移动文件，再提交 Saved；文件存在或移动成功不等于保存完成。失败重试复用原会话和可验证源，只补未完成步骤。完整删除与 purge_video 先写意图，再删文件并提交数据库结果；恢复先处理删除，防止已删记录复活。批量允许部分失败，封面失败不拖累主视频。

事实事务成功才推进检查点，停止最终事实提交后才生成评价。同进程重试优先补交内存停止事实；进程恢复只认旧检查点，尾段记未知，补缺失评价但不重算已有快照。单条恢复失败不阻塞其他记录；损坏 MP4 不保证修复，可保留统计。相机等资源不确认释放时需结束进程后进入恢复，迟到释放与结果入口的产品要求仍由 D08 闭环。

启动空间与滚动低水位当前按 2 Mbps × 30 分钟 × 1.2 估算约 540 MB，低水位至少 100 MiB，每 5 秒检查空间，写入错误立即停止；不承诺该预留支持 480 分钟或不限时。是否改为保障目标总时长见[评审事项 D06](../评审与验收/设计约束与待确认事项.md)。

## 配置、提醒与评价

updateSettings(value, expectedRevision, requestId) 与 updatePreferences(patch, expectedRevision, requestId) 按设置策略检查运行状态，分别维护 Room 和 DataStore 版本。Preparing/Monitoring 接受轻量规则与偏好修改；暗屏等待 patch 和默认恢复要求停止及释放。sessionSettings 保留本次实际配置，目标时长与自动停止固定为开始时的值。动态规则变更以 Room 事务保存配置版本及旧段事实，历史事件按原版本解释；不会重新加载模型或重新绑定摄像头。读取失败或未知格式不当首次缺失，不用默认值覆盖已有内容。跨 Room、DataStore、文件不制造伪原子事务。精确签名以[MonitorRuntime](../../androidApp/src/main/kotlin/childmonitor/domain/MonitorRuntime.kt)为准。

ReminderScheduler 负责优先级、间隔、失效取消和休息许可，平台音频只播放固定资源并回报开始/完成/失败。中断/保存故障优先于看不清、离开、姿态与休息；同等级姿态可合并，条件失效取消待播。锁屏语音独立于保存调度，播放失败不阻碍保存。提醒写入失败受控停止，错误分支不再次抛数据库异常。固定语音维护见[语音资源](语音资源.md)。

休息响应按离开候选起点核验，实际播放开始或声音关闭时可见提示建立许可；仅可靠覆盖内实际休息豁免，Unknown 不补时长。首次离座提醒仍按允许时长，评价另用一次合理额度。

### 评价计算

EvaluationEngine 只消费持久化事件、Coverage、RestWindow 和 ConfigRevision，超过 3 分钟才进入等级评价，无可判断分项则完成型。三个姿态项目各取自身有效在座覆盖，计次按 logicalEventId，时长按交集和并集；最低样本、Great/Good/NotBad 和覆盖封顶见[交互评价规则](../交互设计/主.md#7-评价规则)，不重复维护第二套等级表。

当前实现集合如下，作为源码说明；产品预期及金样仍待[评审事项 D07](../评审与验收/设计约束与待确认事项.md)确认：

- ordinaryAway = away_normal 覆盖扣除建议休息；展示 awayUs 为该可靠普通离座总时长。
- gradedAway = ordinaryAway 再扣除首次不超 3 分钟的合理离座片段。
- awaySeated = seated 与 valid_Away 的交集，仅含启用离座检测的有效在座。
- 在座比例和超时频率分母 = awaySeated + gradedAway。
- 有效覆盖率分子 = seated 与 ordinaryAway 的区间并集时长；保留首次合理离座，建议休息不计入。

历史评价保存规则版本和快照，保存重试、记录刷新、再次回看和后续全局调参不重算。SceneChange 与 FaceIncomplete 不进入三个姿态评分项目。
