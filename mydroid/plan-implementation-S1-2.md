# 第一、二阶段：文件发送与连接管理

按第一阶段、第二阶段的顺序实施。第一阶段修通发送链路，第二阶段补齐三种模式的连接管理与传输期间的会话行为。

## 第一阶段：修通客户端文件发送

## 目标与范围

完成“选择文件 → 准备 → 分片上传 → 主机合并校验 → 展示结果”的完整流程，支持取消和手动重试。

沿用现有发送页面、文件选择器及 HTTP 协议。本阶段只调整客户端发送链路和服务端合并落盘逻辑；连接管理在第二阶段处理，整体 UI 改版、速度展示及记录持久化由后续阶段处理。

确定的批量策略：**单文件失败后继续其余文件；同名文件在主机添加序号保存，不覆盖已有文件。**

## 文件选择与准备

- 文件选择器将 URI 交给 ViewModel，在后台使用项目 `myParseSuspend` 读取真实名称、大小及修改时间；状态在主线程回写。
- 同一待发送列表按 URI 去重；不同 URI 的同名文件允许同时存在。每项使用独立任务标识，完成记录也保留任务标识，不以名称作为列表 key。
- 大小无法确定或解析结果为零时，流式复制到本次任务的临时缓存，以实际长度确认大小；复制过程支持取消。确认是空文件后提示不支持发送，不请求上传或合并。
- 文件无法读取、缓存空间不足等问题记为该文件失败，继续处理其他文件。临时缓存在本次尝试结束后清理，重试时重新准备。
- 修改时间按来源转换为毫秒：MediaStore 时间按秒转换，文件及文档提供的毫秒时间直接使用；无法获取时使用本次准备时间。
- 准备、发送及取消处理中禁止追加或移除文件，避免当前批次发生变化。

## 上传、取消与结果

- 文件和分片均串行发送；保留现有分片大小算法。协议编号从 1 开始，读取偏移仍从零计算。
- MD5 流式计算并检查协程取消。分片读取必须到达指定偏移、读取足够字节；`skip` 无进展时使用读取推进，提前结束则报错，不能上传错误片段。
- 为文件项补充准备、待发送、上传、合并校验、成功、失败和取消状态。失败项展示原因；未执行项保留待发送状态。
- 仅收到合并业务成功响应才标记成功；上传到 100% 后仍显示合并校验。请求超时导致结果无法确认时，提示先检查主机文件，不自动重发。
- 单文件失败后清理分片并继续下一项；批次结束展示成功与失败数量。再次开始只处理未成功项，已成功文件不会重复发送。
- 用户取消时停止后续文件；准备或上传阶段取消当前任务。进入合并阶段后显示“完成当前文件后停止”，等待当前结果，不主动中断合并请求。
- 取消异常必须重抛，不作为业务失败。分片清理在有界、不可取消的清理区间内执行，超时设为 `5000.milliseconds`；清理失败只提示未确认清理完成，不宣称服务端已清空。
- 清理结束前不允许启动新批次；重试上传前先调用现有清理接口清除同一文件的残留分片，清理失败则不继续该文件。
- 页面退出时取消所属任务并执行有界清理，不增加后台上传服务。

## 服务端兼容调整

- 合并先写入独立临时文件，MD5 通过后才发布为最终文件；失败时清理本次临时文件和分片，保留已有文件。
- 最终文件名采用 `名称.ext`、`名称(1).ext`、`名称(2).ext`；名称选择与最终落盘在同一临界区完成，避免并发覆盖。
- 上传、合并、清理接口路径及请求字段保持不变。合并成功响应的 `data` 增加实际保存的 `fileName`，客户端在重命名时显示它。
- HTML 继续使用现有成功判断；客户端连接旧服务端时允许 `data` 为空，以原文件名展示。保留同名文件的保证需要新版服务端。

## 场景验收

使用现有 checklist 的发送相关场景，不新增自动化测试。

- 单文件和多文件发送成功，主机文件名称、大小及内容正确。
- 重复 URI 不重复入队；不同来源同名文件均可发送，主机已有同名文件不被覆盖。
- 中间文件不可读或发送失败，后续文件继续；再次开始不重复发送成功项。
- 未知大小文件可准备后发送，空文件有明确提示。
- 准备及上传时取消可停止；合并时取消等待当前结果并停止后续文件。
- 断网、清理失败及合并响应丢失不误报成功；恢复后可按提示手动处理。
- 浏览器上传同名文件仍成功，并保留原有文件。

## 第二阶段：补齐三种模式的连接管理

### 目标与范围

发送、接收、聊天均具备连接登记、心跳、断连反馈、有限重连和主机模式校验。复用现有 `ClientWsClient`，每个当前页面的业务 ViewModel 持有一个实例，不引入全局连接池。

本阶段只补齐连接相关的公共能力与必要页面交互。下载可靠取消、任务持久化、聊天历史去重及完整发送结果处理仍按后续阶段实施。

### 连接建立与状态

- 页面首次进入及每次重连均通过当前 HTTP 地址读取 `/get-mode` 和 `/read-websocket-ip-port`，更新 WebSocket 端口；HTTP 地址不可达时提示重试或返回扫描，不猜测新地址。
- 模式判断以 `/get-mode` 返回的枚举名称为准。`s_clientInitBack.myDroidMode` 当前为本地化展示文字，不能直接用作枚举判断，保持 HTML 字段含义不变。
- 将连接状态区分为连接中、已连接、重连中、失败、模式已变化和主动断开；顶部统一展示状态及当前主机地址。
- WebSocket 打开后发送初始化消息；收到有效初始化回包后才标记已连接，并保存客户端名称与颜色。初始化等待上限为 `5000.milliseconds`，超时进入断连处理。
- 先建立消息订阅再发起连接；身份信息使用状态流保存，避免初始化回包早于订阅而丢失。消息解析异常记录并忽略该帧，不使监听流程退出。
- 接收页补齐 WebSocket，连接成功后请求文件列表；同模式重连成功后刷新列表。已有下载任务仍由原下载服务持有。
- 未连接时禁止开始新上传、新下载、远端列表刷新和聊天发送；本地文件打开操作不受连接状态影响。

### 心跳、重连与释放

- 保留 `c_ping` 协议，间隔使用 `12000.milliseconds`。当前服务端没有应用层 pong，不新增等待 pong 的超时判断；心跳发送返回失败时进入断连处理。
- 被动断开后最多自动重试四次，间隔依次为 `1000`、`2000`、`4000`、`8000.milliseconds`；每次都重新读取主机信息。仅初始化成功后重置重试次数。
- 自动重试耗尽后显示失败，提供“重新连接”和“返回”操作；手动重试重置次数。重复点击或重复断连回调不能产生并行重连任务。
- 为每次连接维护递增标识，忽略旧连接迟到的消息、关闭和失败回调。关闭旧连接不能改变新连接状态。
- 主动退出时先标记关闭，再停止心跳、重连与信息请求并关闭 socket；关闭回调不能触发重连。ViewModel 清理时释放实例作用域。
- 视图重建继续使用存活的 ViewModel 与连接，不因 Compose 重组或视图重建重复创建 socket。界面收集遵循页面生命周期，状态回写在主线程完成。

### 主机模式变化与传输协作

- 主机模式与进入页面时不同，或变为 `None` 时，进入“模式已变化”状态并停止自动重连，提示返回扫描后重新进入，不在原页面直接切换业务 ViewModel。
- 上传期间连接断开时停止启动后续文件，当前正在执行的 HTTP 文件传输按第一阶段规则等待结果，不仅凭 WebSocket 断开就判断上传失败。当前文件结束后，剩余文件保留待发送状态，不在重连成功后自动续发。
- 确认主机模式变化时，准备或上传阶段按第一阶段取消逻辑停止；已经开始合并时等待当前请求结果，禁止启动下一项。无法确认结果时提示检查主机文件。
- 已启动的下载不因单独的 WebSocket 断开而被强行终止，由下载服务按实际 HTTP 结果更新状态；断连或模式变化后禁止新增远端任务。
- 聊天断连时保留输入内容并禁用发送；本阶段不调整历史消息归属和去重算法。

### 空闲计时与页面退出

- 保留三分钟空闲阈值，使用 `180000.milliseconds`。用户触摸、发送聊天及收到聊天消息刷新活跃时间；心跳、剩余空间推送不计为用户活跃。
- 文件准备、上传、合并、取消清理，以及当前主机存在 Pending 或 Running 下载任务时暂停空闲计时；全部结束后重新开始完整的三分钟计时。
- 空闲提示改为“继续使用”与“返回”两项，不强制退出；继续使用或关闭提示后重新计时。提示出现后若有新消息或传输开始，关闭提示并按活跃状态更新计时。
- 用户主动返回且有上传任务时，提示“继续传输”或“停止并返回”；停止操作执行第一阶段取消清理，合并期间等待当前结果后返回。
- 用户主动离开接收页时不取消下载服务，提示已有下载会继续。后台下载不要求维持页面 WebSocket，本阶段不增加独立后台会话服务。

### 接口与实现边界

- 扩展现有连接状态类型及 `ClientWsClient` 的重试、初始化信息状态，不修改现有 WebSocket 消息名称及 HTTP 路径。
- HTTP 请求异常由连接流程统一转为失败或重试状态，业务 ViewModel 不重复处理同一次连接错误；取消异常继续向上传播。
- 第一阶段发送状态提供“存在活动任务”和“停止后续文件”的最小接口；接收页订阅现有下载状态，为空闲计时提供活动任务信息。
- 统一顶部连接状态与错误操作，复用项目现有文案及 Compose 组件；不扩大为三页面整体视觉改版。

### 场景验收

使用现有 checklist 的连接相关场景，不新增自动化测试。

- 三种模式分别进入，主机能看到客户端登记，顶部在初始化成功后显示已连接。
- 断网后出现重连状态；恢复网络后可重新连接，接收列表刷新，未发送文件不自动开始。
- 主机 WebSocket 端口变化后可通过 HTTP 重新获取；HTTP 地址失效时提示返回扫描。
- 主机切换模式或退出，客户端不继续执行旧模式的新操作；主动退出后不发生后台重连。
- 连续点击重连、快速退出重进及视图重建，不产生重复连接或旧回调覆盖新状态。
- 上传、合并或下载持续超过三分钟不弹空闲退出；真正空闲时可选择继续使用。
- 上传过程中返回可停止并清理；合并过程中返回等待结果；离开接收页后已有下载继续。
