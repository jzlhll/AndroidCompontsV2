# 客户端功能实施计划

## 目标

客户端对等实现 `assets/transfer` 中发送文件、接收文件、文本聊天的功能，沿用现有 HTTP 与 WebSocket 协议。客户端界面突出连接对象、传输状态和文件操作，与服务端界面区分。

## 实施方式

按以下五个阶段顺序推进，每个阶段独立确定详细 plan、实施范围和完成标准后再编码。本文件作为阶段总纲，先编写第一阶段的详细 plan，其余阶段在进入实施前细化。

各阶段只调整完成当前功能所需的代码。涉及服务端修改时保持现有 HTML 接口兼容；场景确认使用 `plan-checklist.md` 中对应条目，不单独设置联调阶段。后续可选功能见 `plan-future.md`。

## 第一阶段：修通文件发送

- 读取所选文件的真实名称、大小和可获取的修改时间；未知大小先解析或缓存确定，空文件给出明确提示。
- 分片编号统一从 1 开始，保留现有分片大小算法、MD5 校验和合并流程。
- 正确区分成功、失败与取消；取消后停止当前任务并清理服务端分片，避免旧任务覆盖新任务状态。
- 处理重复选择和同名文件的列表标识，失败文件保留并允许重新发送。

完成标准：单文件、多文件可完整发送，取消后可重新发送，失败与取消不会显示为完成。

阶段边界：沿用现有发送页面，仅补充必要状态与操作；整体列表样式、速度展示和记录持久化放在第四阶段。

## 第二阶段：补齐连接管理

- 三种模式均接入连接登记、心跳和连接状态展示，补齐接收页 WebSocket。
- 重连时重新获取主机端口与模式；模式变化后停止旧模式操作，提示返回并重新进入。
- 区分连接中、已连接、重连中和连接失败，提供重新连接或返回入口。
- 修正主动关闭与重连的状态处理；有传输任务时不触发空闲退出，收到聊天消息时更新活跃状态。

完成标准：主机退出、网络中断、模式切换及长时间传输时，客户端状态与实际会话一致。

## 第三阶段：完成下载功能闭环

- 下载支持及时取消和失败重试，预留目标文件名以避免同名并发覆盖；任务按主机地址与端口隔离。
- 下载完成后刷新本地文件仓库，提供打开、保存、分享和删除入口；区分删除本地文件与清理记录。
- 核对下载结果及本地文件是否存在，文件失效时展示明确状态。

完成标准：下载、取消和重试状态正确，同名任务不覆盖文件，完成文件可打开、保存、分享和删除。

阶段边界：沿用现有接收页面补齐必要操作；独立传输记录页面与重启后的记录恢复放在第四阶段。

## 第四阶段：完善客户端文件 UI 与记录

- 发送列表展示文件类型图标、名称、大小及逐文件状态；区分准备、上传、合并校验、完成、失败和取消，展示传输进度与速度。
- 接收页区分“对方文件”和“传输记录”，远端列表变化不隐藏已有下载任务。
- 保存必要的传输记录；重新启动后保留完成记录，将未完成任务标记为中断，核对本地文件是否仍存在。
- 统一发送与接收页面的文件操作、空状态和错误反馈，复用前三阶段已实现的传输能力。

完成标准：客户端文件界面与服务端明确区分，任务状态清晰；主机移除文件或客户端重新启动后，仍能找到有效的本地下载记录。

## 第五阶段：完善文本聊天

- 使用服务端分配的客户端身份，正确区分自己与主机的消息。
- 按当前协议处理发送结果，不依赖服务端回传自己的消息；处理发送失败并保留可重新发送的内容。
- 对重连后的历史消息去重，正确恢复消息归属，使用稳定的列表标识。
- 完善长文本布局、输入法发送动作和复制反馈。

完成标准：消息身份正确，重连不重复追加历史，发送失败可感知。

## 界面约定

顶部显示连接对象、当前操作与连接状态。文件采用紧凑列表：左侧类型图标，中间名称、大小和状态，右侧操作，进度放在对应文件下方。发送页底部展示总数量、总大小及开始或取消操作。
