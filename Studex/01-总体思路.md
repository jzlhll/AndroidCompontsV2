# Studex · 01 总体思路

## 1. 是什么

截图驱动的学习笔记 Agent。用户刷知乎、B 站时随手截图，Studex 后台捕获，排成一条**节点链**；用户补文字、调顺序，点一次提交，模型逐节点解析并累积成一篇带原图的 Markdown 文档。

核心不是聊天，而是**可编辑的素材链 + 持续生长的文档**。

## 2. 四个对象

| 对象 | 说明 |
| --- | --- |
| 会话 Session | 一个学习主题 = 一条链 + 一份文档 + 若干轮交互 |
| 节点 Node | 链上单位：纯图 / 纯文字 / 图文。唯一一等公民 |
| 轮次 Turn | 一次提交的输入快照与输出原文，计费、重试、回放的边界 |
| 文档 Document | 由轮次增量合成，只有一个当前版本，节末记录来源节点 |

## 3. 数据流

```
截图 → 前台服务捕获 → 待选区（不自动入链）
  → 用户勾选追加为节点(pending) → 提交
  → SSE 解码与候选预览 → 节点/文档/来源事务提交 → 转绿 + 记忆更新 + 轮次留档
```

三个 Tab 就是这条流的三个观察面：节点（输入）、文档（产出）、会话（过程）。navMenu 右上角新建文档，自动生成第一个起始节点，引导填写学习主题、视频或文章及记录目标；首次提交建立文档前缀，后续轮次复用。

## 4. 节点状态

| 状态 | 界面 |
| --- | --- |
| `pending` | 小圆点 + “待解析”文字 |
| `parsing` | 蓝色小进度 + 状态文字 + 锁标记（含本轮排队） |
| `parsed` | 小圆点 + 48dp 可滚动的已解析文字 |
| `failed` | 红色“失败 · 重试”，可单独重试 |

`parsing` 只在本轮存活；本地提交成功才转 `parsed`，进程退出后只把未提交节点回退 `pending`。状态不构成分组或筛选，始终按链序展示。

## 5. 截图捕获

- 权限：读媒体库 + 前台服务（dataSync 类型）常驻。
- 监听：`ContentObserver` 监听 `MediaStore.Images`，截图目录 `FileObserver` 兜底。
- 判定：路径含 `screenshot` 或文件名 `Screenshot_yyyyMMdd_*`，且宽高比接近屏幕（容差 3%）。
- 捕获后只入待选区并通知，**不自动入链**；可设置开启自动追加。
- 待选区按 `date_added` 倒序，"加载更早"以当前最早时间为游标翻页。

## 6. 排序

节点顺序独立于图片时间。底部选图按 `date_added` 升序插链尾；点击左侧节点圆点，可插入上一个或下一个节点。拖拽写 `sort_key`（fractional indexing），插入取前后中点，不整链重排。

## 7. 技术选型

Kotlin + Compose（4:3 图片卡、节点插入与拖拽、全屏模糊编辑遮罩）、Compose Foundation `HorizontalPager`（三个 Tab 横向切换，各页独立保存滚动状态）、Room、OkHttp 手写 SSE（要逐事件回调与取消）、前台服务 + ContentObserver、Coil。

不上 DI、不上多模块、不上向量库。

## 8. 约束

1. 提交幂等：全局只允许一个活跃轮次，执行器互斥，提交组按 `turn_id + commit_id` 去重。
2. 素材链是来源真相：按来源增量修订文档，重建只显式触发并保留旧版本和用户手写内容。
3. 流式不回滚：中断保留已解析部分。
4. 未改变的已解析节点不重传图片；修改内容才回退，纯排序不回退、不重复读图。
5. 全本机持久化，无账号无云同步；模型请求发送本批素材与选定上下文，首版不做本地 OCR。
6. 长会话使用有来源的节点摘要、分段记忆与相关章节，不逐轮携带全文；跨文档引用由用户手动选择。
