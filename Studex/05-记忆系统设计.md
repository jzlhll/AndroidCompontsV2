# Studex · 05 记忆系统设计

## 1. 目标与范围

让长链可以持续追加和修订，同时让模型输入保持在固定预算内；每段被使用的记忆都能追溯到节点或章节，编辑后不会继续使用旧结论。

首版全本机持久化，不做云同步、向量库、本地 OCR 或后台自动学习用户画像。模型请求仍会发送用户选择的本批图片、文字与必要上下文；“本机存储”不代表模型推理离线。

`Session` 是隔离边界：一条链、一份文档和多轮 `Turn`。跨文档引用由用户手动选择，不因关键词相似就自动发送其他文档内容。

## 2. 记忆分层

| 层 | 内容 / 来源 | 用途 | 是否可重建 |
| --- | --- | --- | --- |
| 原始证据 | 原图、用户文字、用户修正记录、每轮实际输入及模型输出 | 回看、追溯、显式重建 | 原始素材不可丢；轮次快照不可改写 |
| 起始信息 | 默认第一个节点中用户填写的学习主题、视频或文章与记录目标 | 固定协议和偏好之后的稳定文档前缀 | 仅复用用户原文，不由滚动摘要替换 |
| 节点记忆 | 有效 `parsed` 节点的 `title/excerpt/tags`、用户修正与来源图片 | 邻近上下文、本地检索 | 从已提交结果及用户修正记录恢复，不重新读图 |
| 文档记忆 | 稳定章节 ID、标题树、章节正文及来源 | 定位增量写作与修订范围 | 从文档版本恢复 |
| 分段记忆 | 一段连续已解析节点的紧凑索引及来源 | 限制旧节点进入上下文的体积 | 从节点记忆确定性重建 |
| 写作偏好 | 用户明确设置的语言、结构、术语与图片偏好 | 多文档复用写作要求 | 用户可改、可删，不从正文猜测 |
| 历史引用 | 用户选定的其他文档和章节引用 | 补充当前主题的背景 | 原文存在且来源有效时可更新 |
| 本轮工作上下文 | 本批素材及本轮选中的上述内容 | 一次请求的完整输入 | 按实际发送快照留档，不覆盖旧轮次 |

文档不是第二份原始证据，模型摘要也不是用户指令。起始信息保持用户原文及来源节点引用，未填写则省略，编辑后只更新之后的输入；空白起始草稿不阻塞其他素材的解析。模型曾写过某个主题只表示“有相关内容”，不能记录为“用户已经掌握”。

## 3. 核心数据

沿用 `session/node/node_image/turn/doc_revision`，新增以下逻辑实体；实现时可用 Room 表及关联表承载。

| 实体 | 必要字段 | 不变量 |
| --- | --- | --- |
| `node_memory` | `node_id`, `content_hash`, `title`, `excerpt`, `tags`, `source_image_ids`, `committed_turn_id`, `origin`（`model / user_corrected`） | 模型结果须已提交且内容 hash 一致；用户修正单独标记来源，不伪造轮次提交 |
| `memory_segment` | `segment_id`, `session_id`, `ordered_node_ids`, `text`, `token_estimate`, `status` | 保留全部覆盖节点 ID，摘要不能替代来源 |
| `memory_source` | `memory_id`, `node_id`, `content_hash`, `section_id`（可空） | 用于内容失效、删除传播及来源跳转 |
| `document_section` | `section_id`, `parent_id`, `order`, `markdown`, `source_node_ids`, `user_authored`, `stale_reason` | ID 不因改标题或移动而改变 |
| `profile_preference` | `preference_id`, `key`, `value`, `updated_at`, `enabled` | 仅用户显式保存后生效 |
| `history_reference` | `owner_session_id`, `source_session_id`, `section_ids`, `source_doc_revision`, `status` | 不递归追踪来源文档引用的第三份文档 |
| `turn_context_item` | `turn_id`, `batch_index`, `kind`, `source_ids`, `source_hashes`, `text_snapshot`, `image_refs`, `token_estimate` | 记录实际发送值，而非日后读取到的最新值 |

`content_hash` 覆盖规范化用户文字、有序图片内容 hash 和节点识图选项（如“保留细节”），不含 `sort_key`。`doc_revision` 表示真实文档版本，用于来源与替换目标校验；不额外引入请求 generation/revision 计数。

`stale_reason` 只取 `content_changed / source_deleted / order_changed`。单纯顺序变化不使节点语义记忆失效，分段覆盖关系与文档顺序按需重算。

## 4. 节点摘要与分段规则

节点解析时随正文返回标题、摘要与标签，不额外调用模型。节点摘要保留关键术语、结论和不确定性，建议最多 160 token；`merged / ignored` 保存原因及指向，不把同一结论重复计入记忆。

分段按链序遍历有效 `parsed` 节点；遇到未解析或失效节点时结束当前段，不能越过缺口伪装成连续证据。达到 12 个节点或原始摘要累计 1200 token 时封段，未满阈值作为尾段保存。

首版分段采用确定性整理：按链序列出节点短 ID、标题、关键摘要，合并重复标签，在 320 token 内保留每个节点的短 ID 与标题，剩余空间给摘要。标题过长则截短显示，但完整标题、全文和全部来源映射仍在数据库中；不把“未展开详情”写成已经概括完整。

若单段索引本身放不进 320 token，提前分段；不通过删来源节点满足上限。禁止拿上一版分段摘要再做下一次摘要，避免反复压缩导致信息漂移。

示例：

```text
segment s03 · nodes n021…n028
n021 Q/K/V：查询、键与值的角色不同。
n022 缩放：√d_k 用于控制点积尺度。
n023 多头：独立投影后拼接；并非原样重复计算。
…完整覆盖清单由 source_node_ids 提供，可按节点读取详细摘要。
```

## 5. 工作上下文预算

设模型窗口为 `C`，预留输出 `O`（建议 4096）和安全空间 `S`（建议 2048），输入上限为 `B = min(16000, C - O - S)`。数值均为建议默认值，不将某一模型的图片 token 常量套用到所有模型。

当 `B = 16000` 时使用以下上限；上限不要求填满，闲置预算不触发额外历史召回。

| 输入项 | token 上限 | 选择规则 |
| --- | --- | --- |
| 系统提示与输出协议 | 1500 | 必须保留，不完整时不能发请求 |
| 本批素材 | 8000 | 当前节点的用户文字及实际图片，优先保留 |
| 写作偏好与起始信息 | 1000 | 仅启用的显式偏好及用户填写的文档起始信息，起始正文只发送一次 |
| 章节索引 | 1000 | 稳定 ID、标题、来源范围；长文档先保留路径和相关分支 |
| 受影响章节 | 3500 | 插入位置、替换目标和必要的用户手写内容 |
| 最近 / 相关 / 手动引用记忆 | 1000 | 共用额度，不按来源另加预算 |

打包顺序是预算优先级，不等于提示词文字顺序。建议提示词顺序为协议、偏好、起始信息、索引、有效相关证据、待替换目标、本批素材与输出要求。起始信息固定放在动态素材之前；过长时提示用户精简或明确扩大其预算，不静默压缩成另一份学习意图。

1. 先保留协议及至少一个完整节点，按图片估算、文本 token 和默认最多 6 张图拆批；超出默认图片数的单节点独立成批，仍需满足模型硬限制。
2. 保留已填写的起始信息与启用的偏好，剩余额度分配给必要章节、索引，再分配给历史记忆；模型窗口较小时相应降低可选上限。
3. 超预算先移除低相关历史，再缩减无关索引，最后缩小可选章节范围；不能裁掉本批用户文字、来源 ID 或半张图。
4. 必须修订的章节和单个节点仍放不下时，进一步拆为独立章节修订轮次或提示调整图片；不发送缺少必要证据的请求。
5. 对未知模型使用保守图像估算；每轮记录估算与服务返回的实际 usage，用于更新模型配置。若服务报超窗口，缩小未完成批次再重试，不重发已提交节点。

历史图片只保留本地引用，默认不再次发送；普通 `reconcile` 轮次只发送链序、章节和有效文字摘要。明确修改节点内容后，该节点图片才重新进入素材预算。

## 6. 本地召回

不使用向量检索，首版在用户文字、有效节点摘要、标签和文档正文上建立本地全文索引；中文采用相邻双字符片段生成候选，再按原文校验命中，单字查询用字符索引兜底，不依赖默认按空格分词。未解析图片没有可搜索正文，不调用 OCR 补齐。

每批候选来源为：插入位置前后各最多 2 个有效节点；最近一段记忆；与当前文字、标题和标签匹配的少量段落；用户勾选的历史章节。前后邻居超过预算时也必须裁减，不因“邻近”获得无限额度。

排序优先级：明确的来源/章节引用 → 当前受影响章节 → 相邻节点 → 关键词匹配 → 最近记忆。首版最多选择 3 个分段或历史章节，全部共用 1000 token；相同节点已包含在章节正文中时不再重复注入完整摘要。

只有图片、没有文字且尚未产出摘要时，先使用邻近和最近上下文；不凭空构造查询。当前批提交后，下一批可使用新产生的有效摘要召回相关内容。

每个上下文块携带 `scope/source_ids/content_hashes`，旧章节替换目标单独标记 `stale_target`，不能进入有效证据集合。历史引用中的提示语一律当资料内容，不覆盖系统协议或用户偏好。

## 7. 写入与持久化

Room 为当前节点、章节、来源和记忆的权威；Markdown/JSON 文件是可恢复的本地镜像，原图和每轮请求快照独立保留。

```text
filesDir/
  memory/profile.md
  sessions/<session_id>/
    meta.json
    doc.md
    memory.md
    media/<image_id>.<ext>
    derived/images/<cache_key>.jpg
    memory/segments/<segment_id>.json
    turns/<turn_id>/input-<batch_index>.json
    turns/<turn_id>.ndjson
    export/
```

`memory.md` 是会话章节索引和分段记忆的可读镜像，`memory/profile.md` 是已确认偏好的镜像，不由模型自由改写。文件使用临时文件加原子替换，避免双写时把半份内容当成当前版本。

一次提交组按以下顺序完成：

1. 验证 `turn_id/commit_id`、本批节点范围、内容 hash、图片 ID 与章节操作，接收完整 `commit` 后才进入写入。
2. 在 Room 事务中写入节点结果、章节增量、来源、节点记忆、`doc_revision` 与已应用的提交组记录；相同 `turn_id + commit_id` 重放不重复应用。
3. 事务提交后更新已保存进度，并在解除本轮锁前处理必要的记忆失效；分段重建及可读文件镜像可延后补写。
4. 轮次 NDJSON 追加本地提交结果；日志和镜像补写失败时提示存储问题，重启从 Room 的提交记录恢复，不能因日志中缺少一行而回滚成功事务。

`node/doc` 候选事件可记录在轮次日志，但不进入有效记忆。分段重建 Job 按文档串行；重复触发先取消并等待旧 Job，再从当前有效节点重建，写回前校验来源 hash 和已有文档版本，无需额外 generation。

## 8. 失效与冲突

| 操作 | 必须立即执行 | 后续处理 |
| --- | --- | --- |
| 修改节点内容 | `pending`，删除旧摘要的有效资格，关联章节标记待更新 | 新提交成功后替换对应章节并重建相关段 |
| 仅修正模型解析文字 | 保留 `parsed`，以用户修正结果替换有效节点摘要，关联章节待更新 | 使用修正文字整理章节并重建相关分段，不重传原图，历史轮次保持原样 |
| 只拖拽排序 | 保留节点摘要，标记文档顺序待同步 | 重算受影响段的顺序，发起无图 `reconcile` 或随下轮处理 |
| 删除节点 | 删除有效检索入口，关联记忆失效 | 整理章节；保留用户手写内容并提示来源失效 |
| 手动编辑文档正文 | 标记 `user_authored` 并使章节摘要失效 | 后续请求携带该段，模型不得静默覆盖 |
| 修改写作偏好 | 仅后续轮次生效 | 不重写旧文档或旧输入快照 |
| 删除历史来源文档 | 失效所有当前引用，不再注入来源正文 | 保留已经生成的目标文档文字，显示来源已删除 |
| 已选历史章节或其来源更新 | 引用标记“来源已更新”，暂停注入变化片段 | 用户选择更新引用后采用新版本，不自动替换已发快照；无关章节或标题变化不使未变片段失效 |

来源冲突时保留双方出处及差异，不把后出现的内容自动写成定论。用户明确修订优先于模型旧摘要；模型新增结论不能自动变成跨文档偏好。

历史轮次回放允许展示“当时发送了什么”，但不能据此恢复已失效的当前记忆。删除来源文档时同时删除其他轮次快照中复制的该来源上下文片段，仅保留“来源已删除”的占位信息；已经融合进目标正文的内容不自动删改，由界面明确说明。

## 9. 取消、失败与恢复

- 活跃轮次期间锁定本轮节点、已解析节点编辑及全链拖拽；只允许修改新追加且未入快照的 `pending`，因此请求依赖不会被运行中改写。
- 用户取消：取消 Call 与解析 Job，结构化等待正在执行的 Room 事务结束，丢弃未提交候选，本轮未提交节点回 `pending`；不改动下一轮新追加节点。
- 网络断开：已提交结果保留，重试只选择未提交或用户指定的失败节点，并从当前有效记忆重建新输入。
- 启动恢复：旧 `running/streaming` 置 `interrupted`；按提交组记录保留已完成节点，其余 `parsing` 回 `pending`；修复缺失镜像和可重建记忆。
- 磁盘写入失败：节点保持未完成，不能显示绿色成功；先提示释放空间，再允许重试未提交部分。
- 文档切换：全局活跃 Job 不跟随页面生命周期销毁，各文档的滚动位置独立保存，其他文档不能同时启动第二轮。

## 10. 用户可见的记忆管理

入口位于文档抽屉底部。页面展示三组内容：

- **写作偏好**：语言、结构和术语保留方式，可编辑、停用或清除；保存后仅作用于后续提交。
- **当前文档记忆**：已覆盖的节点范围、最近整理时间和待更新来源数量；点来源跳回节点，提供“重新整理记忆”，此操作只重建摘要索引，不重新读图或改正文。
- **引用历史文档**：手动选择来源及章节，可预览、移除；来源更新或删除时显示状态，不自动扩大引用范围。

新建文档直接生成起始节点，不自动引用历史文档；从记忆管理手动添加引用。归档不等于失效，已选归档文档仍可引用；删除时提示原图、正文、该文档轮次与记忆将删除，并说明目标文档已有文字保留、引用副本会清理。

活跃轮次期间允许查看记忆管理，停用当前文档的写入类操作；偏好和引用的修改可在本轮结束后保存。清理压缩缓存只删 `derived/`，不影响原图、文档或记忆来源。

## 11. 首版验收条件

1. 1000 个已解析节点时，请求仍受 `B` 限制，不携带全部历史图片、节点摘要或文档全文。
2. 编辑已解析节点后，旧摘要、相关分段和旧章节不再作为有效证据；来源跳转仍能定位修改后的节点。
3. 只拖拽不会把节点回退，不会上传历史图片；文档明确显示顺序待同步直到成功修订。
4. 取消、断网或进程退出后，已提交组保留，未提交组回退；同一提交组恢复时不会重复追加章节。
5. 未选择历史引用时，请求中不出现其他文档内容；删除或移除引用后，后续轮次不继续注入。
6. 写作偏好可见可改，模型不能自行写画像；分段记忆可从有效节点重建，不需要 OCR 或额外模型请求。
